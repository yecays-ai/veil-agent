# 数据文件损坏与费用账本安全恢复（Windows）

原则：宁可停下，也不静默丢记录。下面的工具只增加「看得懂、可操作的恢复入口」，不降低任何校验标准；任何一步都不会删除数据。

## 一、恢复旧备份后，费用账本怎么处理

`restore --replace` 恢复完成后会自动与「恢复前的账本」（保存在 `*.before-restore-*` 安全副本里）对账：

- 按请求标识（id）对账，并保留每个请求的完整过程（reserve 预留 → dispatch 发出 → settle 结算）。备份之后新产生的请求会补回；备份里还停在「预留/已发出」、而当前账本里已结算的请求，会补上后面的结算记录。同一个 id 不是只留一条。
- 两份账本对同一步骤记录得不一样（例如同一个请求结算金额不同），或当前账本里有损坏的行：保留备份里的那条，另一个版本和原始行原样存进 `data\costs-unverified.jsonl`，**不按零元处理，也不丢弃**，同时**暂停所有付费请求**（聊天、自主活动、瞄一眼、记忆整理都不再发请求），直到你核对。
- 屏幕会写明补回了多少、有没有无法确认的项目。
- 供应商已经收的费用不会因为恢复而撤销；恢复后请用 `/cost` 核对今日与本月花费。

### 付费请求被暂停了怎么办

1. 完全关闭 VEIL。
2. `.venv\Scripts\python.exe data_repair.py ledger-status` 查看是哪些项目、证据文件在哪里。
3. 对照供应商后台账单，确认账本里保留的金额合理。
4. `.venv\Scripts\python.exe data_repair.py ledger-verify`，输入 `VERIFIED` 确认。标记文件会改名保留为 `costs-unverified.verified-<时间>.json`，证据文件也都还在。

## 二、聊天或账本文件损坏（例如断电时最后一行写到一半）

症状：启动或聊天时提示「本机账本损坏，已停止」，里面写着要运行的命令。

1. 完全关闭 VEIL（修复工具会检查服务是否还在运行）。
2. 先只查看：`.venv\Scripts\python.exe data_repair.py diagnose --file data\fixture\chat.jsonl`（换成提示里的路径）。它会写明第几行、从第几个字节起、是什么问题、这一行的开头内容；不会改动任何东西。
3. 确认后修复：`.venv\Scripts\python.exe data_repair.py repair --file ...`，输入 `REPAIR`。它会：
   - 先把原文件完整保存成 `<原名>.corrupt-<时间>`（并校验一致）；
   - 把有问题的行**原样**移到 `<名字>.quarantine-<时间>.jsonl`，其余记录一字不动；
   - 只缺末尾换行的文件，只补一个换行，不改任何记录。
4. 修的是费用账本 `costs.jsonl` 时：被隔离的行可能对应真实花费，所以修复后同样会暂停付费请求，要按上面的步骤核对并 `ledger-verify`。

只能处理项目 `data` 文件夹里的 `.jsonl` 文件。
