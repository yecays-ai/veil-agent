## 怎么用这份清单

1. 每个事项都有一个复选框 `- [ ]`。你体验通过后告诉开发 Agent「A-1、A-3 通过」，由 Agent 在这里打勾并写日期，同时回到对应工单补一行验收记录。
2. 各项状态的含义是分开的，互不代替：

| 状态 | 含义 | 谁能改变它 |
| --- | --- | --- |
| 待验收 | 已合并、已部署，等你实际用一次。 | 你 |
| 待确认 | 没有你的明确验收记录，也没找到使用痕迹。 | 你（可直接批量确认） |
| 已通过（Windows 使用过） | 本机有使用痕迹（版本文件、日志、配置、成品），但不是逐条验的。 | 你确认或保持 |
| 已验收 | 你有明确确认记录（日期或原话）。 | 只由你的记录决定 |
| 暂缓 | 你明确说过先不测、先放着。 | 你 |
| 开发侧自验 | 你说过这类不用你做，由开发侧核对。 | 开发 Agent |
| 待授权 | 动作会写正式数据或动正式环境，必须先经你同意。 | 你，逐项授权 |
| 待拍板 | 方向或取舍要你定，定完才能继续施工。 | 你 |

3. **CI 通过、开发侧测试通过、PR 已合并、已部署，都不等于你已经验收。** 没有你的明确记录，一律留在「待验收 / 待确认」。
4. 本清单是归集结果：同一个功能被后续工单替代、修复或明确取消的，记在 §11；你以前确认过的，记在 §13；两者都不再重复要求。
5. **涉及删除、覆盖、并发写入、数据恢复的验收，一律用隔离数据或专门为你创建的测试数据**，不动真实共同经历：记忆删除走 §3 B-6 的「专门测试记忆」，恢复与账本演练走 §8 G-1 的复制目录，正式库的历史恢复只在 §3 B-3 的维护窗口里、经你授权、先 dry-run。
