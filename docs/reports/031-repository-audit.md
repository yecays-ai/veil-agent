## 1. 给 Lan 的结论

**VEIL 有值得保留的基础，但现在还不能称为可以放心扩展高权限能力的健康版本。先修权限、重启与费用边界，再推进完整语音和更大的自主权限；无需全仓库重写。**

普通聊天的逐条保存、共享预算的预留/结算、文件工具白名单、实验室拒绝覆盖、角色目录隔离都有实际代码和离线测试支持。问题集中在多个工单接起来的地方：新消息形态与旧记忆调度、Ombre 与本地隐藏状态、长期任务与工具结果、网页线程与能力状态文件。这已经是需要治理的结构性技术债，而不只是排版或文件太长。

本次确认 **12 个根因：P0 1 项、P1 6 项、P2 5 项**。P0 是记忆删除审批边界缺口，已先在私下报告；只用替身记录调用，没有执行真实删除。公开文档不提供可直接利用的参数、步骤或精确入口。没有证据表明 Lan 的真实数据已经被删除、泄露或多扣费。

当前最实用的处理顺序：

1. 先堵住删除审批缺口，并修复“主动留言后重启误判记忆损坏”和隐藏状态不同步。
2. 补齐 Ombre 请求的费用硬边界、长期任务核实与进度上限、能力文件并发写入。
3. 建立可核对的完整冷备份和恢复步骤，再处理依赖维护、退出时序与过期文档。

普通文字功能可以作为修复基线保留，但本报告不为当前删除工具、自主续做或更高权限工具背书。安全修复完成前，不建议扩大权限；语音界面设计可以独立推进，接入更多自动行动应等待上述阻断项关闭。

## 5. 十二条真实功能链路

| 场景 | 入口 → 执行 → 保存 | 失败、重启与重复实现判断 |
|---|---|---|
| 启动/退出/重连 | bat → launcher mutex/endpoint → `web_agent.main` → Store 锁、Ombre host | 正常退出关连接/进程；缺依赖显示错误。异常杀主进程不会执行 finally；host 只看 stop 文件/子进程，不看网页父进程。08 与残留服务风险见第 8 节 |
| 普通/多气泡聊天 | `Hub.submit` → `run_chat` → `Chat.send/_tool_chat/send_message` → `<role>/chat.jsonl` | 先持久化再显示，失败不自动重试；`Chat.recent` 支持多 assistant，Memory 的轮次算法却不支持（02）。不是两个聊天后端，而是两种轮次定义 |
| 网页/语音输入发送 | 页面 SpeechRecognition → 文本框 → 显式 send → 同一个 `/api/send` | sessionStorage 保护已确认转写；网络失败保留输入；不自动调用模型。假识别对象不能验证 Chrome 的权限与回调时序 |
| 身份/人设/历史 | `load_character` → 本机 persona + self_facts + 历史 → 模型 | 配置/人设缺失停机；角色来自配置。未见把 Peter 私人关系写死为 Ghost 设定；显示/审批仍有 Peter 字样。网页重启只重放模型历史窗口，旧数据仍在磁盘，但缺少分页入口 |
| 记忆全生命周期 | context/NativeMemoryTools/斜杠命令 → Memory.call → Ombre；本地 state/versions/delete-requests | `/forget` 先本地隐藏，失败仍阻断；`trace` 旧版本先留档。01、03 是绕过/多状态真源问题；新建 hold 在远端成功、本地留痕前断开仍有不确定结果，没有跨系统事务 |
| Ombre 常驻/恢复 | `open_ombre` → start_or_connect → host 锁 + HTTP MCP | 连接/工具异常有提示，未实现会话内自动重连；下次启动可连接存活服务。health 不是 vault 身份证明，最终依赖每角色 token；端口错误通常认证失败，并非已证实串库 |
| Lab/文件权限 | 工具 schema → invoke → checked_path → 本地 exclusive create/append 或只读 MCP | 非 Lab 写入要批准；Lab 拒覆盖/非法路径、限制字节并核对哈希。追加失败明确结果不确定，不自动重试；当前没有执行脚本入口 |
| 自主唤醒/暂停/让位 | Hub idle → Controller due/run → Chat autonomy 模式 | resident-state 原子保存；active 标记恢复成失败记录，不重播旧唤醒。12 个工具步骤与 deadline 在边界检查；长调用不能被立即终止 |
| 长期任务 | status/update → LongTaskStore → long-task.json；工具前后检查点 | 状态不授权文件访问，原子替换失败保留旧版；40 条进度后卡住（05）；用显示摘要判定核实（06） |
| 主动消息 | 自主工具循环 → 共享 Hub 同步门 → send_message → 现有 chat.jsonl + assistant 事件 | 唤醒/工具调用 ID 去重，持久化最多 3 条；不新增投递队列。重新开 Memory 的兼容性漏测（02）；普通聊天去重注册只在进程内，跨服务重启不是持久 exactly-once |
| 模型/工具/预算 | 直接聊天 SDK 无自动重试 → reserve → model → settle；工具执行前另留后续预算 | 直接调用失败保留预留。Ombre 的内部重试/输出上限与后台向量不受同等边界覆盖（04），估算账本不等于供应商账单 |
| Peter/Ghost 隔离 | 角色 ID → data/role → memory/workspace/task；共享 costs 与 session.lock | 假数据证明路径隔离、全角色共享总预算；单全局锁只允许一场正式会话，不是多角色并行服务。未读 Ghost 私有数据，不宣称实际两角色验收通过 |

## 8. 安全与维护现状

### 8.1 已有且有代码证据的保护

- **网页服务**：`web_agent.py:193–211,287–290` 仅监听 `127.0.0.1`，校验 Host/Origin、随机 token，响应 no-store/no-referrer，不记请求 URL。token 每次服务启动生成，写本地 endpoint；页面读入后去掉 URL 中 token。有效期是本次进程，无独立超时/主动轮换。
- **Ombre**：`ombre_resident.py:17–38,78–100,185–199` 强制 loopback、MCP 静态 token、独立目录；不向模型提供 token。上游 MCP Bearer 与 Dashboard cookie 是两套认证。固定源码 `src/web/_shared.py:675–680,810–850` 将面板凭据哈希和会话存在 vault 内，PBKDF2；不是明文面板密码。MCP token 跨重启保存，备份会带走它。
- **缩小攻击面**：`ombre_entry.py:14–40,77–86` 屏蔽更新、隧道、配置等入口，禁止自动本地模型/隧道；不是对上游全部管理路由完成了安全认证。
- **权限**：`tools_agent.py:16–47,75–93,390–455,457–552` 程序 allowlist、resolve 后检查范围、Lab 限额/拒覆盖、追加身份核对；文件中的“同意”不能替代 approval 回调。权限不靠提示词。031-01 是已确认例外，必须修。
- **数据**：`veil_agent.py:86–139` JSONL 逐条 fsync、撕裂末行拒绝追加、OS 进程锁；`long_tasks.py:136–152` 原子快照。磁盘写失败不会被主聊天循环当作普通供应商错误继续发送。
- **密钥与源码**：空 `.env.example`、忽略私有目录、供应商 key 只在本机读取并通过进程环境传递；Ombre 下载源码及依赖清单校验固定 SHA；本轮历史密钥扫描无命中。

### 8.2 已有但尚未证明有效到全部场景的保护

- 首次 Ombre 备份能复制虚构 Markdown，已有单测；没有真实 SQLite/WAL、一致性/还原召回演练。正常 close 有 stop 文件、等待与强制退出，但没有本轮真实进程树证据。
- 运行中关闭工具/暂停/退出为协作式让位；模型请求与某个 MCP 调用完成前不能保证立刻结束。`AutonomyController.should_yield` 检查 deadline，不是能在任意指令处抢占的硬计时器。
- 预算对父进程直接请求有证据，Ombre 只能按目前估算记账；不能称全链路硬上限（04）。
- 角色目录隔离有假数据回归；本轮没有读取私人目录或实际运行 Ghost，不证明所有本机改配都安全。
- 备份文件、token、聊天、人设的 Windows ACL、磁盘加密、云盘保护、外置盘保存情况没有读取或验证；不能称已加密，也不能称用户电脑已经泄露。
- 分支保护 API 返回 **403 Resource not accessible by integration**。这表示未知，不能写成“没有分支保护”。当前 CI 有通过记录，不代表保护规则强制要求它。

**虚构数据冷恢复结果**：构造完整隔离实例，保存 13 个文件，含聊天、隐藏状态、虚构 SQLite 索引、Lab、日记、persona、假 key、角色 TOML、任务 pending、自主开关及已结算/未结算费用。关闭包装层写入者后复制到新目录，13 个文件 SHA-256 全等；重建包装层后两条聊天、隐藏过滤、任务 ID/pending、自主开启状态、费用/预留均一致。按 README 三项集合备份则缺角色配置，load_character 失败。

复制后的持续追加授权因为文件 inode/创建时间变化不再匹配；这是保守失效，**应重新批准，而不是让备份伪造同一文件身份**。本次索引只是虚构 SQLite 的字节复制，未证明真实 Ombre 索引可查询；没有启动真实模型、验证 NTFS ACL、跨机器 Python/Node 安装或真实 Dashboard 登录。详细证据见附件。

**运行中快照**：没有跨 chat/cost/memory/task 的全局快照事务；网页 Store 锁并不阻止独立 Ombre 面板/自然衰减写入。`_copy_first_backup` 在连接健康服务之前就复制，异常主进程留下的 host 仍可能正在写。不能在当前实现上承诺热备一致。最小可用方案先采用确认所有写入者停止的冷备份；031 不尝试真实热备或杀用户进程。

**灾难判断**：单个文件坏了会保守停机，避免继续覆盖；若没有额外备份，项目目录被误删/盘损坏时没有恢复保证。首次同盘 memory 副本不能挽救聊天/Lab/配置，也可能早于最近工作；正常代码更新不主动覆盖 data/persona/.env，但没有完整升级回退包或迁移电脑流程。

| 任务卡住 | pending、失败及当前任务可查询；05/06 会造成不可正常续做 | 修根因并显示具体阻断原因，不加第二套任务调度框架 |
| 日志容量 | 上游 `src/utils.py:57–58,805–812` 的 server.log **已有 1 MB × 当前文件+3 历史文件轮转**；父 host 的 `process.log` 以追加方式打开，无本项目容量/保留期限策略 | 仅规范操作日志；不能将聊天、费用和记忆历史当普通日志自动丢弃 |
| 日志隐私 | 网页不记含 token URL，VEIL diagnostics 只记结构化事实；上游 `dehydrator.py:1023,1166` 的解析失败 warning 可记录模型文本片段，异常字符串也缺统一脱敏 | 本机日志也按敏感数据保护；没有证据称真 key 已进入日志，不能在公共 PR 上传原日志 |

严重的存储/账本损坏、备份失败、记忆服务持续不可用、工具副作用不确定应显式通知并保守阻断；普通降级/短暂断网可以简短提示，不应每条心跳刷屏。无需先引入集中日志平台或远端监控。

## 9. 架构改善建议：小步，不重写

| 观察 | 是否是 AI 堆积问题、证据与最小行动 |
|---|---|
| 重复状态定义 | **是**。Chat 与 Memory 各自定义轮次（02），Ombre 原生隐藏与 VEIL 本地隐藏/开场缓存是多个真源（03）。先统一语义与同步契约，再考虑抽取小函数 |
| 显示文字成为业务身份 | **是**。长期任务拿工具摘要做 pending 身份（06）；工具通知/角色显示改字就可能影响续做。先存稳定 ID/路径，不新造任务框架 |
| 多工单集中改同一处 | **是**。`_tool_chat` 同时处理供应商记录、长度/校准、预留、消息、任务检查点、权限委派、让位、日志；内部还有已不可能进入的 autonomy 分支（外层已限定非 autonomy）。先补交叉回归，再只抽工具执行结果/检查点边界，保持顺序 |
| 重复读改写能力文件 | **是**。Files/Native/自主开关各自保存同一 JSON、同临时文件；已出现并发失败（07）。统一一个小的状态保存入口和锁，收益明确 |
| 记忆适配层是否多余 | **不多余**。它承载程序级隐藏、预算、角色目录和审批，直接让模型连上游会丢失边界。应收紧边界，不能为“少一层”删保护 |
| 旧 extract 是否死代码 | **不是**。本机配置仍可选 extract，测试也覆盖；与 native 的正式比较未完成。维持兼容，单开退役决定；不能用 Vulture 候选做删除授权 |
| 新一套消息投递是否必要 | **当前不需要**。主动消息复用了同一 chat 账本、Hub 事件和同步门。先修轮次/恢复问题，不引入队列系统 |
| UI 与模型历史耦合 | **已有维护限制**。`Chat.recent` 在 662 行按历史窗口截取，`serve_chat` 294–295 行只重放该窗口；长期网页内存事件与模型窗口不是同一目标。旧消息仍在磁盘，但重启后更早消息不可见；是否增加浏览历史需单独确定范围 |
| 隐式/动态依赖 | veil_agent 运行时导入 autonomy/long_tasks，二者又导回 veil_agent；main 有模块别名避免重复加载。当前没有证据证明循环启动失败。宜明确构造顺序，不为形式拆成大量小包 |
| 无用遗产/实验 | 017 运行脚本确实失配（11）；将历史实验钉到对应版本。不要重跑付费实验或删除历史报告 |
| 文件长是否必须拆 | **不能单凭长度决定**。Store/Budget 可以先原样保留；Chat 策略接缝、能力文件写入才有明确收益。当前不需要 Web 框架迁移、通用事件总线、完整数据库重建或多 Agent 调度平台 |

## 11. Lan 的简短体验验收

下面只保留自动化不能替代的体验。**P0 修复前，不让 Lan 演示漏洞或操作重要记忆；以下用于对应修复后的验收。** 已被假数据证明的 40 条上限、参数检查等不再要求 Lan 手工复现。

| Lan 做什么 | 正常应看到什么 | 哪种现象是问题 |
|---|---|---|
| Windows 双击网页入口，关页面后再开；正常退出服务后重开 | 能接回同一角色；聊天和安全的主动留言保留；重开不报记忆状态损坏 | 出现第二服务/端口冲突、记忆启动失败或留言重复 |
| 在独立测试角色中做一次记忆保存、修改、面板隐藏，继续聊天，再重启 | 提示清楚；隐藏内容不再被当作开场/回忆；历史与批准/拒绝语义一致 | 已隐藏内容又被提供、页面与模型反馈相反。不要用真实敏感记忆测试 |
| Chrome 中英文各说一句，手动停止/编辑/发送；再拒绝麦克风权限 | 已确认文字保留且只追加一次，只有点击发送才进入聊天；拒绝有清楚提示 | 自动发送、重复文字、原输入丢失或识别一直卡住 |
| 建一个安全的两阶段 Lab 任务，正常重启后让它继续；期间发送聊天或暂停 | 旧产出保留、不重复追加，聊天优先；必要审批明确，任务状态能解释停在哪里 | 重复写入、停不下来、没有核实就称完成，或无法继续且无原因 |
| 032 提供恢复入口后，用它生成的专用演练副本在另一个目录打开 | 明确显示演练角色，聊天/记忆/任务/费用一致；需重新确认的文件授权有说明 | 恢复失败、错连正式服务、费用预留消失或正式数据变化；开发端应先完成演练再交付 |

真实供应商费用和召回质量只在今后获批的正常使用中核对；031 不要求额外消费，不承诺真实模型一定按四行格式总结。
