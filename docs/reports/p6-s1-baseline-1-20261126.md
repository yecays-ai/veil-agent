# P6-S1 Baseline-1｜检索、卡片与元数据确定性修复基线

> **性质**：隔离、零付费、可复现基线。全部数据为虚构，全部模型为本地假模型；未读取或写入正式聊天/记忆/人设/密钥，未调用任何付费 API。
> **生成方式**：python scripts/p6_s1_baseline.py --out baseline-1.json（脚本随本单提交）
> **代码版本**：以本单合并提交为准；复跑时脚本会把当前 git HEAD 写入 JSON 的 code_commit 字段。

## 一、用途

本基线供 P6-S4 直接复用，无需重新审计基础链路：S4 在开始 Tier 0/1 实验前先复跑本脚本，确认 18 项检查全部通过，即可把当前检索链路、配置与判别行为当作实验固定基线。

## 二、固定条件

| 项 | 值 |
|---|---|
| 环境 | 临时目录 + 虚构数据 + FakeEmbedder + FakeJudgeModel，无网络、无付费调用 |
| Embedding 模型标识 | baseline-fake-embedding（用于模型身份/维度保护验证） |
| 检索配置 | backend=brain，weight_vector=0.65，weight_keyword=0.35 |
| 判官默认参数 | recall_judge.DEFAULTS：timeout_seconds=4.0，ombre_candidates=8，vector_candidates=8，breaker_failures=3，breaker_seconds=300 |
| 数据规模 | 20 条卡片样本（14 条 CRLF / 6 条 LF）、若干 3 维/1024 维向量记忆、不同 created 日期记忆 |

## 三、实测结果（20/20 项检查通过）

### 1. 卡片完整性（对应 G-A04）

| 指标 | 修复前（旧硬编码分隔） | 修复后 |
|---|---:|---:|
| 卡片能读到 opening+ending 的样本 | 6/20（仅 LF 样本） | **20/20** |
| 卡片平均字符数 | 86.2 | **260.0** |

- CRLF、LF、UTF-8 BOM 与 bytes 四种输入得到相同卡片；旧实现用 raw.partition('\n---\n')，对 CRLF 文件取不到 body。
- 参考审计：P6-1 中 154/225（68.4%）记忆为 CRLF，卡片均值 289.5 → 116.5 字。

### 2. 每轮 Embedding 调用（对应 G-A05）

| 路径 | 实测调用次数 |
|---|---:|
| 旧路径（judge.prefetch + 独立 search_candidates） | 2 |
| 当前（judge 的 query_vector 共享给检索，一次预留一次结算） | **1** |

- 判官未启用（wake/rotate/assisted 分支）时，检索自身 Embedding 1 次，不受影响。

### 3. 主动检索日期与配置权重（对应 G-A09）

- date_from=2026-11-10、date_to=2026-11-30：只返回 11 月 20 日记忆，11 月 1 日被过滤（创建日含边界）。
- 非法日期 2026-13-40 被拒绝（ValueError），不会静默返回错误范围。
- 权重从 [memory.retrieval] 读取：实测 weight_vector=0.65 / weight_keyword=0.35；改配置后 authority.retrieval_settings() 立即反映（0.9/0.1）。

### 4. 向量维度与模型身份（对应 G-A14）

| 场景 | 行为 |
|---|---|
| 3 维向量模型写入与检索 | 正常工作，不再要求 dim==1024 |
| 混合维度（3 维 query 对 1024 维记忆） | 跳过不兼容向量（本次跳过 4 条），不崩溃，保留关键词通道 |
| 模型身份不一致（meta.embedding_model != 当前模型） | 向量通道降级为关键词并记录 model_mismatch/keyword_only |
| 写入方发现模型不一致 | 不写向量，memory 保持 vector_state=pending，write_journal 记录 embedding_model_mismatch |
| 待索引恢复 | retry_pending_vectors 重试 2 条，saved=2，pending=0 |
| 换 Embedding 模型后的待索引 | 先被阻断（retried=0、saved=0、blocked=embedding_model_mismatch，0 次付费 embed），执行显式 reindex 后 13 条全部恢复（saved=13） |

### 4b. 换模型后的待索引与显式 reindex（合并后加固）

`scripts/embedding_reindex.py` 是唯一被允许的模型切换操作：dry-run 先看数量，--apply 才清空旧向量、把所有记忆标为 pending、移除旧模型身份；之后正常待索引重试会用新模型重建。基线实测 20/20 检查通过，其中新增两项：

- 模型不一致时 retry_pending_vectors 在付费 embed 之前就返回 blocked=embedding_model_mismatch（embedder 调用 0 次、零写入）；
- 执行 prepare_embedding_reindex 后，13 条记忆恢复为 ready（retried=13/saved=13），meta 记录新模型。

### 5. 判官诊断（对应 G-A12）

| 场景 | 实测诊断 |
|---|---|
| 正常空召回 | judge.status=empty，degraded 为空 |
| 判官模型超时 | judge.status=failed，reason=timeout，detail=model，model_seconds≈0.61，degraded={stage:judge, fallback:today_pool} |
| Embedding 失败 | judge.status=failed，reason=embedding_error，detail=RuntimeError，degraded={stage:judge} |
| 自主活动判官超时 | degraded={stage:judge, reason:timeout, detail:model, fallback:pool}（回退候选池） |

- Embedding 与判官模型使用独立计时：embedding_seconds / model_seconds 分别记录，不再共用一个 deadline。
- 参考审计：P6-1 中 Brain 时代判官失败 5/5 全为 timeout:model（共享 4s）。

### 6. 连续性与死代码移除（对应 G-B01/G-A08）

- 首轮注入 4 条；下一轮跟进（“后来呢”）carry 3 条；重复同一话题时 cooldown 丢弃 3 条（实测值随假数据生成的 id 数量稳定，两次复跑一致）。
- reuse_recall() 与随机 drift 分支已移除：Memory 无 reuse_recall 属性，brain_retrieval 无 DRIFT_MARK；承接、冷却、轮内去重仍工作。

## 四、复现步骤

1. 在仓库根目录执行 python scripts/p6_s1_baseline.py --out baseline-1.json。
2. 输出 JSON 包含 code_commit、python 版本、配置、七组结果与 checks（当前 20 项）；全部 checks ok 即基线成立。
3. P6-S4 实验前复跑并与本报告数值对照；如差异超过预期（如 Embedding 变为 2 次/轮、卡片可见率下降），先停下排查，不得把差异带入实验。
4. 合并后加固说明：P6-S1 PR #452 合并后独立审查发现“换模型时 pending 重试先付费后拒绝”的问题；修复见独立 hotfix 分支 ticket/455-p6-s1-postmerge-hardening（本报告已按加固后的代码更新数值）。

## 五、边界说明

- 本基线只覆盖确定性链路与假模型行为；真实模型效果、延迟与付费参数实验统一留给 P6-S4。
- “修复前”数字来自旧算法在本脚本内的同数据模拟与 P6-1 审计记录，不来自正式库运行对比。
- 未对正式 154 条 CRLF 历史记忆做批量改写；修复只在读取/更新时局部兼容。
