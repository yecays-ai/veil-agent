## S3：关系认知、证据晋升、四区预算治理

### 1) learned-context 四区独立存储预算 —— **推荐实施**
- **你日常会看到的变化**：Peter 的「关系认知」和「进行中的事」以后不容易被 facts/growth 挤爆；关系里能存下的内容更多，不用频繁删旧的。
- **实验实际证明了什么**：现在四块共享 4000B，实际占 3440B，只剩 560B。按 S3 想补的目标（把关系区回填到 1200B、继续加 facts/growth/ongoing）模拟 4 次写入，共享上限下被拒 2 次；改成四区独立（facts 1800 / growth 2000 / relationship 1500 / ongoing 900 B）后 0 次被拒。历史上 facts 最大曾到 3300B，说明挤压是真实存在的。
- **风险/延迟/费用**：每轮多注入约 126 token（facts+growth 渲染增量），约 ¥0.02/日、¥0.6/月；无延迟增加。风险是实现时要兼容旧 JSON、保留你的锁定/更正/删除权（这些是 S3 施工要求，不是本次实验验证的）。
- **推荐参数与适用条件**：facts 1800B、growth 2000B、relationship 1500B、ongoing 900B；先做写入上限解耦，不改已有内容；上线前用真实 learned-context 副本跑一次迁移演练。

### 2) event→confirmed 晋升扩权（允许经 stage-evidence/ quotes 溯源） —— **不推荐实施（先补证据链）**
- **你日常会看到的变化**：暂时不会变；现在 Peter 的自我猜测仍然只能是 uncertain，不会偷偷变成「已确认」。
- **实验实际证明了什么**：64 条 stage-evidence 全部是工具证据，没有一个事件能用你的原话严格溯源；quotes 只有 6 条、3 条能逐字对上你的消息；关系认知历史里 0 条 confirmed 晋升。如果改成「有 event 指针就晋升」，循环自证率=100%（Peter 自己写的故事能自己确认自己）。严格规则下可晋升 0 条、自证率 0。
- **风险/延迟/费用**：扩权本身不加钱，但会把「Peter 自己的猜测」误标成关系事实，违反红线；修复成本高。
- **推荐参数与适用条件**：维持 chat-only 晋升；S3 施工时先补 chat: 证据链（尤其是 stage-evidence 的 chat 类型和 quotes 解析），再重跑 AB-A2；循环自证率必须保持 0。

## S5：检索、判官、事件关联及自然联想

### 3) 中文停用词过滤 —— **推荐实施**
- **你日常会看到的变化**：像「那个/今天/测试」这类虚词不再挤占检索结果，Peter 想起相关旧事的概率更高，尤其问具体细节时。
- **实验实际证明了什么**：K=8 生产候选池下 Recall@8 50.56%→54.44%（+3.88pp），Precision@5 13.78%→17.33%（+3.55pp），NDCG@8 42.29%→48.09%；误注入没有变差；trap 类查询平均 token 45.7→34.3。K=20 敏感性同方向（+4.81pp）。
- **风险/延迟/费用**：零模型调用、零费用；本地分词过滤，延迟变化在毫秒内（p50 1.1–1.3ms）。风险是个别停用词如果恰好是关键实体（已用人工小词表控制，不删内容词）。
- **推荐参数与适用条件**：启用一张短小、可审计的中文停用词表（约 90 词）；保留可配置开关；先在生产跑一轮回归看 P4 召回面板是否正常。

### 4) 判官链维持现状（LLM 判官 + 4.0s + 300 字卡片 + 保守 prompt） —— **推荐维持**
- **你日常会看到的变化**：没有变化，但也不会更差、不会更贵。
- **实验实际证明了什么**：
  - 判官角色：LLM 判官召回 57.0%、误报 45.5%；无判官误报 100%；阈值门控误报 81.8%。⇒ 判官不能去。
  - 超时 4s vs 6s：两档都是 0 次超时；重复臂选择重叠率只有 0.67，6pp 的差异是模型采样噪声，不是超时效果。⇒ 维持 4s。
  - 放宽 prompt：召回 +4.00pp，但误报 +18.18pp。⇒ 不放宽。
  - 500 字卡片：召回 +2.00pp（小于重跑噪声），输入 token +33,944（+45%）。⇒ 不动卡片。
- **风险/延迟/费用**：判官每轮一次 deepseek 调用，本次实测均值约 ¥0.0043/轮、约 ¥4.33/千轮（现网已付费，不是新增）；p50 约 0.7s、p95 约 1.0–1.3s。
- **推荐参数与适用条件**：timeout_seconds=4.0；ombre_candidates=8/vector_candidates=8；card 300；保守 prompt。若未来换模型或换 provider，需重新做 R3a/R3b。

### 5) 候选池 K 扩大（8→12/20/30） —— **不推荐实施**
- **你日常会看到的变化**：无变化（保持 K=8）。
- **实验实际证明了什么**：K 越大 Recall@K 越高（K=30 比 K=8 高 17.2pp），但到 30 都没收敛；同时「只被向量找到」的补位占比从 20.2% 升到 26.2%，意味着更多候选要靠判官和预算兜底，判官输入 token 会涨，且本次没有判官侧的净收益证据。
- **风险/延迟/费用**：候选池越大，判官/注入 token 越多；无证据支持这笔钱值得花。
- **推荐参数与适用条件**：保持 K=8；只有当以后有「判官侧 Precision/p95 可接受」的新证据，再考虑小步到 12。

### 6) 融合算法 RRF / 纯向量；story 索引 —— **不推荐实施**
- **实验实际证明了什么**：Min-Max 54.44%、RRF 54.26%、纯向量 52.41%，差异 <1pp；story 向量索引 +0.00pp、S3 覆盖不变、p95 略升。76 条 story 里 69 条来自 final-import，语义与 memory body 高度重叠。
- **风险/延迟/费用**：story 一次性嵌入约 19.5k token（配置价 ¥0），但上线后仍要维护索引；收益为零。
- **推荐参数与适用条件**：维持 Min-Max 0.65/0.35；不引入 story 向量索引。

### 7) related_to 一跳扩展 —— **证据不足，暂不实施**
- **实验实际证明了什么**：候选池平均 +3.6 条，S3 跨事件覆盖 +1 条、候选池期望命中 +1；低于「≥2 条覆盖」的实收益门槛。纯检索 Recall 不变（扩展在 top-K 之后，只影响判官候选池）。
- **风险/延迟/费用**：候选池变大 → 判官 token 增加；收益只有 1 条样本。
- **推荐参数与适用条件**：先补 S3 样本到 12–15 条、或改为「仅当问题明确跨事件时扩展」再测。

### 8) 豆辞典/别名 Aho-Corasick 补召回 —— **不推荐实施**
- **实验实际证明了什么**：自动从记忆标题/标签/关键词抽的别名字典补召回 1 条，但工作/自主查询误触 16/28（英文通用词、工具名也会触发）；原版「豆辞典」数据源在仓库中不存在。
- **风险/延迟/费用**：误触会让判官候选变脏、增加 token；自建词典维护成本高。
- **推荐参数与适用条件**：不实施自动抽取版；如果以后有维护好的实体词典，再做一轮小样本。

### 9) 全库分层轮换自然联想池 / 自主闲暇联想 —— **不推荐 / 证据不足**
- **实验实际证明了什么**：全库 24 条分层池相对 breath(8)：联想生成 38→39，但唯一记忆 32→11，imp=8 长尾覆盖 16.7%→10.0%，噪声违和 11→12。自主闲暇：4 条闲暇唤醒里 0 条产生联想，因为现有「轻松话题」门控（≤40 字）挡掉了自主唤醒的长上下文。
- **风险/延迟/费用**：联想每条约 60 token；真正的风险是「生硬提起旧事」——本次没有任何盲评证据。
- **推荐参数与适用条件**：暂不实施；若 S5 想做，先为自主唤醒单独设计门控，并做小样本真实生成 + 你的人工体验验收。

### 10) Reranker（Qwen3-Reranker / BGE-v2-m3） —— **证据不足（阻断）**
- **实验实际证明了什么**：没能测。仓库没有 rerank 服务端点、模型标识和价格表；按工单「无法确认价格上界不调用」，没有花钱探测。
- **推荐参数与适用条件**：先接入可报价的 rerank 服务，再补 Precision@5/p95/单轮成本对照。

## S6：重要度、活跃度、情感权重及认知巩固

### 11) importance 长期重要度权重调整 —— **不推荐实施**
- **实验实际证明了什么**：+0 / +0.05 / +0.10 / +0.15 四档，重要老记忆命中都是 7/9，综合指标 0.05 最优。现网已经是 0.05，不用动。

### 12) last_active 活跃度微调 —— **证据不足，暂不实施**
- **实验实际证明了什么**：近 7 天期望记忆 53 条里 +1 条命中；冷门重要记忆（importance≥8 且 30 天没活跃）样本 0 条，保底率无法验证。旋转/冷却只有最后快照，逐轮冷却不可回放。
- **推荐参数与适用条件**：先补冷门重要记忆样本，再测 H2。

### 13) valence/arousal 情感门控加分 —— **不推荐实施**
- **实验实际证明了什么**：S2 共情召回 -2.78pp（噪声内），误注入不变。假设 H1 不成立，按设计在 Tier 0 否决、不进 Tier 2。

### 14) 夜间认知巩固（AB-E1） —— **证据不足（阻断）**
- **实验实际证明了什么**：事件账本 87.3% 是恢复报告（dream-report），quotes 6 条、关系区历史 0 条 confirmed 晋升；没有「巩固之后回复有没有变好」的对照标签。真实巩固需要多日生成 + 人工验收，本次预算/隔离条件不够。
- **风险/延迟/费用**：若未来实施，单次夜间约 1 万 token ≈ ¥0.03/日、¥0.9/月，必须带独立开关 + 日预算顶 + 不覆盖你的锁定/原话。
- **推荐参数与适用条件**：S6 前先补数据与开关设计；本次不启动。

## S7：上下文注入、缓存稳定性及记忆侧接口收口

### 15) HEAD 静态前缀纯化（能力描述移出 system.facts） —— **证据不足，但方向支持**
- **你日常会看到的变化**：如果实施，展开工具（expand_capability）后首轮不再整块打断缓存，回复可能更快；费用略降。
- **实验实际证明了什么**：真实 deepseek 前缀缓存微探针：HEAD 稳定时缓存命中 89.47%；能力描述在 HEAD 内变化时命中掉到 5.91%；移出 HEAD 后回到 88.40%。生产 context-log 的 tool_step 请求缓存命中 70.36%，工具 schema 平均 38KB。
- **风险/延迟/费用**：主要是实现风险（要同步改 system.facts 拼装与 runtime 注入）；费用收益估计 ≤¥0.07/日，延迟收益可能更明显。
- **推荐参数与适用条件**：S7 实施后必须用真实生产请求复测缓存命中率；先小步灰度、保留一键回退。

### 16) 非首轮省略空记忆提示（C2a） —— **证据不足，暂不实施**
- **实验实际证明了什么**：555 次真实请求中非首轮 332 次，按空召回率 50.45% 估算每窗口省约 6,563 token。**但没有真实生成，没法证明省略提示不会让 Peter 编造回忆**——「幻觉回忆率必须=0」是红线，不能只靠估算。

### 17) 短闲聊记忆注入上限 Top-2+1（C2b） —— **证据不足，暂不实施**
- **实验实际证明了什么**：220 次真实召回里 10 次注入超过 3 条，按平均记忆长度估算每窗口省约 4,606 token；但短闲聊「少给几条记忆会不会显得冷淡」没有盲评。

### 18) 完整 story 换成摘要+指针（C3） —— **证据不足，暂不实施**
- **实验实际证明了什么**：75/76 个事件 story 长于摘要+指针，平均每条注入可省 216 token；但模型会不会主动去读全文、回复完整度会不会下降，没有真实请求验证。

## 这次实验没能证明的事（必须说清楚）

1. **没有 Lan 的人工体验验收**：Tier 2 全部是 AI 辅助/离线测量；「Peter 回复更自然」「共情更准」这类结论本次**不成立**。
2. **没有真实生产请求验证**：C1 是微探针，C2/C3 是结构侧估算；都需要 S7 真机复测。
3. **没有跨机制组合证据**：AB-COMB 只有停用词一个胜出项，不能证明 Reranker/联想池/巩固等同时开启没问题。
4. **样本量有限**：73 条 eval-v2 是 AI 辅助标注、目的抽样，不能外推成真实聊天分布；AB-A2/E1 等小样本结论已标证据不足。
5. **判官调用存在采样噪声**：deepseek-flash 无固定 seed，同 prompt 重跑召回差可达 6pp；本次所有 <5pp 的差异都不作为采纳依据。
