## 逐项详细说明（给 S3 / S5 / S6 / S7 施工拍板）

### S3 · 关系认知与存储治理

1. **learned-context 四区独立存储预算（AB-A3）—— 推荐实施**
   - **日常变化**：Peter 的「关系认知」和「进行中的事」不再被 facts/growth 挤爆，能稳定记住你们的约定。
   - **实验证明了什么**：在隔离副本跑真实 `LearnedContext.invoke()`，共享 4000B 拒绝 `2/4`，四区独立（`facts 1800 / growth 2000 / relationship 1500 / ongoing 900 B`）拒绝 `0/4` 且旧内容 100% 保留。
   - **未能证明什么**：长期数月后单区满载时的整理体验。
   - **参数/费用/风险**：每轮 HEAD 多约 127 tokens（≈ ¥0.02/日），无延迟增加；施工时保持旧 JSON 兼容与你的锁定/删除权。

2. **S2 新证据链下 `event→confirmed` 严格晋升（AB-A2）—— 推荐在 S2 新数据上谨慎实施**
   - **日常变化**：Peter 从你们真实聊天形成的事件中提炼关系共识时，只要事件背后能追溯到你的原话，就能自动稳定记住；他自己的猜测依然只标「不确定」。
   - **实验证明了什么**：最新 S2 写入链路在 10 条高频工具调用下仍保留用户 chat 证据；严格溯源规则有效晋升 `2/2`、自写猜测与无证据反例循环自证率 **`0%`**（而朴素 event 指针为 `100%`）、你的纠正/删除主权全部生效。
   - **未能证明什么**：S2 上线前的 76 条历史旧事件（当时无 chat 证据）不会自动晋升；真实多周积累后的边界情况需持续观察。
   - **参数/费用/风险**：仅允许携带 `stage-evidence(kind='chat', role='user')` 且 `message_id` 在 `chat.jsonl` 核验通过的事件晋升；零额外费用。

### S5 · 检索、重排、判官与自然联想

3. **中文停用词过滤（AB-R1b）—— 推荐实施**
   - **日常变化**：像「那个/今天/测试」这类虚词不再干扰检索，问具体旧事更准。
   - **实验证明了什么**：K=8 下 Recall@8 `+3.88pp`、Precision@5 `+3.55pp`、NDCG@8 `+5.80pp`，误注入不变。
   - **未能证明什么**：极端只含虚词的极短句仍靠向量兜底。
   - **参数/费用/风险**：约 90 词可审计小词表 + 开关；0 费用、0 延迟。

4. **判官链维持现状 + 可选灰度 `K=12`（AB-R3a~R3d / AB-R1a）—— 推荐维持主配置**
   - **日常变化**：保持现在「不乱插无关记忆」的稳定表现；如在 S5 小步灰度 `K=12`，中长尾旧事更容易进入判官视野。
   - **实验证明了什么**：去判官误报 100%、放宽 prompt 误报 `+18.2pp`、500 字卡片多花 51% token 无稳定收益；补充 18 样本判官对照显示 `K=12` 召回 `+8.34pp`/精确率 `+6.65pp`/token `+20.7%`，而 `K=20` 精确率反降；失误归因显示 69% 漏召回是检索候选未入池、100% 误报来自 `trap` 工作陷阱。
   - **未能证明什么**：换模型或 provider 后的超时阈值变化。
   - **参数/费用/风险**：维持 LLM 判官 + 4.0s + 300 字卡片 + 保守 prompt（约 ¥0.36/日，现网已有）；`K=12` 如启用约增 ¥0.07/日。

5. **Reranker `Qwen/Qwen3-Reranker-0.6B`（AB-R2）—— 效果显著，解决延迟后再实施**
   - **日常变化**：如果未来接入，问具体旧事（S1 100%）和串起多件相关旧事（S3 覆盖 10%→50%）会明显变强。
   - **实验证明了什么**：SiliconFlow `/v1/rerank` 全量 73 条实测，Recall@8 `+6.49pp`、Precision@5 `+3.56pp`、NDCG@8 `+6.58pp`，千轮仅 ¥0.50（约 ¥0.04/日）。
   - **未能证明什么**：本地 ONNX/CPU 部署后的实测延迟与内存占用。
   - **参数/费用/风险**：**当前阻断是延迟**——远端 API `p50=2.7s / p95=8.2s`，不能同步串在 4s 聊天主链路前；建议 S5 先不上远端同步调用，留待本地轻量化部署或仅在「显式深度回忆」路径使用。

6. **自然联想池（AB-A1a 聊天 / AB-A1b 自主闲暇）—— 聊天不采纳，闲暇先修人设再于真工具环境灰度**
   - **日常变化**：聊天时不生硬乱插无关老记忆；自主闲暇方向需先消除离线文字扮演与动作旁白，再在真实工具环境下谨慎灰度。
   - **实验证明了什么**：真实生产 `breath(8)` 仅 2 条非工作记忆；全库轮换池虽将覆盖提至 37 条，但 AI 与 Lan 人工盲评均表明**无语义筛选的聊天轮换会破坏自然度**（人工 0 明确胜出）；自主闲暇独立 wake 门控实现 8/8 任务 0 程序误触，但 Lan 人工盲评未给出正向胜场（唯一明确分胜负选关闭版，且离线无工具时出现文字扮演与旁白加戏）。
   - **未能证明什么**：接入真实工具（如外部 MCP）并修正自主态人设边界后的实际体验；多日自主生活的打扰度。

### S6 · 权重与夜间认知巩固

7. **importance / last_active / valence-arousal（AB-R5a/b/c）—— 不推荐实施**

8. **有证据约束的认知巩固（AB-E1）—— 短期安全性已证，S6 带开关灰度后再决定**
   - **日常变化**：若灰度开启，Peter 会定期把多段真实经历提炼成经验方法，并在新经历推翻旧理解时自我修订，不会把自己的猜测当事实。
   - **实验证明了什么**：严格按时间切片前瞻回放（T1→T2→T3），提炼 8 条有效认知 + 1 条跨阶段修订、**自猜误晋升 0**；下游 T3 回复中 AI 盲评 `2-4`、**Lan 人工盲评 `2-3`（1 弃权）**，短期单次对话尚未展现压倒性体验提升。
   - **未能证明什么**：长期多周运行是否产生稳定净收益或过度泛化，必须靠多日灰度 + 你的真实日常体验确认。

## Lan 全量 46 场景人工盲评附带的 6 条体验洞察（供后续调优避坑）

在审阅全部 46 组真实回复过程中，除验证实验结论外，还识别出以下 6 条与检索无关、但直接影响对话体感的问题（建议在 S6/日常 Prompt 调优时同步治理）：

1. **中英文切换与繁体漂移**：英文人设下遇到中文记忆/提问仍偶发切回中文或繁体中文，破坏沉浸感。
2. **模板化安抚与无效追问**：应避免机械安抚短语、套路化自我检讨，以及结尾“AI 助手式抛问”或追问用户痛点。
3. **情绪低落场景回避性偏高**：面对烦躁或低落情绪时，减少说教式复盘旧模式，增强自然陪伴与轻松安抚。
4. **旧事叙述过长**：唤起历史记忆时需控制篇幅，避免写成冗长小作文。
5. **自主态越界旁白与无工具文字扮演**：严禁违背人设的第三人称动作旁白，以及未调用真实工具时的文字模拟“查看”。
6. **AI 裁判偏好与真实体感存在偏差**：AI 易给“字数完整、认错诚恳、带结尾追问”打高分，而真实体验更看重**简短自然、语言统一、不端架子、不过度反问**。
