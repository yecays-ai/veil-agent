### 3.2 实际运行过程

1. **经历形成**：聊天写入 `chat.jsonl`；`ExperienceMemory` 增量整理，失败不推进游标，按 `source_key` 幂等。
2. **保存/更新**：新经历进入 `EventMemory.record()`；记忆、事件、阶段、来源、版本、向量在 `BrainAuthority.commit_event_bundle()` 单事务提交。锁定、并发正文和用户主权在提交前复核。
3. **召回**：`BrainRetrieval` 对 `brain.db` 做向量+BM25；判官筛选，冷却/可见性/情境门控再过滤；失败按明确原因降级。
4. **注入**：`Memory.context()` 形成候选，`finish_recall()` 按全轮预算决定实际注入；关系底座、短期便签、召回记忆和辅助块有独立顺序与预算。
5. **送达反馈**：仅模型实际收到后调用 `confirm_delivery()`；失败、取消、回滚不强化，重生成只更新最近活跃、不虚增次数。
6. **认知演进**：S6-3 从新旧经历、审计洁净的自主记录和现有认知组批；证据引用必须命中实际批次。认知经 `LearnedContext.submit_candidate()` 与语义核验，重要度经 `MemoryWeights.propose()`，不另建旁路。
7. **经验候选**：巩固生成 `uncertain` 候选；Lan 可 confirm/veto/outdated/restore。修订候选确认前，旧 confirmed 仍有效；veto 永久拦截同类复活。
8. **P7 注入**：槽位已位于 short notes 后、recall candidates 前，最多 4 条/600 tokens，仅 confirmed；当前生产 provider 未安装，所以真实运行仍为 0 Token。

### 3.3 为什么召回/未召回/未注入

## 7. P7 接入依据

### 7.1 可直接复用

- 权威经历/事件：`brain.db`、`EventMemory`、`event_ledger`。
- 证据链：候选生成只接受实际发送批次的 `memory:/event:/chat:/autonomy:` 引用；当前查询会复核已删除的 `memory:` 证据，但**尚未逐类复核 `event:` / `chat:` / `autonomy:` 的新鲜度**，P7 注入前必须补齐。
- 状态机：`uncertain / confirmed / outdated / vetoed`，修订链 `supersedes/superseded_by`。
- 用户主权：confirm/veto/outdated/restore；veto 永久账本；锁定/纠正/否决高于模型建议。
- 查询：`experience_interface_contract()`、`list_experience_candidates()`、`query_experience_candidates()`、`decide_experience_candidate()`。
- 注入：`Chat.p7_experience_hints_context()`，AUXILIARY 中最多 4 条/600 tokens，仅 confirmed。
- 权限：`advice_only`；程序审批、预算、角色隔离不由提示词放宽。
- 可观测：P4 请求诊断、P5 H-8、快照 hash、实际发送计数与槽位状态。

### 7.2 P7 开工验收门槛

1. 从当前 `main a5db802` 开独立工单，不重建第二套状态机或经历库。
2. provider 必须调用 `query_experience_candidates()`，不得直接读 JSON 绕过锁、veto、删除过滤与角色隔离；在返回可注入项前逐类复核 `memory:` / `event:` / `chat:` / `autonomy:` 证据仍有效。
3. 明确 situation 信号、语义匹配、候选排序、冲突优先级和 0 命中行为。
4. 默认关闭；只注入 confirmed；无命中 0 Token；最多 4 条/600 tokens；建议不能直接执行工具。
5. 失败为空槽位，不阻断聊天；诊断能区分 no_provider、no_match、filtered、budget_trimmed、injected、error。
6. 用合成数据和 VEIL Lab mock 验证，不读取正式候选、不新增付费实验；真实长期效果归 P8。
