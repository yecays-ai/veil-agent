# VEIL Reliability｜长期可靠性工程计划

## 目的与维护规则

本计划让关键行为的退化更容易在合并前发现，并让运行期异常能够被追踪和安全处理。`STATUS.md` 是唯一当前进度；`HANDOFF.md` 只用于窗口交接；本文只保存稳定的阶段路线、行为契约、证据类型和退出条件，不把某个 PR、CI 或体验验收状态当作长期结论。

统一施工原则：以最新 main 和仓库状态文件为准；优先复用成熟实现，不另建测试框架；每张工单只处理一个明确问题；自动测试只用虚构数据和假服务，不用真实聊天、记忆、密钥或付费模型；自动通过不替代适用的 Windows 体验验收；不因检查过度限制正常的 Peter 行为。预算尚未完全闭环的问题保持独立未关闭项，不在本计划中宣称已解决。

## 阶段一｜质量契约盘点（已完成：只读审计）

目标是核对自动测试、CI、安全扫描和审查机制，梳理记忆、工具权限、自主任务、备份恢复、桌面和重启连续性等关键行为，并按实际风险形成缺口清单和最小施工顺序。退出条件是每个已确认缺口有源码或运行证据、优先级和后续最小方案；审计本身不改变产品行为。

## 阶段二｜核心数据与跨模块行为回归（已完成）

保护记忆隐藏、检索、历史、目录及访问权限的一致性；保护自主任务执行、结果核实、检查点和重启恢复；验证文件操作审批与实际结果、聊天/记忆/任务/备份数据完整性，以及服务异常、写入失败、断线和重启的安全边界。已确认的真实缺陷应以真实内部接线、虚构数据和必要的受控故障注入保留永久回归，不以测试数量代替拦截证明。

退出条件：关键行为遭破坏时，相关测试能失败并指出边界；正常可见、可用的数据不被误拦截；已确认的阻断缺陷已处理，未验证的 Windows 体验明确保留待验收。

## 阶段三｜GitHub 强制质量门禁（退出证据已完整；收尾 PR 受门禁保护）

让必要的自动测试、安全扫描和第二阶段跨模块回归在 PR 合并前运行；补齐桌面、共享网页、服务、启动脚本和依赖的触发范围；只关注功能、安全和数据风险的审查意见，并验证最终提交的 CI 与分支保护。Cubic 的评论或普通 GitHub review 不视为 required status check。

退出条件：main 对所有人（含管理员）要求通过 PR 合并；最新 PR 提交必须通过四平台 Tests 矩阵与依赖安全检查，缺失、失败、取消或过期的检查不能放行；直接推送和绕过保护不可用。用安全的模拟 PR 验证失败拦截、修复后放行、必要检查缺失时阻止合并，并核验 main 的实际保护配置。Cubic 按现行流程完成审查，但不伪装成 GitHub required status check。

## 阶段四｜Windows 真实运行验证（已完成）

验证 Agent 的启动、关闭、重新连接和重启，正常聊天、记忆、工具调用、自主活动和长期任务，Electron 与本地服务协同，持续运行、异常断线与恢复，并以虚构角色验证备份恢复。自动验证和 Lan 的真实体验分开记录。

退出条件：开发端先在隔离环境完成端到端验证，Lan 再按明确场景验收；数据不丢失、不重复，异常时有可理解的反馈和恢复办法；未验收内容保持待验收。

## 阶段五｜运行期监测与安全恢复（已完成）

检测后台活动、记忆服务和任务状态等异常，记录不暴露私人数据的必要诊断，区分可自动恢复与必须暂停处理的故障，避免恢复时重复执行结果不明的副作用，并保留暂停、恢复和问题追踪能力。监测不得产生无意义模型请求或频繁通知。

实现复用 Ombre 有界恢复、长期任务副作用检查点、文件工具状态、能力快照和自主活动开关，形成一个角色隔离的本地安全摘要。它由已有事件驱动，不轮询服务、不发送后台请求、不调用模型；只保存固定诊断字段。服务恢复与原操作完成分别记录：只有安全重发得到成功回执才标为已恢复，结果不确定的写入保持 unknown；自主副作用不确定时保留检查点并暂停活动。

退出条件已满足：虚构故障注入覆盖安全恢复、unknown 保持、暂停、防重复副作用、诊断脱敏和零模型探测；运行状态在现有网页与 Electron 共用页面显示。Reliability 五阶段正式完成，后续回到产品功能开发。

剩余低风险事项作为普通 backlog：状态页只保留最近一次安全摘要，不扩展历史监控后台；只有出现明确功能阻断、数据丢失、安全问题或重大成本风险时才另开 bug 工单，不自动延伸新的 Reliability 阶段。

## 证据与验收边界

源码与单元/跨模块回归可证明内部契约；GitHub CI 可证明受支持平台的自动检查；真实 Windows 体验只能由相应场景验收确认。任何一类证据都不替代另一类。后续只根据已确认实施结果更新 `STATUS.md`，不把路线计划表述为已交付功能。
