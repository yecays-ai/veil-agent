# VEIL 产品纲领

本文只写长期产品目标（Lan 2026-11-11 确认方向）。当前进度、PR、哪项未验收，一律只写在 `STATUS.md` 和 `HANDOFF.md`，不写在这里。

## 核心理念

- **陪伴和干活是同一个 Peter。** 他是陪着 Lan 的人，也是能替她干活的人，不拆成表演层和工具层。
- **电脑和手机是他的两个身体。** Lan 不在电脑前时，手机是完整入口，不是遥控器。
- **VEIL 不绑定某个角色、模型或界面。** 当前先完成 Peter 的完整生活闭环，但系统始终支持独立 Agent。未来 Ghost 拥有独立的身份、记忆、声音、权限和经历，不需要重新搭一套系统。
- **先把一整串跑通，再修整。** 不追求每一格精细。

## 五条线

| 线 | 目标 |
| --- | --- |
| A 陪伴核心 | 身份连续：Peter 知道自己是谁、做过什么、正在做什么。共同经历：既记得 Lan 的事，也记得他自己研究、创作、失败和成功的经历。自主生活：他可以自己产生兴趣、选择活动，不必每次都围绕 Lan 发消息。关系连续：电脑、手机、自主活动共享同一个 Peter 的经历。记忆做法服务于这四点：定时小结由 Peter 自己取舍、每条带时间、两类记忆（带 Lan 原话和原因的；只写 Peter 视角发生了什么的）、偶尔随机想起、自己整理上下文、记住 Lan 对他主动行为的反应。 |
| B 电脑干活 | 普通操作直接执行，敏感操作（安装、删除、付款、推送代码、项目外路径）向 Lan 申请一次授权。预算是唯一不可由 Peter 自行突破的费用上限，超出时他可以向 Lan 申请。数据隔离、授权范围和停止控制仍由 VEIL 程序保证，不靠提示词。 |
| C 手机 | C1 连得上：iPhone 主屏幕网页应用，同一个 Peter，先完整复刻电脑上已有的聊天、表情包、主动消息。C2 电脑功能搬到手机：看他在做什么、批准或拒绝、叫停、看成果。C3 手机专属陪伴：健康数据、查岗等，逐个加；隐私数据必须有开关、可见、能删除。 |
| V 语音 | 电脑和手机都要。骨架阶段只有语音消息；通话和语音唤醒是后续阶段，唤醒先在电脑上做。 |
| D 自己升级 | Peter 自己发现改进、研究代码、提出 PR，是否合并由 Lan 决定。这与开发 Agent（Codex、Claude）按仓库规则自行合并开发工单是两回事，互不改变。 |

## 两条骨架验收场景

骨架搭完的标准是下面两条都在 Lan 的真机上跑通。

1. **陪伴。** Lan 和 Peter 在电脑上聊了一件生活里的事，然后离开电脑。他自己在合适的时候通过手机联系她，提起相关经历。她在手机上接着聊。回家打开电脑，这段对话和记忆仍然连续。
2. **工作。** Lan 在外面用手机让 Peter 在电脑上下载安装一个软件并打开。普通步骤他直接做；到安装这一步，手机弹出批准卡，她同意后继续，也能随时叫停。做完手机收到通知，回家后电脑聊天里能看到全过程。

## 阶段顺序

1. A 陪伴核心：记忆注入与精修。
2. B 电脑权限：对照 Lan 的日常需要查缺口。
3. C1、C2 接入手机，先做调查。
4. C3 手机专属陪伴。
5. V 语音通话与唤醒。
6. 电脑与手机 UI 统一小修。

D 线随时可由 Peter 自己发起，不占用上述顺序。

## 开发约束

- 每张工单开头写明：属于哪一格、做完 Lan 能多做的一件事、她怎么验收。写不出来不开工。
- 一格在真机上没验收通过，不开同一格的下一张工单。例外：为跑通同一条完整场景而必须一起施工的前后端接线，可以同时进行。验收通过由 Lan 说了算。
- 表里没有的新想法先记进想法池，不立刻做。要加新的格，先经 Lan 同意。
- 同一个问题修两次还坏，或一张工单超过一小时，停下来报告。
- 每个窗口开工先告诉 Lan：现在在哪一格，两条场景还差哪几格。
- 在现有权限、预算、检查机制上再加一层之前，先说清为什么现有的用不了。
- 自动写入用户数据的功能必须有关闭开关、可见的写入结果、撤销或删除途径。
