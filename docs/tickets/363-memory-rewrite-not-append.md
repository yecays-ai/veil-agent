# 工单 363：记忆不再越整理越长（第 1 步：堵住膨胀）

所属格：A 陪伴 · 记忆。路线（三步）见项目共享的「记忆改进路线」文档；本单是第 1 步，不碰现有记忆、不改自动想起。

## 起因（已核对）

Lan 2026-11-15 的只读审计（193 条，逐条读）：记忆越整理越长、越碎。原因有两处，都在代码里确认过：

1. `hold(target_id / merge_ids)` 把源条目全文拼到目标后面，源条目原样留着（`memory_native.py` 旧合并分支）。审计：123 次编辑 78 次是追加，净增约 4.2 万字；一条游戏账本被追加 24 次到 14,584 字。
2. Ombre 自己的 `hold` 在搜到很像的旧记忆、模型又判定是同一件事时，用 `---` 把新内容拼到旧记忆后面并换掉标题（Lan 电脑上固定版本 Ombre 源码 `tools/_common.py` 的 `merge_or_create`、`tools/hold/core.py` 的 `raw_merge=True`），Peter 不知道。
3. 353 之后自动想起只带超过 600 字记忆的开头，所以拼在末尾的「后来」从来没被想起。

## Lan 已定（2026-11-15）

- 更新一条记忆就是整段重写，放权给他：可以自由重组、整合，不强制保留旧句子。
- 被合并的旧条目归档，不删。
- 三条底线：原始聊天和历史版本不丢；Lan 有最终修改权（改、恢复、锁定）；不编造。
- 采纳外部意见的部分（Lan 交由开发侧决定）：600 字作为硬上限（理由是上面第 3 条）；重写漏掉旧文里的日期时提醒一次；有相关旧记忆时必须先选，不能直接新建；工具说明写清合并和关联的界限。专有名词检查没有做：他的记忆多是英文小写，抽不准。

## 价值

| 输入 | 系统行为 | Lan 看到的 |
| --- | --- | --- |
| 接着聊 Fog Tide 的新进展，他想记 | 程序先找出最像的 3 条旧记忆给他，他选「更新」并整段重写 | 记忆页还是那一条，内容是新的整段回忆，没有变长一截；「历史版本」里有旧的 |
| 吵架后和好了，他想记 | 他选「关联」 | 多一条和好的，详情写着「接着『吵架那条』」 |
| 三条记同一晚的，他合成一条 | 重写目标，其余两条归档 | 「已归档」里有那两条，写着并进了哪条，可一键恢复 |
| 她改对了一条并锁定 | 他再改这条会被挡住 | 锁定的条目前面有 🔒 |
| 她改过一条，他后来又改了 | 记录下来 | 列表和详情标「他改过你改的」，可恢复她的版本 |

比最简单的办法（只改说明文字让他先搜再记）多的：那句说明以前就有，没用；这次由程序把候选递到他面前，重写、归档、锁定由程序执行。

## 找轮子

- 复用：Ombre 自带的归档（`trace delete=true` 是软删除进 `archive/`，`restore=true` 恢复，默认搜索不含归档）、Ombre 配置 `merge_threshold`（VEIL 启动 Ombre 时本来就写配置）、VEIL 的版本记录 `memory-versions.jsonl`、353 的展示方式。
- Ombre 不能按请求建立两条记忆之间的关系（`relink` 只能改已有关系），所以「接着哪条」记在 VEIL 侧 `memory-sidecar.jsonl`（只追加的事件记录，不含正文）。
- 参考：旧仓库 veil 的记忆维护（新建 / 更新 / 合并 / 归档）；SillyTavern 反复重写会走样的经验，所以每次重写都留旧版本、她能锁。
- 不魔改 Ombre，不新增依赖。

## 做了什么

1. Ombre 自动拼接关掉：`resident_config` 写 `merge_threshold = 1000`；`[memory] ombre_auto_merge = true` 恢复。Ombre 重启后生效。完全相同的文字 Ombre 仍会认作同一条。
2. 新记忆（`hold` 不带 `target_id`）：程序先用他的标题和正文搜 3 条可见的旧记忆。有的话这次不存，把它们（各前 300 字）给他看，让他选：同一件事 → `target_id` 整段重写；后来的阶段 → `link_to`；都不是 → 原样再发一次就存成新的。状态显示「待他选择」。
3. `hold(target_id)`：整段替换，旧版本进版本记录；`merge_ids` 的条目逐条归档（先留旧版本），记下并进了哪条；旧文里的日期（10-31、10月31日、oct 31 等）在新文里没有，提醒一次，原样再发一次就存。
4. 他写的每条记忆最多 600 字（`hold` 和 `trace` 整段替换都管；她在记忆页写不受这个限制，仍是 1500）。
5. 锁定：她锁的条目，他的 `hold`、`trace`（改、删、归档、合并掉）都被挡，读和 `reinforce` 照常。
6. 每次存、重写都在侧车记一笔时间（`hold` / `rewrite` / `experience` / `experience-rewrite`）。
7. 354 经历整理：「改了想法」从追加一行改成整段重写（最多 500 字），给模型看的旧条目从末尾 400 字改成整条（最多 1200 字）；锁定的不改。
8. 记忆页：分组多一个「已归档」（可恢复）；详情多「锁定 / 解锁」「历史版本」（可恢复成某一版）、「接着 / 后来的 / 并进来几条 / 最近一次写于」；他改过她改的会提示，点「知道了」消掉。

## 可能变差（对比时逐项看）

- 多一步，他可能嫌麻烦少记了（看每天存的次数）。
- 重写可能丢细节或口气走样；可能编出没发生的事。
- 关联可能连错。
- 每次新存多一来一回，多一段候选文字进上下文。
- 600 字对复杂的事可能不够。
- 想得起对的、不反复冒同一条、不带不相关的、长期不丢不错、能看能关能删。

## 回退

`[memory] ombre_auto_merge = true` 只恢复 Ombre 的自动合并；其余行为随代码回退。侧车文件可以直接删除，不影响记忆本身。

## 验收（Lan）

1. 接着聊一件之前他记过的事，让他记：记忆页是原来那条变了，没有多一条，也没变长一截；详情「历史版本」能看到旧的。
2. 一件事的后续（例如吵完和好）：多一条，详情写「接着」哪条，两条各自的态度都在。
3. 一件完全新的事：正常新建，没乱连。
4. 改一条并锁定，让他改这条：他做不到。解锁后他改了，列表上标「他改过你改的」，「历史版本」能恢复你的。
5. 让他「记一下今天 Fog Tide 赚了多少」：他不往记忆里写（去计划或实验室文件）。
6. 「已归档」里能看到被并掉的条目，点恢复能回来。
