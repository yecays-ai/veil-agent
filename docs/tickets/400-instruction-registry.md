# 工单 400：指令登记表（四部分之一：指令统一管理）

## 目标

把分散在代码里的提示词统一登记，解决写死的问题；新增指令自动进入管理系统，不需要再改页面。

这是 Lan 定的四部分计划的第一部分。完成后：所有会进模型的文字都有编号、有默认文本、有分类、
有注入位置；Lan 改过的存在本机并覆盖默认；以后加提示词必须登记，否则测试失败。

## 本单做了什么

- 新增 `prompts/`：登记表（registry）、覆盖层（store）、默认文本（defaults）、防写死的扫描（inline）。
- 迁移 22 条文本：系统事实、说话样例说明、四个聊天工具说明、背景说明、记忆笔记三段、
  自动想起/开场记忆的开头与空态、经历笔记开头、醒来提示的行为段/过渡句/跨唤醒线索/已读未变、
  瞄一眼说明与收尾、关于你的开头说明。
- 其余条目先登记为 file / marker：人设、背景、样例、记忆笔记、时间账本、历史、断点、
  召回、卡片、弹幕、渠道标记、待批准、长期任务、生活记录、Lab、想法、预算、错过的闹钟。
- 新增只读接口 `GET /api/instructions` 和「指令」页（只读列表，按八类折叠）。
- 改造前后对同一场景的请求内容做逐字节对比：一致。
- 启动时校验登记表；新增测试覆盖登记表、覆盖层、只读权限、工具说明按请求读取、防写死扫描。

## 没有做（下一单）

- 编辑界面、中文说明、搜索（工单 401）。
- 其余工具说明逐条迁移（`prompts/inline_allowlist.txt` 是清单）。
- 请求快照（第三部分）、长期维护门禁细化（第四部分）。

## 验收（Lan）

1. 更新重开，左侧出现「指令」。
2. 打开能看到八类、全部条目；点开「自主活动 → 醒来提示的行为段」能看到原文。
3. 在 `persona/instructions/` 放一条 `autonomy.wake.rules.md` 覆盖后，重启看新内容（本单还没有编辑界面）。
4. 我新增一条登记后，刷新页面自动多一行，不用改页面。

## 风险

- 文本搬家可能改变措辞：已用逐字节对比验证，且现有 276 个测试通过。
- 缓存：只改启动校验与显示，不改变请求顺序；`test_cache_order` 通过。
