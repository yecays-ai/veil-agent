# 工单 408：工具参数解析容错（换行、智能引号、尾逗号）

属于：A 陪伴核心（他能把关于你的事写进 Learned Context）
做完 Lan 能多做的一件事：他写「关于你」的段落时，不会因为正文里有换行或引号就被程序打回；就算还失败，报错里也会带上他发来的原文，他能照着改。
她怎么验收：让他记一件关于你的事（或等一次自主活动里出现 `jot_about_lan`），看是否写进去；在 Peter 页的 Learned Context 里能看到新内容。

## 当前状态

2026-11-20 晚上，`jot_about_lan`（`profile_append`）当天 **11 次尝试、0 次成功**，全部被「arguments are not a valid JSON object」拒绝。10-28 也有过 5 次，同类问题一直存在，只是当天集中爆发。

原因：模型把整段中文直接放进 JSON 字符串，正文里的**换行、智能引号、尾逗号**没有转义，`json.loads` 和 `ast.literal_eval` 都失败。工单 399 的兜底只在参数不以 `{` / `[` 开头时才当纯文本收下，所以这种「以 `{` 开头但转义坏了」的调用一律被拒，模型也看不到自己发错在哪，只能反复重试。

## 本次改动

1. `veil_agent._repair_tool_arguments`：JSON 和 Python 字面量都失败后，做一次最小修复再解析：
   - 字符串里的裸换行 / 回车 / 制表符转义；
   - 没有 ASCII 引号时，把成对的智能引号当成 JSON 分隔符（值里本来就有弯引号的保持原样）；
   - 去掉对象/数组结尾的多余逗号。
2. `Chat.tool_arguments`：JSON → `ast.literal_eval` → 修复后 JSON →（不以 `{`/`[` 开头时）纯文本。
3. 仍然解析失败时，拒绝消息里附上收到的前 160 个字符，让他能看到自己发错在哪并重试。
4. 其它工具的参数解析、权限、审批、日志都不变。

## 影响范围

- 只影响「参数解析失败」这条路径；合法 JSON、Python 字典、纯文本的行为逐字节不变。
- 修复只在第一次解析失败后发生，不会改变已能解析的调用。
- 拒绝消息变长（附原文片段），工具结果仍有长度上限。

## 验收步骤

- 自动：`tests.test_chat.ToolArgumentTests`（新增 4 个：裸换行、智能引号作分隔符、尾逗号、形似对象但确实坏掉的文本仍拒绝）、`tests.test_tools`（拒绝消息带原文），以及 `tests.test_chat`、`tests.test_tools`、`tests.test_prompt_registry`。
- 真机：让他写一条关于你的内容，看是否成功；失败时看他能不能根据错误里的原文改对。

## 风险与回滚

- 改动集中在 `veil_agent.py` 的参数解析与拒绝消息；修复是「多一次尝试」，不改语义。回滚即 revert。
- 已知边界：如果正文里有**没转义的英文双引号**，字符串边界本身就不可判定，修复不了，仍会被拒绝（但错误里会带上原文）。
