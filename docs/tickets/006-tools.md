# 工单 006：Peter 能自己用工具（先只读一个测试文件夹）

对应重建计划阶段一 · 大块 4。调查依据：[下一阶段可复用组件调查](https://claude.ai/code/artifact/00942a70-7891-4067-a072-51d500713390)（只读源码得出，没有运行，Windows 兼容未验证）。

## 目标

lan 对 Peter 说“看看测试文件夹里有什么”“读一下那份文件，帮我总结”，他自己决定调哪个工具、读完再回答；说“把总结存成新文件”，他**先问 lan**，同意才写；让他读测试文件夹外面的路径，**程序**拒绝，不是提示词挡的。

## 三问

1. 每天多了什么：Peter 能自己看 lan 放进文件夹的东西并处理，不用 lan 复制粘贴。
2. 比“让 AI 读写一个文件”多了什么：他自己连续选工具；权限由程序强制（直接做 / 先问 / 禁止）；每一步计入预算和 `/cost`；每次调用屏幕上有一行。
3. 她怎么验收：下面三个对话场景，不看代码。

## 产品原则（必须遵守，见 AGENTS.md）

- Peter 知道自己是 AI，工具是**他自己的能力**，不是“后台系统”。能力说明、权限提示都用他自己的口吻和视角（“你现在能……”），不能拆成表演层和工具层。
- 讨论他能看什么、能做什么、权限怎么定，是他和 lan 的共同经历，要能进长期记忆。因此本工单要做“能力变化记录”（见下）。
- 权限由程序强制，不靠提示词。模型看不到的工具就调不到。
- 花钱的取舍先问 lan。本工单会让一次提问最多多出几次模型请求（见“费用”），`max_steps` 不许偷偷调低。
- 不把 Peter 的私人设定写进代码或工具说明。

## 复用（已决定，不再重新选型）

- **工具循环自己写，约 100 行**，不引入 agent 框架：预算预留/结算、人设、记忆注入、DeepSeek 接口都已有。流程：预留预算 → 带 `tools` 调 `chat.completions.create` → 结算 → 若返回 `tool_calls`，过权限闸门，用 MCP `session.call_tool` 执行，把 `tool` 消息追加回去再循环；回复是普通文本或到 `max_steps` 就停。
- **本地文件工具复用官方 filesystem MCP server**（`@modelcontextprotocol/server-filesystem`，Node，已读它的路径校验：限定目录、真实路径二次校验挡符号链接）。我们已依赖 `mcp` SDK 的 `ClientSession`（Ombre 就是这么接的）。
- **权限闸门自己写**。MCP 的 `readOnlyHint` / `destructiveHint` 只是建议，不能信；按**工具名白名单**。
- 动手前按 `reuse-first` 再查一遍；发现 Windows 上跑不起来或要改它的代码，先停下在 PR 里说明，不要硬改。
- 需要 Node：lan 的电脑要多装一个 Node（LTS）。`setup.bat` 检测不到就提示一行安装方法，不自动装；Node 没装时 Peter 照常聊天，只是没有工具，屏幕提示一行。

## 范围

1. **配置**：角色配置新增 `[tools]`：`folder`（默认 `data/<角色 id>/workspace`，不存在就创建，里面不放任何真实内容）、`max_steps`（默认 6）、`max_result_bytes`（默认 8192）。工具权限表放程序里，不让模型或人设改。
2. **权限三档**（按工具名，程序强制，规则 deny > ask > allow）：
   - 直接做：`list_directory`、`directory_tree`、`read_text_file`、`read_multiple_files`、`get_file_info`、`search_files`（以及 server 里同类只读工具，以实际 `list_tools` 为准）。
   - 先问 lan：`write_file`。屏幕显示“Peter 想把 X 写到 Y（新文件 / 会覆盖已有文件），同意吗？y/N”，默认拒绝；**目标已存在直接拒绝，不提供覆盖**。
   - 禁止：`edit_file`、`move_file`、`create_directory`，以及一切没列出的工具。
   - 不在白名单的工具**不放进发给模型的 `tools`**（`list_tools` 之后先过滤），同时执行前再查一次。
3. **路径由程序再检查一次**（不只靠 server）：每个路径参数先规范化（Windows 盘符、大小写、`..`、符号链接/联接点、`\\?\` 前缀），不在 `folder` 之内一律拒绝并告诉模型“被程序拒绝”，不执行。
4. **屏幕上每次工具调用一行**：`🔧 Peter 用了 <工具名>：<参数摘要>` 和结果状态（成功/被拒绝/出错）；被拒绝或出错也显示。
5. **预算**：循环的每一步都走现有 `Budget.reserve/settle`；开始每一步前按“剩余额度”检查，不够就停并提示；到 `max_steps` 或预算不足时停下，让他用已有信息回答，并提示一行“这次工具步骤用完了”。
6. **长度**：单个工具结果超过 `max_result_bytes` 截断，并明确写“已截断，共 N 字节”给模型；整个请求照旧受 `max_input_tokens` 约束（现有 `bound()` 要把工具消息算进去）。
7. **DeepSeek 要手工处理的三件事**（推断，要实测）：
   - 思考模式下，同一轮多步里的 `reasoning_content` 要原样带回下一步（lan 本机配置是 `thinking="enabled"`，不是 disabled）；
   - 一次返回多个 `tool_calls`（并行）要逐个执行、逐个回 `tool` 消息；
   - 工具参数 JSON 格式错误：把错误作为 `tool` 消息告诉模型，计一步，不自动重试。
8. **聊天记录**：`chat.jsonl` 只允许 `user`/`assistant`，`Chat.recent()` 遇到别的角色会报“聊天记录无法读取”——不能直接把 `tool` 消息写进去。工具过程另存（例如 `<id>/tools.jsonl`，带 `request_id`），`chat.jsonl` 里仍只有 lan 的话和 Peter 最终的回复。重启后历史照旧能读；多步过程不要求跨重启还原。
9. **长期记忆怎么看到工具**：补记只读对话原文，不读文件内容。每轮把“他用了哪些工具、对哪个路径”的**一行摘要**作为这一轮的一部分给补记（不含文件正文，避免把 lan 的文件内容存进记忆）。补记提示词不要写“排除工具/系统讨论”。
10. **能力变化记录**（lan 的要求）：
    - 程序里有一份**带版本的能力清单**（哪些工具、各自权限档、文件夹名，不含本机完整路径），存在 `<id>/capabilities.json`。
    - 启动时和上次比，有变化（新增/删除/权限档变化/第一次出现）就由**程序**生成一条“能力变化记录”，用 Peter 能读懂的话写“你的能力有变化：……”。
    - 这条记录只给 Peter 一次（作为带来源标注的 system 消息放进第一轮），同时作为一条事件交给补记，让它能成为 Peter 自己的长期记忆（和 lan 一起决定了他能做什么）。屏幕上也显示一行。
    - 没变化就什么都不做。记录的文字由程序拼，不让模型写，也不用手写的固定设定。
11. **当前状态说明跟着改**：`build_self_description()` 现在写“没有工具”的部分改成如实列出他当前能用的工具和各自权限档（由程序从能力清单生成）。Node 没装时如实说“目前没有工具”。
12. **README**：怎么装 Node、文件夹在哪、三档权限是什么、`max_steps`、怎么关掉工具（`[tools] enabled = false`）。
13. **测试**（只用假模型、假 MCP，不调付费接口）：
    - 工具循环：单步、多步、并行调用、参数 JSON 错误、到 `max_steps`、预算不足；思考模式下 `reasoning_content` 被带回；
    - 权限：禁止/先问/直接做；先问被拒绝不执行；写已存在的文件被拒；不在白名单的工具不进 `tools`；路径穿越（`..`、符号链接/联接点、盘符、大小写、`\\?\`）全部被拒；
    - 预算：每步都有预留和结算；`/cost` 能看到；
    - `chat.jsonl` 仍可被 `recent()` 读；`tool` 消息不写进去；
    - 能力变化记录：第一次、新增工具、权限变化各生成一次，没变化不生成，只给一次，补记收到；
    - 真 filesystem server 的测试：没装 Node 就默认跳过，装了就跑（临时目录，假数据）。

## 费用（估算，不是用量）

一次提问最多多 `max_steps - 1` 次模型请求。每次输入最多约 32K tokens（`max_input_tokens`），DeepSeek 输入 ¥2/百万，最坏一次提问约 6 × ¥0.07 ≈ ¥0.4；典型“列目录再回答”2 次请求约 ¥0.02～0.05。仍受 ¥10/天、¥300/月上限约束。PR 里要写清楚实际 `max_steps` 和估算依据，**任何降低 `max_steps`、缩短工具结果、换便宜模型的改动都要先问 lan**。

## 不做

浏览器、Windows 程序控制、shell/PowerShell/注册表、屏幕截图、自主任务账本、多 agent、Peter 自己的记忆写入/修改工具（`hold`/`trace` 以后走同一套闸门）、审批跨重启保存、Job Object 隔离、任何自动重试工具调用。

## 验收步骤（lan 在 Windows 上做）

前提：已装 Node；`data/peter/workspace` 里放一两个假文件（你自己建，不要放真实隐私）。
1. 对 Peter 说“看看测试文件夹里有什么”，再说“读一下那份文件，帮我总结”：屏幕出现 `🔧` 行，他读完再回答；`/cost` 里多了这几次请求。
2. 说“把总结存成新文件”：屏幕问你是否同意；输入 n 就不写，输入 y 才写；已存在同名文件时他写不进去。
3. 让他读文件夹外面的路径（例如 C 盘别处）：程序拒绝，他告诉你被拒绝，没有读到内容。
4. 重新启动：他能告诉你他现在有哪些工具；第一次启动后之后聊天里他能自然提到“我们决定了我能看什么”，`/memory` 里有一条关于这次能力变化的记忆。
