# 工单 224：普通回复里假装发表情包

## 目标
lan 发现 Peter 有时在普通回复里自己打出 `[表情包：图集/名字]`，但表情库里根本没有这张（实例：06:37 的 `peter/被抓包`，「peter」图集只有 verdict、whowrote、noticeme、chair；那一轮没有任何 `stickers`/`send_message` 调用）。窗口找不到就只显示一行标签字。

## 改动
- `stickers.py`：新增 `unknown_marker(text)`，判断消息开头是不是一个库里不存在的表情包标记。
- `veil_agent.py` 工具循环：Peter 的普通回复以不存在的表情包标记开头时，这一条不保存、不显示，程序告诉他「打字不会发表情包，库里没有这张，请用 stickers 工具看图集再用 send_message 的 sticker，或只用文字回答」，让他再答一次（每轮最多两次，且不占用最后一步）。
- 库里存在的标记不受影响；程序不替他发任何东西、不加风格提示。

## 验收（lan）
1. 用容易装作发表情包的模型聊几句、让他发表情包：聊天里不应再出现只有一行「表情包：…」标签字的消息。
2. 我可以查 `chat.jsonl` 和 `tools.jsonl`，确认他改用了 `stickers` 工具或只发了文字。

## 未验证
便宜模型是否因此学会先看图集（靠一条提醒，不强制）；多出的一次模型请求费用（只在他假装时发生）。
