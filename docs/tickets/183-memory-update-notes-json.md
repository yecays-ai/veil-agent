# 工单 183：旧记忆能追加、便签整理不再被格式小差异卡死

## 目标

- Peter 看到过的记忆（自动召回带出来的，或他自己搜到的），之后都能用 `hold(target_id)` 追加新内容，不用先重新搜一遍；没给他看过的、被隐藏的、已抹掉的记忆仍然不能改。
- 短期便签的后台模型回复外面包了代码块或前后带了说明文字时，仍能取出 JSON 并正常整理；真的取不出时，`notes.jsonl` 的 error 行记录模型原话前 300 字、总长度和连续失败次数。

## 现状（lan 电脑 2026-11-01 的数据）

- 140 次新建记忆里 105 次没有先搜；`hold(target_id)` 因「ID 不在本轮搜索结果里」被拒绝 12 次。
- 便签整理 175 次尝试 89 次出错（80 次是「未返回有效 JSON」），11-01 当天 28 次里 26 次失败。

## 做了什么

- `memory_agent.py`：`Memory.surfaced_ids` 记录最近 40 条给 Peter 看过的记忆 ID（自动召回、`breath_search`）。
- `memory_native.py`：`hold` 的 `target_id` / `merge_ids` 接受搜索结果（保留最近 20 条，不再每次搜索清空）和 `surfaced_ids` 里的 ID；后者用时现读硬盘最新正文，仍检查可见性。追加前仍会完整存旧版本。
- `short_term_notes.py`：先严格解析 JSON，失败再取第一个完整 `{...}`；仍失败时 error 行加 `reply_head`、`reply_chars`、`consecutive_failures`。整理逻辑、提示词、检查点规则都没改。

## 没做

- 召回查询带上下文、瞄一眼不召回、合并重复记忆、记忆条目变短：各自需要 lan 决定，另开单。

## 验收

1. 更新后聊几句，等一次便签整理（半小时一次，或点新对话），便签出现新条目；如果后台模型仍失败，`data\peter\notes.jsonl` 最后的 error 行里能看到模型原话。
2. 让 Peter 记一件和他刚被召回的旧记忆是同一件事的新细节：他应该直接追加到那条记忆，而不是新建一条。
