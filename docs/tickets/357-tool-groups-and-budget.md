# 357 工具分组、工具预算和「以后加工具」的固定做法

属于哪一格：A（陪伴核心；工具说明少占位置，聊天原文和他自己的语气才有地方）。

做完 Lan 能多做的一件事：以后给 Peter 加新功能，不用再回头改一遍工具说明；她在「上下文」页能看到每个工具占多大、属于哪一组、最近用了几次。

她怎么验收：见文末。

## 目标

1. 每次请求固定带的工具说明变少，而且不靠再缩说明文字。
2. 以后新增工具有一条写死的规则和一项自动检查，超了就过不了检查。
3. Lan 能看到完整清单，自己判断哪些该常驻。

## 当前状态

依据（2026-11-14/15，Lan 电脑只读统计，只取数字；完整报告在 Lan 审过的方案文档里）：

- 改前：全部组收起时工具说明约 51KB，`social` 展开时约 88KB（这一组 +37KB）；11-14 一半的请求是 88KB。
- 很少用却每次都带的工具：trace 3.6KB（15 天 30 次）、maintenance 2.1KB（5 次）、workbench 2.0KB（45 次）、delegate 1.8KB（2 次）、letter_write 1.2KB（1 次）。
- 「一缩就不调用」在她的数据里没有出现（145、216 之后各类工具的调用次数没有下降）。
- 漏洞：没登记前缀的新 MCP 服务不属于任何组，默认每次都带。

沿用工单 216 已有的展开机制（`expand_capability`：聊天里展开后保留 3 次请求，自主醒来保留到结束），不新增机制，不改任何工具的说明文字。

## 改动

- `tool_groups.py`：一份总表。每个工具只有三种去处：常驻、某个组、或（没登记的）自动归组。
  - 常驻：发消息、存记忆和找记忆、翻聊天记录、想法和生活记录、资料卡、实验室文件、看屏幕和窗口、定下次醒来、长期任务。
  - 新组：整理记忆 `memory_admin`（改、删、合并、写信、计划等）、干活 `build`（工作台、维护、委派）、桌面文件 `desktop_files`。
  - `social` 拆成五组：花园论坛 `garden_forum`、花园游戏 `garden_play`、花园其他 `garden_more`、乌有乡 `nowhere`、小红书 `xiaohongshu`。他说「打开 social」仍然能用，会把五组都打开。
  - 没登记的 MCP 服务自动成为一组（`mcp_<服务名>`）；程序里没登记的工具进 `other` 组。都不会每次都带。
  - 维护任务进行中时，`maintenance` 不随组收起。
- `characters/peter/character.toml`：`tool_groups` 换成新组名；上一行注释是旧的一行，换回去就恢复改前的分组。
- 「上下文」页新增「工具清单」：每个工具的大小、所属组、是否常驻、近期调用次数，以及常驻合计和预算。
- Peter 更新后第一次对话会收到一次性说明：哪些能力移到了哪个组，什么都没删。
- `tests/test_tool_budget.py`：自动检查（见下）。

## 以后加工具怎么做

写进 `AGENTS.md`「新增工具」一节，摘要：

1. 新工具默认进组，不进常驻。只有「几乎每次聊天都可能用到」才申请常驻，并且要 Lan 同意。
2. 在 `tool_groups.py` 登记到一个现有组，或新开一组并写一句组简介。
3. 单个工具说明不超过 1.5KB；长说明放进工具返回的结果或 `get_tool_schema` 这类按需读取的地方。
4. 新接的 MCP 服务什么都不用做也会自动成组；想让它的几个工具常驻，同样走第 1 条。
5. 跑测试。超预算、没登记、一物两处，测试都会失败。

## 整体维度

- 可能变好：节奏（请求更小更快）、给聊天原文和样例留出位置（355 需要）、去花园论坛时不再顺带背上乌有乡和游戏的 25 个以上工具。
- 可能变差：主动性（收进组的工具要多走一步，他可能懒得打开）；真实性（工具不在眼前时，他可能说做了其实没做）；整理记忆、工作台、读桌面文件第一次用会慢一步。
- 应该不变：性格、关系感、情绪；存记忆和想起（都仍常驻）。
- 真实模型改前改后对比：`experiments/tool-groups-357/compare.py`，结果写在 PR 里。

## 费用

不新增调用。每次请求少带工具说明，输入费用只会降；工具列表在缓存前缀里，更新后第一次请求缓存会重建一次。组的开合会改变前缀，这一点和改前相同（216 起就是这样）。

## 验收步骤（Lan）

1. 更新并重开 Peter。打开「上下文」页，下面多出「工具清单」，能看到每个工具的大小、组和次数。
2. 让他做一件收进组里的事，例如「把记忆里某条的标题改一下」或「去花园论坛看看有没有人回你」。他会先打开对应的组再做，不会说没有这个能力。
3. 正常闲聊：和以前一样，不应该出现他突然去开一堆组。
4. 不满意：把 `characters/peter/character.toml` 里 `tool_groups` 换回注释里那一行，重开 Peter，恢复改前。
