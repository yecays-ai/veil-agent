# 工单 403：请求快照与问题定位（四部分之三）

## 目标

Peter 说了一句怪话时，从那条消息直接看到他那一轮**真正发出去的完整请求**：哪些指令、哪些记忆、
哪些运行时内容、顺序是什么，哪几段会命中缓存。

## 本单做了什么

- 每次请求组装完、发出之前，把最终 `messages` 原样写一份快照到
  `data/<角色>/request-snapshots/<request_id>.json`：
  - 每段带来源标签（`identity.persona`、`system.facts`、`memory.recalled`、`history`、`user`…）
  - 中文标题、角色、字数、缓存前缀边界、估算 token、裁剪说明、本轮召回的记忆 id
  - 图片只留 `[图片]`，单段最多 12,000 字，最多保留最近 40 份
- 接口：`GET /api/request-snapshots`（最近若干）、`GET /api/request-snapshot?id=` 或 `?message_id=`
- 「指令」页新增「请求快照」页签：最近请求列表 → 点开看分段全文，并标出「以上是固定前缀」。
- 消息右键菜单新增 **This request**：直接打开这条消息所属那一轮的快照（没有快照时给出说明）。

## 安全与体积

- 快照只写不读，任何失败都被吞掉，不影响发送。
- 不含 API Key；图片转占位；每段与总量都有上限；只留最近 40 份，可在文件夹里直接删。
- 不改请求内容、顺序、缓存边界。

## 验收（Lan）

1. 更新重开，给 Peter 发一句话，打开「指令 → 请求快照」，能看到这一轮。
2. 长按他的一条回复 → **This request** → 直接看到那一轮：人设、系统事实、记忆、历史、你的消息。
3. 看得到「以上是固定前缀」那条线，知道哪部分会命中缓存。
4. 自主活动醒来后也能看到它的快照（用户消息是醒来提示）。
