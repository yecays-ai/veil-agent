# 工单 083：聊天恢复与上下文预算可靠性

## 目标

重启后不重复展示已发送的旧语音，长聊按真实 token 使用情况保留更多历史，并阻止模型原样输出 DSML 工具协议。

## 当前状态

PR #126（工单 082）已合并，提交 `fb8c1bb`；必需 CI 通过，桌面 UI 的 Windows 体验验收仍待 Lan。本机 provider 上限是 32,768 tokens，不是 30,000 字符。原裁剪估算固定按 0.5 token/UTF-8 byte，且没有显示注入分项；语音恢复只查看最近历史窗口。当前修复读取完整角色聊天账本排除已发送语音，按同一角色/模型已观测 token/字节最高比率加安全余量校准并展示上下文预算，拦截截图中的双全角竖线 DSML `calls` 标记。回归检查位于 `tests/test_web.py` 和 `tests/test_chat.py`。不增加依赖：复用 provider usage 和本地花费账本，只保存 token 数/请求字节数，不记录消息原文。

## 验收步骤

1. 超过 20 轮并重启聊天，确认已发送旧语音不再追加到末尾；新语音只显示一次且时长正常。
2. 长聊出现裁剪提示时核对人设/系统、记忆、工具定义、运行上下文、当前输入和历史的 token 估算；重启后模型实测比例仍生效，完整本机聊天记录不变。
3. 模拟截图中的双全角竖线 DSML `calls` 内容及工具步数耗尽，确认界面与历史只保存安全提示，未执行原始文本里的工具。
