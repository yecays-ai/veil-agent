# 工单 152：醒来不被对账占满 + 念头池

## 目标

Peter 自主醒来时，步数用在他想做的事上，而不是反复读回刚写的文件、提交长期任务进度；他自己有一个会自然生长和消退的念头池，旧兴趣偶尔回到眼前，但不强制。

## 现状（实现后）

1. **写入核对**：长期任务进行中，醒来期间的写文件、追加、存记忆、移动 Lab 文件等，只要工具明确返回成功，就记为完成，不再要求读回、不再要求 `long_task_update` 交证据，也不拦下一次写入。工具返回出错、结果不确定或进程中断时，仍挂起待核对，下一次写入前必须先核对（读回比对）或标记阻塞。长期任务标记完成仍需写明完成证据，且有待核对项时不能完成。
2. **念头池**：新工具 `thought`（note / touch / keep / done / drop / list）。每条只有一句话（≤160 字符）、回来过几次、上次时间，可附 Ombre 记忆 ID；经历和原因仍存在 Ombre。回来 3 次或 Peter 主动 keep 即成为持续念头；一时的念头 3 天没碰会自然消失；完成或放下的 30 天后清除。文件 `data/peter/thoughts.json`，Ombre 不受影响。不注入聊天。
3. **醒来资料**：Lab 改为最近 12 个文件的名称、大小、修改时间，加最新那个文件开头约 600 字节；其余正文需要时 Peter 自己读。念头池最多给 2 条（一条搁置 2 天以上的持续念头、一条随机的一时念头），同一条 24 小时内不重复出现；没有合适的就不给。长期任务那句改为「可以继续、暂停，或先放着去做别的」。失败或部分完成时程序代写的下一步改为「只核实结果不确定的操作」。
4. **模型记录**：`data/peter/autonomy.jsonl` 每条新增 `model`，记实际使用的模型名称。调度与预算不变。
5. 一次性能力通知 `wake_freedom_152_announced`。

费用：不新增调用。醒来资料比原来短（原最多 6KB Lab 正文）。

## 验收步骤

1. 退出 Peter，双击 update.bat，再启动。
2. 第一次聊天时 Peter 会收到一次能力更新说明，不用管。
3. 放 1–3 天自主醒来，打开「活动」页看每次醒来的工具行：
   - `read_text_file` + `long_task_update` + `long_task_status` 不应再占大部分；
   - 「部分完成」原因里不再出现 `append_file（被拒绝）`、`hold（被拒绝）`、`long_task_update（被拒绝）`。
4. 问他「你最近在想什么、想做什么」，他可以提到自己念头池里的东西；在 `data\peter\thoughts.json` 能看到这些念头（每条一句话）。
5. 生日寻宝这类长期任务仍能照常推进，交付日照常交付；他不会把没做完的说成做完。
6. 打开 `data\peter\autonomy.jsonl` 最后几行，能看到 `"model": "gemini-4-argon"` 之类的模型名。
