# 工单 053：隐藏历史与关联记忆工具一致性

## 目标

Lan 隐藏或恢复一条虚构记忆后，Peter 不能从历史工具读到隐藏正文；正常可见的关联记忆可在目录中找到并读取。

## 当前状态

`memory_history` 现复用自动检索已有的 `Memory.refresh_visibility()`，在返回历史正文前按当前文件可见性重新核验。目录解析与 049 的顶层 YAML 规则一致，不把 `relation_links` 的缩进 `type` 当成记忆类型；`memory_read` 继续复用目录的可见记录。复用检查未发现可直接接入且兼容 VEIL 本地文件、版本和授权模型的成熟开源实现，因此未新增依赖或复制代码；仅复用仓库现有的可见性和 frontmatter 规则。测试仅使用虚构数据。

## 验收步骤

1. 用虚构记忆先修改一次，再在面板隐藏它；让 Peter 查询这条记忆的历史，确认他不能说出修改前正文。
2. 用含 `relation_links` 的虚构正常记忆打开记忆目录；确认能看到它，Peter 可读取正文并在正常聊天中想起它。
3. 取消隐藏第一条虚构记忆后再次让 Peter 查历史；确认合法历史恢复可读。
