# 工单 424 · 导入事件和它的旧碎片只算同一次回忆

## 背景

第五步（69 篇正式迁移）在隔离副本上按工单预演时发现：新事件会把它由之整理出来的旧记忆留在同一个
请求里。用事件正文逐个检索 67 个有来源的事件，39 个出现「完整事件 + 旧碎片」同时注入；导入器写的
`event-import-withdrawn.jsonl` 只是一个账本，运行时不读它，也不会归档旧 md。工单要求正式迁移前解决
这个问题，否则停止正式迁移。

## 目标

- 一个旧 memory ID 只被一个事件认领时：它和新事件不再同时进最终请求，只召回它时给事件的完整故事。
- 同一个旧 memory ID 被两个事件认领时：**不猜**。保留旧碎片原文，不借任何一篇故事；两篇事件分别被
  召回时也不能串故事。
- 坏账本数据不能弄崩召回；没有故事的事件不能被别人的故事折叠；模型后来改写的故事不拿来替换旧碎片。
- 不删除、不归档、不改写任何旧记忆文件；旧碎片仍可用 `memory_read` 按 id 读到。

## 改法

- `memory_agent.Memory._event_ledger()`：从 `events.jsonl` 读一次归属，文件变了（mtime/size）就重建。
  - `unique`：只收**唯一**归属；事件自己的 `memory_id` 始终归自己；共享来源故意不在里面。
  - `owners`：每个来源的全部归属，只用于去重判断。
  - `source_memory_ids` 只接受字符串列表；数字、字符串、对象、null、混合列表里的非字符串项逐项忽略，
    坏行不影响同文件里的正常事件。
  - 读盘失败不当成「空账本」缓存：本轮 fail closed，下一轮重读。
- `duplicate()`：折叠只发生在双方 owner 的**交集**上，而且交集里的事件必须有**导入时定稿的完整故事**；
  一个没故事的事件、或只有模型改写过的故事，都不会把可读的阶段藏掉。
- `resolved()`：只有唯一归属的旧来源、且故事来自定稿导入（`story_source = final-import`）时才替换正文；
  否则保留碎片原文。共享来源没有事件目录提示。
- 没改导入器、没改召回条数／预算／冷却／判官、没有新增模型调用。
