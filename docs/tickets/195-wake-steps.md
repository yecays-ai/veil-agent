# 工单 195：自主醒来少花步数在重复读取上

## 现状
Peter 自主醒来每次最多 20 个工具步骤，每个工具调用都算一步。lan 的日志（11-01 至 11-02）里最近 5 次撞到 20 步的醒来，全是醒来流程：反复读最近活动、读同一份日记/笔记、查想法列表，约 55% 的步骤是这类读取，真正上网为 0。浏览器 `open / click / scroll` 本来就自带页面快照，描述却写着还要 `observe`，且页面正文只给 1200 字。

## 改动（步数上限 20 与 ¥3/天自主预算不变）
- A：`browser_tools.py` 描述写明 open/click/scroll 已带正文和链接，不必紧跟 observe；快照正文上限 1200→3000 字，并按字节再限到 4500，给链接留位置；结果总大小上限 8192 字节不变。
- B：`autonomy.py` 醒来上下文里（复用已有活动记录，不新增记忆系统）：除上一次活动外，再给前两次的一行摘要（时间、决定、关注点、结果）；最新实验室文件的预览从只给开头改成开头 300 字节加结尾 600 字节，接着上次写到的地方；加一句说明这些内容是当前的，需要更多细节再读。完整记录仍可用 `autonomy_history` 等工具查询。

## 测试
`tests/test_autonomy_cleanup.py` 新增 `test_wake_context_carries_earlier_activity_and_lab_tail`。

## 验收
更新后等几次自主醒来，看活动页：自主醒来后能接着之前的事做，`what_did_i_do`、读同一份日记这类重复读取明显减少，更多步骤用在真正做事上。不要求每次都上网。浏览器快照的字数效果需 Peter 实际上网一次确认（未验证）。预计花费约 +¥0.1–0.3/天。
