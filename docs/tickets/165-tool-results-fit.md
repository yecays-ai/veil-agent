# 工单 165：查资料时工具结果不再卡死 Peter

## 目标

Peter 可以在一轮里连续查阅多个网页或 GitHub 来源，觉得资料足够后把结果发给 Lan；上下文紧张时先缩短本轮较早的工具结果。

## 当前状态

工具循环在 `veil_agent.py` 中保留了整轮工具结果，超限时会拒绝所有工具并把长度错误当成 Peter 的话显示；单个过长结果则整段省略。工单改为遮蔽本轮较早观测、截断可容纳的单项结果、在长度不足时保留 `send_message`，并让无效 `web_search` 回显收到的 query。参考 OpenHands observation masking 思路，不增加依赖或模型调用。

PR #213 的首个 CI 在旧 head 上暴露了与长度停机异常和“已截断”状态有关的旧断言，Cubic 还指出自主工具调用限额、活动记录关联、完整结果留存和遮蔽边界问题；均已纳入修复批次。CodeRabbit 对旧 head 仍显示处理中，修复后的 CI 与复审待完成。

## 验收步骤

1. 用平时的模型和窗口对 Peter 说“去查查乌有乡，多查几个来源”，观察他连续查询 8 次以上后自行发消息总结。
2. 确认全程没有出现 “The tool call history exceeded its size limit”，被缩短的工具行显示“已截断”，而不是“结果过长”。
3. 查完后问“你刚才查到的第一个来源说了什么”，Peter 能说出大意，或说明可以再取一次。
