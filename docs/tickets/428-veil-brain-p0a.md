# 工单 428 · VEIL Brain P0-A：隔离副本导入与对账

## 背景

VEIL Brain 正式进入开发（Lan 2026-11-23 批准路线）。P0-A 只做一件事：拿正式记忆库的**隔离副本**，
建起 VEIL Brain 自己的 SQLite 存储，证明记忆、向量、状态、历史版本和来源都能准确保留。
本阶段不动正式库、不挂 Peter 的写入链、不做影子同步（P0-B）、不做检索（P1）。

## 目标

- 新模块 `veil_brain.py`：`import`（隔离副本 → `brain.db` + Markdown 快照 + 对账报告）、
  `check`（在任意目录打开并校验完整性/摘要）、`inspect`（按 ID 读记忆、版本、sidecar、关系、向量）。
- 存储结构预留：事件关联、阶段（空表）、原话、来源、隐藏/锁定/墓碑/版本；`events.jsonl` 的 story
  字段不进库，只保留事件与记忆的映射，避免制造第二套权威事件数据。
- 版本历史完整落库：281 条 `memory-versions.jsonl` 的旧正文、原因、字段、哈希全部可查；
  168 条 sidecar 事件原文与折叠后的状态（锁/链接/来源/合并）都可查。
- 导入过程只读来源：前后文件哈希清单必须一致；报告里写明。

## 改法

- 新增 `veil_brain.py`（标准库，无新依赖）与 `tests/test_veil_brain.py`（6 条）。
- 表：`memories / versions / sidecar_events / sidecar_state / relations / sources / quotes /
  vectors / events / event_sources / event_stages(预留) / meta`。
- 记忆行保存原始 Markdown 全文与正文哈希；正文和标题、时间、重要度、类型、状态、来源字段可查询。
- 向量按原始 float32 字节与 SHA-256 保存，维度单独记录。
- 导入写入单文件 SQLite；`check` 可在另一个目录打开这个文件并复核，证明可移动、可恢复。
- 事件边界说清楚：69 篇事件故事页**作为既有记忆文件**原样保留（它们本来就是记忆库的一部分，
  少了它们就不是完整库）；`events.jsonl` 的 story 字段**没有**进库，`events` 表只有
  event_id / memory_id / source_count，`event_sources` 只有映射。不会出现第二套事件正文。

## 验收（Lan 在 Windows 上做）

1. 我把正式记忆库复制到隔离目录，跑一次导入。
2. 你打开快照目录：283 条记忆，正文可读，索引行标着状态（墓碑/锁定/隐藏/版本数/合并去向）。
3. 抽查三类：普通记忆（如 V01）、有版本记忆（如 72dbd7d6b356）、墓碑（如 2fa6166a7d7d），
   文字与状态都对。
4. 删掉 db 重新导入：对账报告的数量与内容摘要一致。
5. 把 `brain.db` 复制到另一个目录再打开查询：历史版本与状态仍在。
6. 我给出正式库导入前后的校验和：一致（310 个内容文件，哈希清单摘要 `7418ef30…`）。

## 边界与回退

- 不修改正式库、不改 Peter 的读写链；导入产物放在仓库里已忽略的 `.local-tmp/brain-p0a/` 下，不进仓库。
