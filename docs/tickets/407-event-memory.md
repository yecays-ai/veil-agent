# 工单 407：事件记忆（第一版：写入、故事、时间线）

- 格：A（记忆与人格连续性）
- 做完 lan 能多做的一件事：同一天发生的一串事，在记忆里是**一条完整故事**，而不是三条互相“接着”的碎片；她问起那天，Peter 能按时间说出前因后果。
- 她怎么验收：更新后聊一天里发生的几件事（或看今天 06:21/17:08/18:29 那三条），记忆列表里只应出现一条该事件的故事；问“那天我们怎么了”，回答能带上当天先后发生的事；再问细节，他能展开原始阶段。

## 目标

同一事件跨多次保存只形成一条记忆（一个 Ombre 条目 + 一份事件故事），阶段与证据留在本地事件库；新增只读工具 `memory_timeline` 让他能翻一段经历的全部阶段。默认关闭（`[memory.events] enabled`），打开后新保存走事件层；关闭时行为与现在完全一致。

## 当前状态

- 保存：`memory_native._hold` 一次保存 = 一条记忆；同一天三次保存靠 `link_to` 串，形成三条。
- 事件对象：长期记忆层没有；`event_id` 只出现在短期便签和 UI。
- 证据：`tools.jsonl` 只存截断摘要；`request-snapshots` 只保留 40 轮。
- 相关代码：`memory_native.py`（hold/rewrite/trace）、`memory_agent.py`（call/created_id）、`veil_agent.py`（Character.memory、NativeMemoryTools 构造）。

## 本单范围（第一版）

1. 事件库：`events.jsonl`、`event-stages.jsonl`、`stage-evidence.jsonl`、`event-versions.jsonl`（本地，追加式）。
2. 保存时归组：按实体/同日/未关闭事件做确定性归组；证据不足时建“暂定事件”，不硬并。
3. 一条事件一条 Ombre 记忆：正文是事件摘要（≤600 字，保留每段关键句）；完整故事与阶段在事件库，`memory_timeline` 可读。
4. 证据随阶段落盘（聊天/工具最近记录），不依赖 request-snapshots。
5. 新工具 `memory_timeline`（只读）。
6. 开关：`[memory.events] enabled`，默认 false；关闭时旧路径原样。

**不在本单**：页面、召回名额改造、后台自动纠错、194 条迁移（工单 408，含逐条核对与页面）。

## 验收步骤

1. 在 `character.toml` 加 `[memory.events] enabled = true`，重启。
2. 聊一件事，隔一段时间再补一件同一件事；看记忆列表只有一条。
3. 问“这件事从头到尾是怎样的”，他答得出先后；问某个细节，`memory_timeline` 能展开阶段和证据。
4. 关掉开关，重启，保存行为回到现在（新保存一条一条）。

## 接入检查

- 入口：`hold` 工具；开关关闭时不进入。
- 停止与恢复：关开关即回旧行为；事件库只追加，未写完的投影下次保存重试。
- 权限：仍是 Peter 自己的记忆；`memory_timeline` 只读，隐藏/锁定过滤沿用。
- 费用：本版不新增模型调用（故事用确定性拼接，不压缩细节）。
- 数据：事件库在 `data/<角色>/`；旧记忆不动。
- 状态可见：保存返回“更新了《标题》的故事”；时间线工具可见。
- 升级回滚：删事件库或关开关即可；Ombre 里的事件记忆可单独删。
- 真实环境：先用假数据测试；真机开关由 lan 打开。
