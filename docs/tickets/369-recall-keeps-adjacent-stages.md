# 工单 369：同一段经历的相邻阶段，想起时不再互相挤掉

所属格：A 陪伴 · 记忆（接 353 去重、365 目录）。不涉及写入、不碰任何记忆内容。

## 起因（已核对）
第一批整理把同一经历写成多段并用「接着哪条」连起来后，问「拒绝写入、又让他覆盖第一个文件那次」这类问题，「闸门」那段被「第一次写文件」压掉。原因：想起时的去重（353）把 Peter 的 link_to 连通的整串都当成「同一件事」，只留排名最前的一条；Ombre 的 continuation_of / continues 同样被当成重复。真正答得上问题的那一段被挤掉，只剩目录里的一个标题。

## 找轮子记录
现有实现：`recall_rotation.same_event`、`memory_agent.Memory.context` 的 `duplicate()`、365 的 `experience_chain` / 目录。无需新依赖，只改去重的判定。

## 价值与验收示例
输入：「拒绝写入、又让他覆盖第一个文件那次」→ 以前只想起「第一次写文件」，现在「第一次写文件」和「闸门」两段都在。验收：重启后问一次，看他是否把两段都说得出来。

## 做了什么
1. 重复只指两种：Ombre 标的 `same_event`，或内容向量相似度 ≥ `dedup_similarity`（0.88）。这两种仍只出一条。
2. `continuation_of` / `continues` 和 Peter 的 link_to 是「同一经历的不同阶段」，不再互相挤掉，各阶段自己搜得到就能想起。
3. 同一段经历最多占 `stage_slots`（默认 2，1–3）个想起名额，防止一段经历占满；其余阶段仍在 365 的目录行里。被挡的计数记在 `last_recall_skipped['stage_cap']`。
4. 沿用 `[memory.recall] dedup = false` 关闭去重（和以前一样全关）。冷却不变。

## 整体维度检查
- 想得起对的：闸门题改善。
- 不反复冒同一条：冷却和 stage_slots 不变/新增上限。
- 不带不相关的：未变。
- 偶尔想起旧事：未变。
- 看得见能关能删：不写入数据；开关沿用 dedup。
