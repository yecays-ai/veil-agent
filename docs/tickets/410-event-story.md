# 工单 410：完整事件故事、理解变化、事件关系与迁移预览

- 格：A（记忆与人格连续性）
- 做完 lan 能多做的一件事：一段经历不再只是几段原文拼在一起，而是一段有前因后果、保留当时理解和后来改变的故事；独立经历之间能长期关联，归错能拆/移；旧记忆先得到逐条可核对的归组预览。
- 她怎么验收：打开事件层，看一段经历的详情：故事是连贯叙述、不是阶段列表；有“理解变化”；相关经历在下方；旧记忆预览清单每条都有去向。

## 目标

1. 事件故事由模型整理为自然叙述，保留日期/数字/文件名/原话，区分事实与猜测，写出理解变化；校验失败回退到阶段拼接，绝不丢事实。
2. 保存时可带 `interpretation`（当时的理解），事件维护 `belief_history`（日期 + 内容），故事和页面都展示。
3. 独立事件之间记录 `related_to`（只关联、不合并），详情页展示；新增 `move_stage` / `split_event`，自动纠错后可重建两边故事。
4. 旧记忆迁移只做**只读预览**：`event_migration.py` 读取角色 vault，按“稀有共同名字/物件 + 时间接近”给出每条记忆的拟归事件，写 JSONL 清单；不写正式库。

**不在本单**：正式迁移旧记忆（要 lan 逐条核对后单独执行）；自动拆分仍需证据/人工确认。

## 当前状态

- 事件故事是阶段全文按时间拼接（`event_memory._story`）。
- 没有 `belief_history`；`hold` 没有“当时理解”字段。
- 事件之间没有关联；自动纠错只合并共用同一条 Ombre 记忆的事件。
- 旧 153 条记忆没有归组预览。

## 验收步骤

1. 开关打开，聊三件同一经历的事；详情里的故事应是一段连贯叙述，含日期、物件、原话，猜测写成“我以为”。
2. 保存时带一句“我当时以为……”，详情出现“理解变化”。
3. 两段独立经历共享人物/物件时，详情出现“相关经历”，但仍是两段。
4. 把一条阶段拆到新事件，两边故事和阶段数都更新；操作日志可查。
5. 运行 `python event_migration.py --root . --role peter --out preview.jsonl`，每行一条记忆、一个拟归事件；原记忆文件不变。

## 接入检查

- 入口：`hold` 的 `interpretation`（可选）；事件详情；`event_migration.py` CLI。
- 停止与恢复：故事模型失败/预算不足回退阶段拼接；事件仍可读。
- 权限：迁移预览只读；拆/移只在本地事件库，Ombre 投影重写仍走锁/可见性。
- 费用：每次保存新增一次故事整理调用（预算不足回退，不阻断保存）。
- 数据：`events.jsonl` 增加 `story_source` / `belief_history` / `related_to`；旧记忆不动。
- 状态可见：详情页显示故事、理解变化、相关经历；迁移清单逐条可看。
- 升级回滚：关 `[memory.events]` 回旧行为；事件库只追加。
- 真实环境：假模型测试 + 真实模型故事抽查；正式旧库不动。
