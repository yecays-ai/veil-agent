# 工单 013：简单前端（浅色、简洁的本机聊天页）

## lan 要的体验

现在是黑底白字的终端，看着难受。要一个**简单、简洁**的聊天界面：浅色背景、字大一点、一条一条的对话气泡，不花哨。仍然只在本机用，不上网，不改变任何已有的安全边界。

## 方案（默认，lan 没有另外指定）

- **本机网页**：`python veil_agent.py --web`（`start.bat` 另给一个双击入口）启动一个只监听 `127.0.0.1` 的小服务，自动用默认浏览器打开。用 Python 标准库（`http.server`），不引入新依赖；页面是一个静态 HTML 文件（`web/index.html`，内联 CSS/JS，无外部请求、无 CDN）。
- **为什么不是桌面窗口**：浅色主题、字号、换行、复制文字都靠浏览器现成能力，最省事；以后要换成桌面窗口或加语音，聊天核心不用动。
- **外观**：默认浅色（米白底、深灰字），字号 16px 以上，对话气泡左右分开；右上角一个“深色/浅色”开关，记在浏览器本地。不做头像、动画、主题商店。
- **功能（只做这些）**：发送消息；显示 Peter 回复；显示 `🔧` 工具行和记忆行（和终端里现在显示的内容一致）；`/cost`、`/memory`、`/forget`、`/restore`、`/delete`、`/self` 照常输入，结果显示在对话里；新建文件和追加授权这类需要终端输入 `y` 的确认，改成页面里的“同意/拒绝”两个按钮（**文字必须和终端里一致，包括路径和动作，不得简化**）。

## 必须保留的边界

1. 只监听 `127.0.0.1`，启动时生成一次性随机令牌，所有请求都要带（防止本机别的网页偷偷调用）；拒绝跨域和非本机 Host。
2. 权限仍由程序判断：页面只是“按钮代替在终端输入 `y`”，不能多出任何新权限；拒绝/超时默认为“拒绝”。
3. 不把人设、密钥、聊天记录、记忆写进页面源码或日志；不在页面里显示 `.env` 内容。
4. 一次只处理一条消息（沿用现在的单线程聊天循环）；请求进行中页面显示“正在回复”，输入框不可再发。
5. `--web` 不加时，终端版行为一字不变。

## 不做的事

- 不改 `Chat.send`、`_tool_chat`、发送顺序、预算、记忆、工具权限（这些在 012 里刚动过，**本工单不得改它们**，只能在外面包一层）。
- 不做流式输出、多会话、多角色切换、语音、头像、云同步、手机访问。
- 不引入前端框架或构建步骤。

## 实现提示

- `run_chat` 现在把 `input`/`output`/`approval` 都做成可注入函数：网页版提供自己的 `input_fn`（等页面提交）、`output`（追加到页面消息列表）、`approval`（等页面按钮），在后台线程里跑同一个 `run_chat`。页面用 500ms 轮询取新消息即可，不需要 WebSocket。
- 同意/拒绝的确认文字从现有 `tools_agent` 的确认提示原样取，不要重写一份。
- 测试：用假模型起服务，验证令牌错误被拒、非本机 Host 被拒、消息往返、`/cost` 往返、同意/拒绝按钮对应 `y`/`n`、拒绝后不写文件；不调用付费模型。页面外观由 lan 看。

## lan 验收（Windows）

1. 双击 `start.bat`（或运行 `--web`）能自动打开页面；浅色，字够大，眼睛不累。
2. 聊几句，回复和终端版一致；`/cost` 能用。
3. 让 Peter 新建一个假文件：页面出现带完整路径的“同意/拒绝”，点拒绝后没有文件，点同意后有。
4. 关掉浏览器页签再打开同一个地址（带令牌）能接上；用别的地址/没有令牌访问被拒绝。
5. 不加 `--web` 仍是原来的终端版。

页面真实观感、Windows 防火墙或浏览器是否拦截本机服务、长回复和 Markdown 显示效果。
