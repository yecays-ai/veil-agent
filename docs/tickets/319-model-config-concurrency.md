# 工单 318 · 模型配置并发修复

## 目标

模型设置在并发初始化、保存和选模时不会互相卡死；旧实例遇到其他进程修改配置后，刷新即可读取最新 `models.json` 并继续编辑保存，不覆盖对方的数据，也不丢失模型、API Key 或费用上限。

## 当前状态

- 已确认锁顺序问题：初始化按“文件锁 → `_ENV_LOCK`”获取，桌面保存/选模在 `Hub` 外层先拿 `_ENV_LOCK` 和模型锁再进入 `save()`/`use()`，存在循环等待。
- 已统一为 `_ENV_LOCK` → `self.lock` → `models.json` 文件锁；初始化、保存、选模和重新加载使用同一顺序。
- 新增 `ModelSettings.reload()`：重新读取磁盘最新配置、必要时完成迁移、刷新内存快照和旧快照标识。
- 桌面初始事件快照在空闲时重载模型设置；旧实例保存/选模发现配置已被其他进程修改时，自动重载后再次允许保存。刷新页面即可恢复，不需要重启 Peter。
- 回归覆盖：旧实例拒绝覆盖后重载并继续保存；初始化、保存、选模并发不卡死。
- 未验证：真实 Windows 双实例桌面操作；留待 Lan 验收。

## 验收步骤

1. 打开两个使用同一配置的 Peter 实例/测试实例，在一边修改模型或费用上限。
2. 到另一边打开模型设置并刷新：显示最新值；修改并保存成功，不覆盖另一边的配置。
3. 确认模型、API Key、费用上限仍在，聊天和 OpenCode 工作台不受影响。
