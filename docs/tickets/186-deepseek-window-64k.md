# 工单 186：DeepSeek 内置输入上限 64K

## 背景
lan 11-01 用内置 deepseek 每次报「当前输入及必要上下文太长，超过模型上限（上限 32768）」。系统人设约 5125、工具定义约 23965、状态约 430、当前消息（含图）约 4244，合计约 33763，历史和记忆已全部裁掉仍放不下，聊天发不出去。

## 改动
`characters/peter/character.toml`：`[providers.deepseek] max_input_tokens` 32768 → 65536。其余不变。

## 费用（估算，「未验证」）
上限只是天花板。多出来的部分是历史对话，DeepSeek 对重复前缀有缓存价（缓存 ¥0.04/百万，未命中 ¥2/百万）。最坏每次多 3 万 token 未命中约 ¥0.06；一轮里后续几步通常命中缓存。按每天 150 次调用，估计每天多 ¥1～3，最坏约 ¥9。看 `data\costs.jsonl` 的实际数字。

## 验收
1. 退出 Peter，双击 update.bat，再启动。
2. 带一张图发一句话，不再出现「超过 32768」。
3. 用一天后看 costs.jsonl 与前一天比，告诉我多了多少。
