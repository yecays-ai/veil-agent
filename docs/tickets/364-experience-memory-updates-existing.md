# 工单 364：自动整理先找旧记忆，同一件事并进去

所属格：A 陪伴 · 记忆。接着 363（记忆不再越整理越长）。

## 起因（已核对）

Lan 2026-11-15 晚截图：自动整理把 CC / KYC 的后续写成了一条新记忆（「the KYC post I had to kill」），可之前已经有 CC 的记忆，完全可以并进去，写成一小段：接上 CC 两天以为挂了、紧急删掉、删完两天 KYC 又过了、恢复了。同一天还多出好几条新记忆。

代码原因：`experience_memory._candidates` 只把它自己最近 12 条整理条目给模型看。Peter 平时聊天里自己存的记忆、更早的条目，模型都看不到，只能新建。363 只改了他自己存记忆那条路。

## Lan 已定（2026-11-15）

- 按方案做：整理前搜整个记忆库给旧记忆、能并就并、写法简单（一件事一小段，带一点他自己的情绪）、锁定的不碰、旧版本照样留。
- 「也不一定什么都要记进去，有些小事该忘就忘」，不然聊十天半个月记忆库会大得难以想象。

## 做了什么

1. 整理前，程序把这段聊天切成最多 4 段，用 Ombre 的 `breath_search` 在整个记忆库里搜，最多加 6 条相关旧记忆进候选（不管是谁写的）。锁定的、超过 1200 字的不给（太长的旧条目留给路线第 3 步整理）。搜索失败只是少了候选，不挡整理。
2. 说明改成：候选里有同一件事的，就整段重写那条（一小段讲清来龙去脉，最多 600 字，和他自己存记忆的上限一致），旧文里的日期保留；只有真没有旧记忆的才新建。
3. 「大多数东西会像人一样忘掉」：闲聊、一时的情绪、以后不会再提的小事都不记。每次最多新建从 3 条降到 2 条。
4. 写法：一件事一小段，平实，发生了什么、结果怎样、一点他当时的情绪或态度。

## 可能变差（对比时看）

- 连错：把不相关的旧记忆当成同一件事重写掉（旧版本在「历史版本」里可恢复）。
- 重写丢掉旧记忆里的细节或日期。
- 记得太少：该记的也忘了。
- 每次整理多几次搜索（只花一点向量钱），模型请求变长一点。

## 验收（Lan）

1. 接着聊一件之前记过的事（不管是他自己存的还是整理出来的），等自动整理跑完：记忆页是原来那条变成新的一段，没多一条；「历史版本」有旧的。
2. 一天里只有闲聊：不新增记忆。
3. 锁定一条后再聊它的后续：那条不变。
