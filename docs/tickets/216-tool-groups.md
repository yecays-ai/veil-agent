# 工单 216：工具分组，按需展开，减少每次请求的工具说明

## 目标
Peter 每次请求带的工具说明明显变少，输入上下文更干净；他想上网、逛论坛、看 GitHub 或操控桌面时，自己展开对应能力再用，不需要 lan 下指令。

## 现状
- 你本机 context-log 最近记录：工具说明约 88KB，估算占一次请求输入的一半以上；10-28 量到的是 46KB，新增工具后又长回来。
- 他 11-01 以后调用的 3060 次里，桌面观察、实验室、记忆、说话、便签这类占大头，上网只占约 1%，GitHub 约 2%，论坛和乌有乡约 10%。

## 改动
1. 新增 4 个可展开的组，由 `characters/peter/character.toml` 的 `tool_groups` 决定：
   - `web`：web_search、web_fetch、browser
   - `github`：github_read
   - `social`：小红书、花园论坛和漂流瓶、乌有乡
   - `desktop_control`：启动应用、点击、画图、管理窗口（windows_launch、windows_manage、windows_control_action、windows_canvas_action、桌面图标整理）；找应用（windows_discover_apps）和只读观察一直提供
   其余（记忆、说话、便签、实验室、桌面只读观察、生活记录等）一直提供，不分组。
2. 新工具 `expand_capability`：参数 groups（要展开的组）、可选 reason。说明里列出还没展开的组和各自内容。展开后，对应工具从下一步起可用；权限、审批、预算都不变。已全部展开时这个工具不再出现。
3. 展开的有效期：聊天里是当前这轮加之后 3 轮；自主醒来是整个这次醒来，下次醒来重新是关闭状态。自主醒来里，展开动作不占 20 步（和 215 的免费回顾调用共用每次醒来最多 6 次）；聊天里展开算一步。
4. 一次性通知：第一次启动带新分组的版本时，告诉他一次现在工具分组了、用 expand_capability 打开，之后不再重复，也记进 capability_history，你和他都能查。系统提示里不加能力清单。
5. 没配置 `tool_groups` 的角色行为不变；配置里写了不认识的组名会直接报错。

## 不做
- 不删除或禁用任何能力；不改 20 步和每天 ¥3；不改模型选择。
- 不把桌面观察、实验室读写放进展开组（他天天用，每次多一步展开不划算）。

## 费用
工具列表一变，缓存的那部分输入会失效一次；每次展开大约多 ¥0.03 到 ¥0.1（按便宜模型粗估，贵模型更高，未验证）。每次请求少带的工具说明按估算约 25k token 的一部分，整体预计下降。更新后几天看 `data/peter/context-log.jsonl` 里的 `tool_schema_bytes` 和 `data/costs.jsonl` 核对，不降就告诉我，我退回。

## 验收（lan 日常体验）
1. 更新并完全重开 Peter。在「上下文」页或 `context-log.jsonl` 看 `tool_schema_bytes`，比之前的约 88000 明显变小。
2. 他会收到一次「工具分组了」的通知；问他或让他查 capability_history 能看到这条记录。
3. 让他「去网上查个东西」或「去花园论坛看看」，他应该先展开对应组，再实际使用工具（聊天窗口会显示 expand_capability 一行）。
4. 之后几天观察：他自己想上网、逛论坛、做东西的次数。只是观察项，不是通过标准。
5. 已有的权限和询问逻辑不变，展开后需要你同意的操作还是会问你。
