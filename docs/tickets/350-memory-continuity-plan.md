## 共同规则（每张工单都适用）

1. **放哪一层写死，不许猜**：

   | 变化频率 | 位置 | 内容 |
   | --- | --- | --- |
   | 每轮都变 | 末段（`changing` / `runtime_required`） | 时间差、账本、想起的记忆 |
   | 每天变一两次 | 可缓存前缀之后、聊天历史之前（新建一块） | 时间线小结、关系史 |
   | 基本不变 | 最前面 | 人设、关于 Lan 的笔记 |

2. **先交确定性夹具，再交功能**：用假时钟（`budget.clock` 已可替换）、固定的虚构聊天样本、假记忆后端，一条命令几秒内跑完整个场景，进 CI。没有夹具的 PR 不算完成。CI 里不调任何付费接口。

3. **合并前做一次真实模型前后对比**（Lan 2026-11-11 要求）：在测试副本上用 DeepSeek 官方接口，同一组固定的虚构场景，分别跑改动前（main）和改动后（分支），把对比数字写进 PR。有正向变化才合并；没有变化或变差就停下报告，不合并。每张工单这项对比的真实花费上限 ¥2，花了多少写进 PR。对比脚本不进 CI。

4. **不批量改写或删除现有 170 条记忆。** 任何自动写入必须有开关、Lan 看得到写了什么、能撤销或删除，验收要覆盖这三样是否真的有效。原有每轮记忆召回的可视化保留。

5. **不把「记忆写进去了」「模型复述了记忆」当作通过。** 验收看的是真实聊天里的行为。

6. 工具说明约 55KB 是另一件事，本组工单不处理。不把最近 20 轮只覆盖两小时左右理解成「到期删除」，历史是按轮数和容量裁剪的。

7. 仓库现行规则照旧：先拉最新 main，读 `AGENTS.md`、`STATUS.md`、`HANDOFF.md`、`docs/PRODUCT_PREMISE.md`；同一 PR 更新 `STATUS.md` 和 `HANDOFF.md`；多个 PR 并行时合并前先合入最新 main 再跑一遍检查。真机体验没通过不算完成。
