# 工单 005d：记忆零碎、重复、只存标签（验收反馈）

## 现象（lan 真实使用，2026-10-19）

- 同一事实反复保存近义短句（红砖色、蓝色、植物各存了好几条）。
- 只存"喜欢蓝色"，没存原因（名字读音）和共同经历。
- 把一次测试的瞬时状态（"原因尚未保存"、哪句测试话刚存没存）存成记忆。注意：Peter 是知道自己是 AI 的伙伴，讨论他的记忆、能看见什么、权限、升级、两人在一起的经历，都应该保存（lan 2026-10-19 纠正；与手机版“API 扮演角色”的定位不同）。
- 原话对不上被丢弃时只报条数，不知道丢了什么。

## 原因（读代码得出，未用真实模型复现）

补记提示词是我们自己写的：每 4 轮独立提取，看不到已存记忆；要求 concise；没有"更新原记忆"这个操作；没有区分“该存的伙伴设定讨论”和“一次测试的瞬时状态”。Ombre 只做存储和检索，且合并只在文字非常相似时触发。

## 沿用的既有设计

yecays-ai/veil 的 `lib/memory/maintenance-input.ts` 已经解决过同类问题：把已有记忆交给模型、已有就不新增、可更新而不是新增、写"何时/为什么/经历"、排除闲聊和应用自己已保存的信息。本工单把这套规则移植到 Peter 的 Python 提取层，不重写其他部分。

## 改动

- 提取请求带上最近 40 条未隐藏的已有记忆（编号、标题、前 300 字）。
- 记忆条目新增 `op`：`create` 或 `update`（带 `target`）。更新用 Ombre `trace(content=…)` 整段替换（Ombre 会重建向量）；目标不存在或已隐藏则丢弃并记录。
- 提示词：写事实 + 原因 + 共同经历，每种语言最多 500 字；已有就不输出；排除闲聊、调侃、玩笑、关于记忆系统本身的讨论。原话必须逐字匹配的校验不变。
- 被丢弃的候选（标题 + 原因）追加到本机 `memory/_agent/dropped.jsonl`，`/memory` 显示最近 5 条。它含模型生成的标题，只在本机，和记忆库一样不提交。
- 条目保存 `text`（中文正文前 600 字）用于上述去重提示。旧条目没有 `text` 时只提供标题。

- 每次补记请求把本机人设文件的内容（启动时读取，前 6000 字，只在本机和模型供应商之间传输，不进仓库）作为身份上下文放进系统提示，不再手写固定设定；人设更新后重启即生效。
- 同一事件的事实、原因、感受和共同决定合并为一条完整记忆，只有部分有独立长期价值时才拆分。

## 不做

- 不批量清理已有的重复条目（lan 的库里旧重复仍在；需要时另开工单，合并前要她确认）。
- 不改 Ombre、不改预算规则、不改召回。

## 局限

- 去重靠模型比较最近 40 条；更早的记忆看不到。尚未用真实 DeepSeek 验证质量，需 lan 在 Windows 用蓝色/名字读音这类真实对话验收。
