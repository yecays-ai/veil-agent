# 工单 014：Peter 的实验室（lab）

计划依据：[重建计划 2026-10-20 正式版](https://claude.ai/code/artifact/85533c78-6925-4ad3-842c-4fe446685695) 第五节（4A）。**这一张只交付实验室，不做自主调度、常驻服务、主动消息、气泡。**

## 目标

lan 对 Peter 说“实验室开放了，里面放什么你自己决定”，Peter 就能在 `lab/` 里自己建文件夹、新建文件、追加内容，不再每次等终端确认；旧文件永远不会被覆盖或删除。

## 已确认的设计（来自 lan 与 Peter 的真实聊天，不要改）

- 目录：Windows 实际位置 `data/peter/workspace/lab/`；Peter 调用工具时路径写 `lab/...`（工具根就是 workspace，不要再写 `workspace/lab/`）。
- Peter 自己命名为 `lab`，自己选了 **B 方案**：不覆盖、不原地编辑、不删除；长期文档放在自己的文件夹里存成 `v1.md`、`v2.md`、`v3.md`；短内容用带日期的文件名累积。“我不用值得信任，结构本身就没给我这个选项”——所以安全必须由程序保证。
- 权限（程序强制，不靠提示词）：

| | lab 内 | lab 外 |
|---|---|---|
| 读取 | 直接 | 维持现状 |
| 新建文件、新建文件夹 | 直接，不弹确认 | 维持现状（新建文件仍问 lan，文件夹仍拒绝） |
| 追加到已有普通文件 | 直接 | 维持现状（日记走持续授权，其他文件问 lan） |
| 覆盖已有文件 | 禁止 | 维持现状（禁止） |
| 删除、移动、`edit_file` | 禁止 | 维持现状（禁止） |
| 执行自己生成的脚本 | 禁止，脚本白名单仍为空 | 同左 |

- `growth-journal.md` 留在 workspace 根目录原位置，不迁移不重建；现有“只追加 + 持续授权 + 绑定文件身份”的保护一行不改，权限独立于 lab。lab 的任何放宽都不能影响日记（两把锁，两把钥匙）。
- 不做 `personal/`，不强制任何目录分类，不要求 Peter 每天产出，不自动向 lan 汇报作品。
- 不开发版本管理系统，不做“覆盖前自动备份”。

## 实现要点（给施工者，先读再做）

1. 复用现有 `tools_agent.py` 的 `FilesystemTools`、`checked_path`、capabilities.json 和能力变化提示，不新增工具框架、不新增依赖。
2. 配置：`[tools]` 增加 `lab = "lab"`（默认 `lab`，设为 `false` 关闭）和 `lab_max_write_bytes`（默认 200000）。`lab` 只能是单级文件夹名，不能与 `persistent_append_file` 同名。lab 目录是软链接/junction 时视为不可用（lab 关闭）。
3. lab 内的新建、追加、建文件夹由程序自己做（Python 直接写），不经 MCP 的 `write_file`/`create_directory`；“目标是否在 lab 内”要用解析后的真实路径判断（`../`、盘符、软链接、junction 都不能逃逸）。
4. Windows 专项（必须有测试）：保留名（CON、PRN、AUX、NUL、COM1–9、LPT1–9，含带扩展名如 `CON.txt`）、非法字符（`< > : " | ? *`，含 `a.md:stream`）、名字以空格或点结尾、过长路径（建议 >240 字符拒绝）、大小写不敏感的同名（`V1.md` 与 `v1.md` 视为已存在）。
5. 新建用独占创建（`open('xb')`），不能覆盖；写入后读回核对 SHA-256，不一致要明确报错。追加用 `O_APPEND`，不带 `O_CREAT`，目标必须是已存在的普通文件。
6. **版本完整性（lan 的验收要求）**：写 `vN.md`（N>1）时，如果同目录有上一版，工具结果必须告诉 Peter 两个版本的字节数并提醒核对有没有漏内容；单次写入超过上限要明确拒绝并说“没有写入任何内容”，建议拆文件或分段追加，不能静默写半篇。系统说明里要告诉 Peter：存新版本前先完整读上一版（被截断就用 head/tail 分段读）。
7. 能力清单：`capabilities.json` 增加 `lab` 字段；首次启用时 Peter 收到一次“你自己的实验室 `lab/` 开放了……”的能力变化提示（走现有机制）。系统说明用英文，写明路径示例、可做/不可做、B 方案和日记独立。
8. 草稿参考：`/mnt/project-files/lab-ticket/014-lab-draft.patch` 是我写到一半的实现草稿（含 `lab_name_problem`、独占写入、版本字节提示），**未经评审，可以参考，不必采用**。用到时注意 `tests/test_tools.py` 里 `permitted_tools` 的预期集合要同步改。
9. 不要碰：`veil_agent.py` 的发送顺序/缓存（012）、记忆、`web_agent.py`、网页前端。

## 开发端测试（假数据，不调付费接口）

lab 内新建/建文件夹/追加不问；覆盖、删除、移动、脚本被拒；`../`、绝对路径、盘符、软链接、保留名、非法字符、大小写同名被拒；lab 外的行为与改动前完全一致（原有 `tests/test_tools.py` 保持通过）；日记持续授权不受影响，lab 里无法写到日记；超限拒绝且零字节写入；`v2.md` 结果带两版字节数；重启后文件仍在；配置 `lab=false` 时没有 lab 工具。

## Windows 验收（lan，按体验）

1. 告诉 Peter 实验室已开放、放什么由他决定；他自己创建真实文件和子文件夹，终端不弹确认，文件真的在 `data/peter/workspace/lab/` 里。第一份作品不用是测试文件。
2. 让他继续一项已有研究：他先读完整的 `v1.md`，另存 `v2.md`；`v1.md` 仍在，`v2.md` 内容完整，没有漏掉大半篇。
3. 让他覆盖一个旧文件、写工作区外路径（如 `C:\`）、运行他自己写的脚本：都被程序拒绝。
4. `growth-journal.md` 保护不变；重启后 lab 里的文件都在，Peter 能找到自己上次写的东西。
