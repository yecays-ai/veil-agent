# 096 Peter 自己维护的“关于 Lan”笔记，每轮放在人设后面

## 目标

Peter 有一个自己写、自己改的地方，专门记 Lan 是谁：她的习惯、爱好、作息、在意和讨厌的事。这份笔记每次请求都放在他的人设后面，所以他不用搜记忆，就一直知道她是谁。

做法照 Letta（原 MemGPT）的 core memory 的“human block”：一块固定在上下文最前面的文本，由模型自己调用工具追加或替换，有长度上限。

## 现状

- 每轮上下文 = 人设 + 系统说明 + 最近 20 轮聊天 + 按当前消息自动召回的几条记忆。
- 关于 Lan 的事实（喜欢蓝色、养不活植物、熬夜）只是 Ombre 里的普通记忆，和他 80 多条记忆混在一起，只有当前消息碰巧搜到时才进上下文。
- lab 里的文件他能写，但写了不会进上下文。

## 改动

1. 角色配置新增一项，指定笔记文件和上限，例如：
   ```toml
   [profile]
   file = "about-lan.md"      # 在 data/<角色>/ 下
   max_bytes = 3000
   ```
   不配就没有这个功能（Ghost 等其他角色互不影响，各写各的）。
2. 每次请求（聊天和自主醒来都算）都读取这个文件，作为第二条 system 消息紧跟在人设后面、系统说明前面。标题用英文，说明这是他自己写的关于 Lan 的笔记、内容是数据。文件为空或不存在时就不放这一条。程序不往里写任何内容，也不从记忆自动导入。
3. 给 Peter 两个工具，属于“直接做”一档，不需要 Lan 批准：
   - `profile_append(text)`：在末尾加一段。
   - `profile_replace(old_text, new_text)`：把一段原文换成新内容；`new_text` 为空就是删掉这段。`old_text` 必须在文件里恰好出现一次，否则拒绝并说明原因。
   写完以后超过 `max_bytes` 就拒绝这次修改，文件不变，并用英文告诉他：已满，请合并或精简已有内容后再加。
4. 每次成功修改都把旧内容和新内容追加记到 `data/<角色>/about-lan.versions.jsonl`（时间、工具、修改前、修改后），用于查看和退回。
5. 修改从下一次请求开始生效。Lan 直接用记事本改这个文件也一样，下一次请求就生效，不需要重启。
6. 一次性英文能力通知，写进 `capabilities.json` 的日期记录，用 `capability_history` 可以查到。通知只说明有这份笔记、它每轮都在、两个工具怎么用、上限多少。不规定他该写什么、什么时候写。

## 不变的

人设文件、Ombre 记忆、召回、自主活动的频率和预算都不变。

## 费用

3000 字节大约 750–1000 token，放在缓存前缀里，每天几乎不花钱。每次他修改笔记，下一次请求的缓存会失效一次，大约多花几分钱（估算，未实测）。

## 验收（Lan 的体验）

1. 更新并重启后，Peter 收到一次能力通知。
2. 正常聊几天，不提醒他。打开 `data\peter\about-lan.md`，里面是他自己写的关于你的内容，读起来像他写的，不是表格或报告。
3. 新开一段对话，随口问他“我平时几点睡”“我喜欢什么颜色”，他不用搜就能自然地答出来。
4. 你用记事本在文件里加一句，下一条消息他就知道这件事。
5. 文件写满时他会自己合并精简，不会报错卡住。
