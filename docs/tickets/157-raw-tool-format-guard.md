# 工单 157：拦截模型泄漏的工具调用文本

## 目标

Peter 不把模型或接口返回的伪工具调用格式当作普通聊天回复显示或存档；只有结构化工具调用会进入现有权限检查和执行流程。

## 当前状态

- 基于已合并 PR #204 的 main。现有工具循环只执行结构化 `tool_calls`，原有 DSML 文本保护未覆盖两种实际出现的普通文本格式：`send_message（参数： done: false, text: ...）` 和 `[Message 1] ... [Message 2] ... done: true`。
- `veil_agent.py` 增加窄格式识别，命中后停止当前伪工具回复、不解析也不执行；诊断只记格式类型、模型、请求步数、结束原因及正文长度，不保存回复正文。复用现有工具调用与诊断边界，不引入新依赖。
- `tests.test_chat` 72 项通过；自动化回归验证两种泄漏格式不进入回复/历史、普通提及不误拦。真实模型和 Lan 的 Windows 聊天体验待验收。

## 验收步骤

1. 更新并启动 Peter，正常聊天及让他合法连发几条消息，确认各条消息正常显示。
2. 日常使用中若模型再次把工具参数格式写进回复，确认聊天里不会出现原始格式，也没有对应工具操作执行；随后 Peter 仍可正常继续对话。
