# 工单 041：修复网页退出响应与服务停止状态不一致

## 目标

Lan 在网页退出服务时能区分请求已接收、正在关闭和最终停止；退出期间已确认保存的数据保留，随后可正常重启并回到同一服务。

## 当前状态

基于最新 main `14cbe535039d80cc865f605420d2ec42dd58e48d`（包含 040/PR #78）。当前 `/api/exit` 先返回成功再标记 Hub 停止，网页也会在收到成功响应时显示“服务已退出”。已将退出请求与关闭完成分为独立状态：请求阶段拒绝新的变更操作并让正在进行的聊天保存完成；主服务完成聊天及资源清理后才发布停止状态。重复退出返回当前阶段，不重复触发关闭。复用了 `/api/events` 状态轮询，没有新增依赖或后台框架。

本地隔离定向验证 6 项通过：退出处理中/完成状态、重复退出、聊天数据落盘、HTTP 鉴权、正常聊天、页面状态展示及启动器回连。原生产代码提交 `a9119bf` 的 GitHub CI Windows/Linux × Python 3.11/3.12 四项全部通过；同步后的提交需重新验证。CodeRabbit 正式审查请求因配额限制未执行，恢复后再审查；PR #79 暂未合并，需审查完成后按仓库规则处理。Windows 真实体验待 Lan 验收。

## 验收步骤

1. 在网页点击“退出服务”，确认先显示“退出请求已收到，正在保存并关闭”，只有服务实际完成聊天和资源清理后才显示“已停止”。
2. 再次启动服务，确认网页能连接并回到原聊天，没有重复服务或退出状态错乱。
