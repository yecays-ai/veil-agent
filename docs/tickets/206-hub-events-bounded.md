# 工单 206：网页实时事件有界化（PERF-02）

## 目标

聊天很久之后，刷新页面或断线重连仍然流畅、不吃内存；历史消息完整可见，不丢、不重复。

## 现状与做法

`Hub.events` 只增不减，重连从头返回全部（1 万条约 3.4 MiB 内存、1.09 MB 响应）。

- 页面用的「实时事件窗口」最多保留最新 5000 条（超过 5500 时一次裁掉最旧的）；事件编号由单调计数器给出，不再依赖列表长度，裁掉后编号不重复、不回退。
- 取事件按编号二分查找；游标比窗口更旧时返回整个窗口；已连上的页面按游标增量接收，在两次轮询之间产生的事件不超过窗口容量时不丢不重（页面约每 0.6 秒轮询一次）。
- 聊天原始记录（`chat.jsonl`）不动；启动时页面回放的历史本来就有轮数上限（`history_rounds`），不受影响。实时事件按编号裁剪：撤回/修改一条已离开窗口的旧消息时，该操作不会作用到页面上（这条消息本来也已不在页面里）。仍在等待回答的审批卡片始终保留，刷新后还能点。

## 验收步骤

1. 更新后打开桌面版，聊天内容与更新前一致。
2. 连续聊天很久（或长期开着）后刷新页面：最近的对话完整显示，刷新速度不随时间变慢。
3. 开两个窗口，一边发消息，另一边实时收到，不重复显示。
