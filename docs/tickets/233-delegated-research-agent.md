# 工单 233：委派只读搜索与阅读

## 目标

Peter 可以把适合委派的多轮搜索、网页/文件阅读、代码只读调查和记忆查询交给单独选择的模型，自己保留最终判断、代码修改、命令执行和回复。主模型根据任务所需能力与预计总成本决定是否委派；委派模型不要求是绝对最低价，也不自动选择。

## 当前状态

现有聊天模型循环在 `veil_agent.py`，统一工具与 MCP 通过 `Chat.tool_schemas()` / `_execute_tool_call()`，模型按用途由 `model_settings.py` 选择，费用由共享 `Budget` 写入 `costs.jsonl`。本工单沿用这些入口；不引入 Agent 框架。主模型可查看委派模型名称、能力边界、实际单价和任务预留上限，再按任务预期质量与总成本自行决定。子 Agent 保留固定只读工具白名单（网页、文件、记忆、GitHub 只读 MCP，以及实验中人工核验过的花园论坛只读 MCP 名单），最多 6 次模型请求、12 次工具调用、90 秒，不能递归委派或发送消息；费用使用委派模型配置中的实际价格，继续受共享每日/每月总额约束并在账本标记为 `delegate`。委派失败不改用其他付费模型重试。

## 验收步骤（Lan 在 Windows 上做）

1. 在“更多 → 模型”选择“委派任务”模型，让 Peter 处理需要多轮资料搜索/代码只读调查的任务；检查当前主模型根据能力与预计总成本决定是否委派，修改代码和命令执行仍留在主模型；活动记录显示委派和实际只读工具调用。
2. 用 `/cost` 确认当天总额包含委派费用，且显示“委派任务”单独分账；关闭委派后，Peter 不再调用子 Agent。
