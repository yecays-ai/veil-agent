# 343 MCP 服务断线自动发现与重连

## 目标
任何 MCP 服务（花园、Nowhere、以后新接的）在 Lan 睡觉或不在时断开，Peter 能发现，程序自动重试把它连回来，Peter 接着用；连不回来时他能说清原因。

## 现状（本单实现）
- 程序后台每 5 秒检查一次所有已启用的 MCP 服务；发现断开后按 15 秒、1 分钟、5 分钟、15 分钟、30 分钟（之后一直 30 分钟）的间隔自动重启连接，聊天和自主活动都不需要参与。
- 只有服务断着、或刚自动恢复的 10 分钟内，每轮提示里才多一句状态（哪个服务、原因、已重试几次、下次多久）；平时什么都不加。
- 新增只读工具 `mcp_status`：列出每个服务的状态、原因、重试次数；可带 `retry` 立即重连一个服务。不新增权限或预算。
- 服务断开时调用它的工具，返回的话说明当前没连上、原因、程序会自动重试、可用 `mcp_status`。
- 复用 `mcp_services.py` 现有的重启逻辑（设置页"重试"同一条）；MCP SDK 自带的重连只覆盖 HTTP 流，不会重启 stdio 子进程，所以没有可直接用的现成件。

## 验收步骤（独立副本，真实花园，只读）
1. 连上后杀掉花园服务进程：几秒内状态变 error，不开聊天，约 45 秒内自己变回 connected。
2. 断开后马上问 Peter"花园现在能用吗"：他看到断线提示，用 `mcp_status`，连上后读到真实状态。
3. 平时（没断）提示里没有 MCP 状态那句。
