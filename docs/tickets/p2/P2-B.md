# P2-B · 读取接管、生命周期收敛与切换回退

## 1. 当前确认的目标

在 P2-A 的 Brain 唯一写入基础上，把全部正式记忆读取切到 Brain，收敛旧机制，交付可重复执行的
切换与回退流程；**正式切换由 Lan 授权后执行，开发者只做隔离演练**。

- 读取覆盖：自动召回、开场记忆、主动查找、自然联想/关联候选、判官候选与向量、跨轮追问承接、
  记忆管理页列表/详情/筛选/版本/状态、事件列表/完整故事/阶段/原话/来源/关联、自主活动与后台读取、
  所有仍直接读 Ombre vault/embeddings.db/Markdown/旧 JSONL 的正式路径。
- 页面 API 兼容：`/api/memory/*` 返回结构与现有前端保持一致；不借 P2 改版页面（#431 继续搁置）。
- 旧机制收敛：逐项审计衰减、自动归档、重复合并、后台整理、sidecar/versions/events 旧路径；
  列出“保留/停用/移交”，保留人工修改保护、锁定保护、事件去重、失败恢复、来源追踪。
- 质量验证：建立固定黄金问题集（真实旧事、不同措辞、事件故事、连续追问），对比读取切换前后
  命中、重要遗漏、无关召回、延迟；样本不足不得宣称“不低于旧系统”。
- 切换协议：一致性备份 → Lan 授权窗口冻结旧写入 → 最终对账 → 锁定单一写入权威 → 切换 →
  验证 → 失败安全恢复；任一环节失败停止，不得两套系统同时接受正式写入。
- 回退演练：用 P2-A 导出物**实际启动 Ombre**（独立 vault/端口），核对切换期间新增、修改、
  删除的结果、ID、正文、版本、状态、sidecar、事件故事与关联；不得用“重新导入 Brain”代替。
- 事件与碎片不重复注入：在隔离聊天中验证同一经历不会以事件和碎片两种形式同时出现。
- 不做：标签/分类治理（P2-C）、正式部署、P3 下线、记忆分层重构。

## 2. 代码与数据现状

- P2-A 完成后：Brain 可独立写、事件故事/阶段入库、写日志与同 ID 导出可用；默认 flag 关闭。
- 仍需切换的读取：`memory_agent.opening`、`_related`（Ombre breath_search）；`recall_judge`
  与 `assisted_recall` 的 `embeddings.db`；`memory_native.panel_entries/versions/archived` 的
  Markdown/versions/sidecar；事件页 JSONL；`recall_rotation` 的 front_matter/raw 读取；
  自主活动/经验整理的后台读取。
- 现有 P1 试用仅 2 轮真实召回（2547/3172 ms，0 失败），旧候选日志仅 17 条；不能作为质量基线。
- 页面 JSON 契约由 `web_agent._get_memory_panel/_get_memory` 决定，前端 `desktop/chat.js` 依赖；
  切换必须保持字段或同 PR 兼容改造并加 UI 测试。
- 事件与碎片去重逻辑在 `recall_rotation`/`memory_agent`（same_event、stage_cap、预算），
  切换后必须保持。
- 旧机制：Ombre 内部衰减/归档、VEIL 的归档/合并/后台经验整理；需逐项确认现状与实际用途。
- 备份：P2-A 的 brain.db + 写日志 + 事件数据；切换前必须有一致性备份和恢复验证。

## 3. 用户体验验收步骤（隔离）

1. **读取矩阵**：隔离环境逐项触发自动召回、开场、主动查找、联想、判官、跨轮追问、记忆页列表/
   详情/筛选/版本、事件列表/故事/阶段/原话/来源、自主活动读取；对比切换前后同一问题得到的记忆与
   事件；页面 JSON 字段/类型与现有前端兼容。
2. **黄金问题集**：固定 30–50 条真实旧事问题（含不同措辞、事件故事、连续追问、无答案问题），
   记录期望记忆/事件；比较 Ombre 与 Brain 的命中、遗漏、无关召回、延迟；重要遗漏不得增加，
   延迟不得明显恶化；结果与样本量如实报告。
3. **去重与承接**：连续聊天追问；同一经历只注入一次（事件或碎片），不重复；旧事件与碎片不互相
   抢占名额；冷却/预算/判官行为不变。
4. **旧机制审计**：逐项列出衰减/自动归档/重复合并/后台整理的保留/停用/移交结论；锁定、人工
   修改保护、事件锁定、失败恢复、来源追踪仍有效。
5. **切换演练**：隔离副本执行完整协议：一致性备份 → 冻结旧写入 → 最终对账 0 差异 → 锁单一
   写入 → 切换 → 保存/修改/删除/隐藏/锁定/归档/事件操作 → 重启 → 页面/召回正常；故意在
   最终对账前制造差异，验证会停止切换并安全恢复，不会双写。
6. **回退演练**：切换后新增/修改/删除各若干条，用 P2-A 导出物启动独立 Ombre（独立 vault/端口），
   核对全部结果、ID、正文、版本、状态、sidecar、事件故事/来源；已 hard delete 的记忆不得复活；
   在 Ombre 上实际聊天、保存、修改、检索。
7. **备份恢复**：切换前备份恢复到全新隔离目录，确认 Brain 数据/事件/版本/检索可用。
8. **失败路径**：Brain 读取失败/超时、页面字段缺失、事件故事损坏时，有明确降级/报错，不静默返回
   空记忆；回退可执行。
9. **正式验收（Lan 执行）**：提供隔离证据、切换窗口步骤、回退步骤；Lan 在真实 Peter 上体验后
   才可宣布 P2-B 完成。

通过标准：读取入口全覆盖且页面兼容；黄金问题集无重要遗漏增加；事件/碎片不重复；切换协议可重复；
回退后切换期新增/修改/删除全部正确；任一失败不得进入正式切换。

## 4. 交付前自审（本单强制）

- 推 PR 前逐条对照本工单，特别是：全部读取入口、页面 API 兼容、黄金问题集、事件/碎片去重、
  切换协议、实际启动 Ombre 的回退、备份恢复、失败降级。
- 切换/回退验收必须覆盖 **P2-C 治理后的数据**（分类迁移后的正式候选数据结构），不能只用旧标签数据。
- PR 说明和 STATUS/HANDOFF 写明每条“完成/未完成 + 证据”；未完成不得声称 P2-B 完成。
- 审查评论只改功能/数据/安全问题；一次性修改、一次性推送。
