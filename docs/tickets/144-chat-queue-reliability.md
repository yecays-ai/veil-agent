# 工单 144：消息队列原子性与回复状态可靠性修复

## 目标

- Peter 取消晚点回复后能正常继续本轮对话，请求回复（Request Reply）不再被并发消息当成乱码吞掉，连续发送语音与文字消息时严格按发送顺序处理。

## 当前状态

- `reply_later(cancel=True)` 未重置 `turn_done` 与 `reply_later_called`，导致取消后本轮意外终止且状态挂起在 `reply_later`；
- `_chat_batch` 和 `claim_steer` 存在检查与取出分离的竞争窗口，`ChatAction` 有概率被转成字符串当作普通消息发送；
- 语音消息转录期间新收到的消息排入队列尾部，导致原批次剩余文字消息重新入队后顺序反转。
- 相关文件：`veil_agent.py`、`web_agent.py`、`tests/test_free_reply.py`。

## 验收

1. 退出 Peter，运行 `update.bat` 启动最新版本。
2. 在对话中触发 Peter 考虑晚点回但紧接着决定马上回（或取消晚点回），确认 Peter 仍能正常发出回复气泡，本轮不会突兀停住，状态记录显示正常回复。
3. 在 Peter 正在思考/生成回复期间点击「请求回复」（星星图标），确认 Peter 收到催复请求并给出实际回复，对话框不会出现任何包含 `ChatAction` 或对象地址的乱码消息。
4. 连续发送一条语音消息 A 和一条文字消息 B，并在语音发送后立即追发一条文字消息 C；确认 Peter 严格按照 A → B → C 的顺序逐一理解和回应，文字 B 不会被推迟到 C 之后。
