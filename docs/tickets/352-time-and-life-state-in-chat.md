# 352 时间感和生活状态接进普通聊天

属于哪一格：A。共同规则见 `350-memory-continuity-plan.md`。

做完 Lan 能多做的一件事：隔几小时或几天再找 Peter，他知道过去了多久，知道手上还有什么没做完，不把做完的事当成待办。

她怎么验收：离开一晚上后回来聊天，看他的开场是否合乎间隔；问他「你手上还有什么事」。

## 目标

复用已有数据，不新增数据库，不调用模型，让普通聊天获得：

- 距离 Lan 上一次发消息的实际时长。
- 当前长期任务及其状态、下一步。
- 当天的生活事件和未勾选的待办数量。

## 当前状态

这些信息只在自主醒来时提供（`autonomy.py` 约 905–925 行）。普通聊天只有当前时间（`self_facts()` 的 `changing`）。

## 要求

1. 时间差由程序按消息时间戳计算。区分「Lan 最后一次发消息」和「Peter 最后一次主动发消息」两个时间。
2. 放在末段每轮变化的部分，不动可缓存前缀，`tests/test_cache_order.py` 保持通过。
3. **不许报时。** 时间差只用于调整开场和语气。注入文字里写明：不要在回复里复述具体时长，不要每轮提时间；自然提到可以，报数不行。间隔很短时（例如一小时内）不注入时间差。
4. **状态结构化，不靠模型判断。** 长期任务和生活记录每条都带状态和日期。状态不是进行中的，一律标成「历史/已结束」，并写明不得当作待办复述。全部标明是数据不是指令，不授予任何权限。
5. 不推断 Lan 没回复就是生气。
6. 优先把自主醒来里已有的那段拼装逻辑提出来共用，不写第二份。

## 夹具（先交）

假时钟加固定聊天样本，覆盖：间隔 10 分钟、3 小时、2 天；长期任务为进行中、暂停、已完成三种；生活记录含今天的事件、已勾选和未勾选待办。断言注入文字的内容和所在层。

## 真实模型前后对比（合并前）

DeepSeek 官方接口，虚构场景，各跑 main 和分支：

- 间隔 2 天后的第一句回复，是否体现出久别（人工看 5 次）。
- 连续 5 轮对话，统计回复里出现具体时长数字的次数，目标为 0 或仅首轮自然提及一次。
- 问「你手上还有什么事」，已完成的事项被说成待办的次数，目标为 0。

## 验收步骤（Lan）

1. 晚上和 Peter 聊完，第二天再打开，看他的第一句是否知道隔了一晚，且没有报「我们 X 小时没说话」。
2. 接着聊五六句，他没有反复提时间。
3. 问他手上还有什么没做完，他说的和长期任务页面一致，没有把做完的当待办。
