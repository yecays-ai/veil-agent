# 工单 056｜长期任务完整调度与检查点回归

## 目标

Peter 的虚构长期任务在工具已产生效果后中断或重启时，能先核实原结果再继续，不重复执行写入；即使已有 40 条进度，也能保留完成证据并开始下一任务。

## 当前状态

现有 `long_tasks.py`、`veil_agent.py` 与 `tests/test_long_tasks.py` 已分别覆盖稳定操作 ID、结果读回、`trace` 身份、40 条进度和对象重建。仍缺少一条经过真实 `_tool_chat`、工具包装层及检查点的组合回归。已检索成熟开源实现，未找到适合本地 Python 原子 JSON 快照且可直接引入的依赖；本单复用仓库现有实现和 unittest，只借鉴意图—观察—确认的通用模式。

## 验收步骤

1. 在开发端提供的隔离虚构角色环境启动任务，让 Peter 修改测试记忆；中断后重新启动，确认他先核实原改动再继续，且没有重复修改。
2. 模拟测试文件写入结果不明，确认 Peter 先检查目标，不能盲目重复写入或宣称完成。
3. 加载开发端准备的 40 条进度虚构任务，确认能核实最后一步、完成、重启后保留历史与证据，并开始新任务。
