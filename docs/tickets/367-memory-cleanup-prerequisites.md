# 工单 367：整理旧记忆前要先修的三处小毛病

所属格：A 陪伴 · 记忆。记忆路线第 3 步（整理旧 194 条）的前置修复；整理本身还在测试副本里验证，没有动正式库。

## 起因（已核对）

第一批整理在测试副本里做对比时，查到三处现有程序的毛病（Lan 11-16 同意单独修）：

1. 记忆页「恢复成这一版」有 1500 字上限（`memory_native.py` 的 `CONTENT_LIMIT`，本来是给页面手写保存用的）。库里有几条旧版本远超 1500 字，点不了恢复，「旧版本可恢复」的承诺没兑现。
2. 想起一段经历时的目录（工单 365）同一天的几段按随机 ID 排，顺序是乱的：取创建时间时被截成了只到日期（`memory_agent.py`）。
3. 上下文页「他平时怎么说话」卡片被下面的「工具清单」盖住：页面里每张卡片被均分高度，这张卡里的编辑框更高，多出来的部分画到下一张卡上，卡片底部的「开启/关闭」「保存」按钮看不见。（Lan 的截图：卡片标着「已关闭」，却找不到开关。）

## 做了什么

1. 恢复旧版本不再受 1500 字限制，改为只受 Ombre 自己的单条上限（48KB）约束；完整原样还原，不截断。恢复后若超过 600 字，提示「自动想起只显示开头，想看全文用 memory_read」。记忆页手写编辑仍是 1500 字，没改。
2. 目录把完整创建时间传给排序，同一天的几段按先后排；无法识别的日期仍能排，不会报错。
3. 这张卡片不再被压缩高度，页面整体可滚动，按钮露出来。样例开关就是卡片右下角的「开启/关闭」按钮（标题旁写着「开着/已关闭」）。

## 找轮子记录

普通修复：用现有的版本记录、Ombre 单条上限（`MERGED_MEMORY_LIMIT_BYTES`）和 365 的目录函数，没有新增依赖和新系统。

## 验收（Lan）

- 记忆页：找一条有很长旧版本的记忆（整理测试里的那几条），点「恢复成这一版」：能恢复，提示超过 600 字。
- 想起一段同一天写了几段的经历：目录里几段按发生先后排。
- 上下文页：「他平时怎么说话」卡片完整显示，右下角能看到「开启/保存」按钮；往下滚能看到「工具清单」「短期便签」。

## 未验证

真机上更新后的页面和恢复长旧版本（云端只用假 Ombre 和静态页面验证过）。
