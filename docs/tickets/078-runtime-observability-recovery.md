# 工单 078｜运行期监测与安全恢复闭环

## 目标

Peter 的关键后台模块异常时会显示安全状态：已确认可恢复的自动恢复，结果不确定的副作用停止重放并暂停自主活动。

## 当前状态

现有 Ombre 恢复、记忆不确定写入保护、长期任务检查点、工具可用状态、能力快照、预算和备份恢复已经分别实现，但网页没有一处能说明最近故障是“已恢复”还是“必须核对”。本单复用这些状态，只增加本地、按事件更新的安全摘要和虚构故障注入；不增加轮询、模型调用、通知服务或监控平台。外部核对了 MIT 的 [`hynek/stamina@5c13c8e`](https://github.com/hynek/stamina/tree/5c13c8e0b4bc5faa54914115a8c796934ba6da9d) 与 [`merttatd/py-healthcheck@0c69b7e`](https://github.com/merttatd/py-healthcheck/tree/0c69b7e3889947de306a8186a5b10f3b90361302)：前者解决通用有限重试，后者解决通用探活；二者都无法判断 VEIL 业务副作用是否已发生，直接引入会增加依赖或误重放风险，因此不采用。

实现将 Ombre 的“服务已恢复”和“原操作已安全完成”分开：只有明确未送达后的一次安全重发得到成功回执才显示已恢复；写入回执丢失继续保持 unknown。自主长期任务的副作用出错会复用原检查点并暂停活动；只读工具失败只提示按原操作重试，不制造第二次副作用。状态文件只含时间、模块、分类、诊断码和处理动作，页面按现有事件拉取展示；没有定时探测或模型调用。

基于 main `1cd0fad106d70d67cac05336ba0fe8898fa3fe02` 在 `ticket/078-runtime-observability-recovery` 实现；本地完整离线套件 426 项通过、4 项可选跳过，桌面测试 3 项通过，未使用真实角色数据或付费接口。

## 验收步骤

1. 打开 Peter 的状态页，确认“运行安全状态”显示正常，且不会周期性弹通知。
2. 如以后发生已安全恢复的记忆服务故障，确认状态显示“已恢复”；如出现结果不确定的长期任务动作，确认自主活动暂停并提示先核对、不要重试。
