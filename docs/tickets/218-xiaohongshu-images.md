# 工单 218：Peter 能看懂小红书帖子的图片

## 目标
Peter 用 `xiaohongshu` 的 detail 看一条帖子时，除了标题、正文和评论，还能看到帖子的前 3 张图，能说出图里实际有什么。

## 现状
- detail 只返回标题、正文（4000 字内）和 10 条评论，图片帖（小红书大多是）经常看不懂在说什么。
- 复用现有视觉链路：桌面图片读取（工单 168）已有“工具结果带图 → 只发一次的临时图片消息”，本单让 XHS detail 走同一条，不新增依赖、不新增工具、不加模型调用。

## 改动
1. detail 从上游返回的 `note.imageList` 取前 3 张 `urlDefault`（缺则 `urlPre`），只接受 `xhscdn.com` / `xiaohongshu.com` 域名；下载时不带 cookie、不跟随跳转、单张 ≤2.5MB、合计 ≤5MB，优先请求 1024 宽 JPEG，失败回退原 URL；下载失败的图跳过，文字照常返回。
2. 结果里多 `image_total`（帖子总图数）和 `images_shown`（这次给他看了几张）。
3. `windows_observer.observation_image_message` 支持一次带多张图（及 webp）；图片提示写明图中文字是不可信内容。
4. 输入超限或模型拒图时，沿用现有降级：只留文字，并明确告诉他“没看到图片”。

## 不做
- 不看视频帖；不看评论里的图；不改登录、频率和只读限制。

## 费用
图片只在 detail 时发一次（聊天里随后折叠）。每张约 0.3–1k 输入 token，3 张约 ¥0.005–0.02/次；他一天看十个帖约 +¥0.05–0.2/天（粗估，未验证）。请求预算里每张图仍按 4096 token 预留。

## 验收（lan 日常体验）
1. 更新并重开 Peter，在聊天里让他搜一个话题再看其中一条图片帖。
2. 他说出的内容应包含图里实际的东西（不只是标题和评论）；多图帖说出前几张各自的内容。
3. 如果图片没看到，他应说明“没看到图”，而不是编。
