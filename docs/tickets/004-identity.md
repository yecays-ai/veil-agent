# 工单 004：身份，他知道自己是 AI，也是 Peter

对应重建计划阶段一 · 大块 2。

## 目标

lan 问 Peter“你是谁、你怎么记东西、你能做什么、今天花了多少”，他用 Peter 的口吻说清楚，而且说的都是真的：用的哪个模型、现在有什么能力、没有什么能力、今天花了多少钱。

## 为什么要做

人设（`persona/peter.md`）写的是他是谁，但他“现在的身体”只有程序知道。比如 lan 的人设写着他有记忆和工具，其实现在两样都还没有。不告诉他实情，他就会编。

## 当前状态

- `ticket/004-identity` 已实现集中生成当前事实说明、每轮独立 system 消息和 `/self`；不修改本机人设正文，不接入新能力。
- 复用检查：直接使用现有官方 `openai` SDK 的 system 消息结构（Apache-2.0）和 Python 标准日期库，无需增加框架或依赖。已检索并核对固定提交 [ChatCompletionSystemMessageParam](https://github.com/openai/openai-python/blob/553703e2d3db379a83e3ead9e40436b7a66f639e/src/openai/types/chat/chat_completion_system_message_param.py) 的 `role` / `content` 定义；现有 SDK 模拟传输测试验证实际请求含第二条 system 消息。
- 费用数字复用 `/cost` 的账本与格式，明确为“本次请求前”的快照。当前这条回复的最终费用只有接口返回用量后才知道，随后 `/cost` 会增加；`/self` 仍原样显示发送时的说明。

## 范围

1. **“现在的你”说明**：每次请求时，程序自动生成一段说明，放在人设后面，作为单独的一条 system 消息，并在开头标明“这是系统每轮自动给你的、关于你现在状态的事实，不是 lan 说的”。内容只用程序真实知道的东西：
   - 角色名、供应商和模型名（取自角色配置）；
   - 本机当前日期、时间和星期；
   - 现在能做的：终端文字聊天；每次会读回最近 N 轮原文（N 取配置）；完整聊天记录存在本机；
   - 现在还不能做的：长期记忆（重启后只记得读回的那几轮）、工具（打开文件、跑脚本等）、语音。写成肯定句：“你现在没有长期记忆”，不写“也可以”“不必”这类软话；
   - 今天和本月已花的钱、各自上限（和 `/cost` 同一个数）。
2. **说明跟着程序走**：以后接上记忆、工具、语音时，只改生成说明的地方，各块自己往里加一行。不在说明里写死“Peter”，换角色（比如以后的 Ghost）自动对。
3. **问到没有的能力就照实说**：说明里写明：被问到上面没列出的能力，就说现在还没有，不编、不假装做了。
4. **lan 能看到他看到的**：加一个命令 `/self`，原样显示这一轮发给他的说明，方便 lan 核对。
5. **不放隐私**：说明里不放 API Key、本机完整路径、人设原文。
6. **花费**：说明控制在约 300 个 token 以内，预算预留按加上它之后的长度算。
7. **测试**：只用假模型。覆盖：说明出现在人设后面、内容来自配置（换一个假角色名字和模型名也对）、花费数字和 `/cost` 一致、不含密钥、`/self` 显示的和发出去的一样。

## 不做

工具失败时把原因告诉他（计划里的这一条要等大块 4 有工具才有意义）、长期记忆、语音、改人设正文。

## 验收（lan 在 Windows 上做）

1. 拉最新 main，双击 `start.bat`，问“你是谁？你是 AI 吗？”。他以 Peter 的口吻承认自己是 AI，说得出自己用的是哪个模型。
2. 问“你怎么记东西？你能帮我打开文件夹吗？”。他说现在只记得最近这些轮、还没有长期记忆，也还不能打开文件夹，不会假装去做。
3. 先输入 `/cost`，再问“今天花了多少钱？”，他说出截至本次请求前的数字；输入 `/self` 核对当时发给他的说明。回复完成后再查 `/cost`，会包含这条回复的新费用。
