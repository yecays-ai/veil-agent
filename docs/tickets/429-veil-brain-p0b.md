# 工单 429 · VEIL Brain P0-B：安全影子同步

## 背景

P0-A 已把隔离副本导入 `brain.db` 并通过验收。P0-B 让影子库跟随 Ombre 的真实变化，但**不接管**
读取、检索或正式写入：Ombre 仍是唯一权威，影子库只同步、核对、报告。

开工前核实了 P0-A 报告里的 7 个悬空事件来源：全部是 #426 删除 feel 后留下的历史引用（备份里有
7 个对应文件，正式库没有相近 id，不指向别的记忆）；同一批 id 还被 8 条 sidecar 链接指向，源记忆都
健在。它们按 #426 的迁移日志归为「已知历史引用」，与新异常分开报告，不算同步损坏。

## 目标

- 只利用已经确认成功的写入结果同步；影子库、worker、队列或数据库的任何异常都不得让 Ombre 保存
  失败或明显增加聊天延迟，漏掉的由周期对账补齐。
- 覆盖新增、修改、删除、隐藏、锁定、归档、合并、版本变化，并检查事件关联。
- 失败可重试、可重新对账，不产生重复记录；可随时关闭，关闭后 Peter 的记忆功能不受影响。
- 观察 7 天，逐条比较正文、状态、版本、向量、关联，不以条数相等代替一致。
- 不做 P1 检索、不切换正式读写、不改记忆管理前端。

## 改法

- 新增 `brain_sync.py`：outbox（写入后只入队 ID）+ 后台 worker + 周期哈希对账 + 报告。
  全部标准库；不引入文件监听。
- `memory_agent.Memory.call()` 在 Ombre 确认成功后调用 `shadow.note_write()`（只入队、全部异常吞掉）；
  `Memory.__init__` 在开启且 `brain.db` 存在时挂载，`__exit__` 关闭 worker。
- 幂等：记忆按 id upsert，版本按 `source_index`、sidecar 按行号、事件按 `event_id` 唯一；重复同步不
  产生重复行。软删除只标 `removed_at`；源文件消失且账本无内容时按硬删除擦除，只留空墓碑。
- 对账：扫源文件比较原始哈希、正文哈希、bucket、标题、时间、重要度、类型、隐藏/墓碑/删除状态；
  逐条核对版本哈希、sidecar 折叠状态、向量维度与 SHA、事件映射；不一致列出。
- 已知删除：#426 迁移日志里的 feel/I id 写入 `known_removed`；事件来源与 sidecar 链接目标按
  已知/意外分类报告。
- 开关：`[memory.brain] shadow`；运行时 `brain_sync.py shadow off/on`（role 目录下
  `brain-shadow-off`）。关闭时写入路径不做任何同步。
- 数据库：`data/<role>/brain.db`，由 `brain_sync.py init --source <隔离副本>` 一次性建立并迁移；
  报告 `brain-sync-report.md`，问题日志 `brain-sync-log.jsonl`。

## 本机隔离复演（不碰正式库）

- 用正式库的隔离副本建 283 条基线：reconcile 结果 `changed 0 / unexpected 0`，逐项比较 283 记忆 / 281
  版本 / 109 状态 / 244 向量 / 69 事件（157 来源）全部一致；已知引用 10 个 id（7 事件来源 + 8 链接）。
- 隔离目录里加一条新记忆 → changed 1；删除 → changed 1（标 removed）；`shadow off` 后 reconcile 被拒绝；
  `shadow on` 后对账补齐。

## 删除与损坏边界

- 硬删除（/delete）：源文件消失且不再有账本内容时，影子库只留空墓碑（id + 时间），正文、原始
  Markdown、旧版本、关系、来源、引用与向量全部清掉，跟随 Ombre 的擦除承诺。
- 扫描不完整（某文件读不了、目录暂时不在）时不推断删除，报告记 scan_incomplete；下一次对账再判。
- `memory-versions.jsonl` 被擦除重写（变短或同长度不同指纹）时整体重建，旧正文不会残留。
- 影子库不反向修改正式记忆、不自动修复；故障演练只在隔离副本。

## 验收（Lan 真实使用，6 项 + 7 天）

1. 开启后在聊天里让 Peter 存一条新记忆：报告出现该条，聊天不卡、不报错。
2. 改一条、在记忆页隐藏/锁定一条、归档/合并一条：影子库状态随之变化，报告逐项列出。
3. `shadow off`：聊天与保存照常，影子库不再新增；`shadow on` 后自动对账补齐，且不出现重复。
4. 故障演练只在隔离副本做：影子库不可用时 Peter 保存仍成功，日志记差异；恢复后重试成功。
5. 重启：启动对账自动跑；报告显示无意外差异，7 个已知删除列在「已知历史引用」。
6. 7 天后按正文哈希、状态、版本、向量、关联逐项对比，再决定是否进入 P1。

## 边界与回退

- 影子库不反向修改正式记忆、不自动修复、不清理历史引用；所有演练用隔离副本，不碰正式
  `brain.db` 与 Ombre 数据。
- 回退：`shadow off` 或删掉 role 目录下的 `brain.db`、报告、日志；正式记忆不受影响。
