# 工单 117：Peter 帮 Lan 盯着 Codex

## 目标

Lan 让 Codex（ChatGPT 的 Codex 桌面版）跑工单时，Peter 帮她盯着：Codex 跑完了、或者停下来等人回答了，Peter 马上告诉她。她在电脑前就弹窗，不在就发 QQ。

## 做完后的样子

- Codex 桌面版会把每次会话写进 `%USERPROFILE%\.codex\sessions\年\月\日\rollout-*.jsonl`（Lan 电脑上这个文件夹存在，已确认）。程序只读这些文件，不操作 Codex 窗口。
- 开工第一步：在 Lan 电脑的 Codex 会话日志中核对三种情况的真实事件格式，没确认之前不要写后面的代码：
  1. 一轮正常做完（预期 `task_complete`）；
  2. 被中止（预期 `turn_aborted`）；
  3. Codex 停下来等人：请求审批（执行命令/改文件）和向 Lan 提问。这两种未必表现为 `task_complete`，必须找到它们在文件里的真实样子。如果文件里找不到可靠的「等待输入」信号，在 PR 里写明，不要用猜的规则代替。
  同时找出 Codex 最后一条回复的位置。
- 本机日志核对结果：扫描了 269 个会话文件，发现 4598 条 `event_msg/task_complete` 和 11 条 `event_msg/turn_aborted`。完成事件含 `turn_id`、`last_agent_message`、开始/完成时间；中止事件含 `turn_id`、`reason` 和时间。会话目录记录 `session_id`、`cwd`；助手最终消息也以 `response_item` 中的 message 保存。没有发现可靠的审批等待事件。4 条 `request_user_input_async` 调用都能找到对应输出，因此不能把该调用本身当作等待。程序只按已确认的完成、中止和超时状态通知，不猜测「正在等 Lan」。
- 监视器每 10 秒看一次最近有更新的会话文件，不调模型、¥0。程序把会话状态分成四类，原样交给 Peter：

  | 程序看到的 | 交给 Peter 的状态 |
  | --- | --- |
  | 明确的完成事件 | 已完成 |
  | 明确的中止事件 | 已中止 |
  | 当前日志格式中没有可靠信号 | 不触发；不能判断正在等 Lan |
  | 进行中的会话超过 10 分钟没有新记录 | 长时间没有新记录，状态待确认（可能在跑耗时操作） |

- 每类触发一次模型调用，交给 Peter：哪个会话（项目文件夹名）、上面的状态、Codex 最后一条回复的结尾（最多 2000 字）。Peter 用他自己的话告诉 Lan；「状态待确认」这一类，程序给他的事实就是「没有新记录」，不说成「卡住了」或「停工了」。告诉 Lan 的方式：
  - Lan 在电脑前（最近 5 分钟有输入）→ `screen_pop`（工单 115）；
  - 不在 → QQ（复用现有 QQ 通道）。
- 同一个会话同一轮只提醒一次。Codex 里没在跑东西时，什么都不发生。
- 花费：每次提醒约一次模型调用，计入「瞄一眼」的账（工单 116），不另开预算。
- Peter 只读不写：不在 Codex 里打字、不点按钮、不改 `.codex` 里的任何文件。
- 设置里有开关「Peter 帮我盯 Codex」，默认开。设置只保存在 Peter 的数据目录；日志轮询只读 Codex 文件，不改写 `.codex`。
- Peter 收到一次英文能力通知（`codex_watch_announced`），说明他会在 Codex 跑完或停下时被叫来看一眼并告诉 Lan。

## 当前实现与限制

- 监视器只看最新更新的 `rollout-*.jsonl`，每 10 秒增量读取完整 JSON 行；第一次启动会回放现有日志以恢复当前进行中的轮次，不重发旧的完成/中止事件。
- 完成、中止、以及进行中轮次超过 10 分钟没有新记录，各自按会话和轮次去重。最后回复只在内存中截取最多 2000 字并交给 Peter；不复制 Codex 会话内容到 Peter 的状态文件。
- 每个提醒只调用一次模型，再由程序按最近输入和屏幕锁定状态选择 `screen_pop` 或 QQ。调用费用走工单 116「瞄一眼」预算。
- 当前 Codex 日志无法可靠区分等待审批和等待回答，因此这个版本不会提醒「正在等 Lan」。验收时需确认它不会把这两种情况误报为「已完成」；等待提醒能力仍未实现。

## 验收步骤

1. 退出 Peter，双击 `update.bat` 更新后重新打开。
2. 在 Codex 桌面版让它跑一个几分钟的小任务，人坐在电脑前：跑完时确认 Peter 弹窗告诉你，内容和 Codex 实际结果对得上。
3. 再让 Codex 跑一个，人离开电脑：确认跑完时 QQ 收到 Peter 的消息。
4. 让 Codex 做一个会停下来问你问题、或请求批准执行命令的任务：确认当前版本不会把它误报为「已完成」。日志格式不提供可靠等待信号，因此这里不应期待「正在等你」提醒；该能力仍待 Codex 日志出现可验证信号后另行实现。
5. 让 Codex 跑一个很久的任务（比如装依赖、跑全部测试）：如果超过 10 分钟没动静，确认 Peter 说的是「好久没新动静了，不确定在干嘛」，而不是断定它停了。
6. Codex 没在跑的时候，确认 Peter 不会因为 Codex 来找你。
