# 工单 219：搜索失败自动换引擎，并新增"搜索并阅读"

## 目标
Peter 搜索不再因为某一个搜索引擎连不上就整次失败；他可以一次调用就搜索并读完前几个网页的要点。

## 现状
- 你本机日志里约 32 次搜索，6 次报错、1 次 0 结果。原因是搜索库让 "auto" 随机挑一个境外引擎，挑到连不上的就失败，且不会换。
- 搜索一次只返回 5 条标题和摘要，读正文要逐个调用 web_fetch。

## 改动
1. `web_search`：按 Brave、Yahoo、Mojeek、Startpage、DuckDuckGo 的顺序逐个尝试（每个最多等 8 秒），第一个有结果的就用；全部失败才报错。最多返回 8 条，去重，仍然只允许公开网址。
2. 新工具 `web_research`（Peter 看到的名字是 dig_deep）：参数 query、可选 pages（1 到 5，默认 3）。搜索后同时读前 pages 个网页，返回来源列表加每页要点；某页读不了会标注，不影响其他页。单次返回上限 12KB，超出的页面可再用 web_fetch 继续读。属于 web 组，需要先 expand_capability。
3. 网页读取服务改为允许同时处理多个请求。

## 不做
- 不接付费搜索 API；不改 web_fetch 的行为和公开网址限制。

## 费用
不增加固定花费。`web_research` 一次返回最多约 12KB（约 3k token），但它替代了搜索加多次读页的多步调用，整体预计持平或更省（粗估，未验证）。

## 验收（lan 日常体验）
1. 更新并完全重开 Peter（无需重跑 setup.bat）。
2. 让 Peter 查一件需要多个来源的事，比如"帮我查查最近有什么好玩的独立游戏，多看几个网页"，他应该先展开上网能力，一次就给出带来源的整理。
3. 连续让他搜 10 次不同的话题，不应再出现"没有返回结果"（日志在 `data\peter\tools.jsonl`，我可以代查）。
