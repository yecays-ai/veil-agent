# 工单 199：数据损坏与账本安全恢复

来源：lan 2026-11-02 批准的数据完整性审计后续（B 工单），在工单 197（备份覆盖与恢复体验）验收后施工。

## 目标

1. 恢复旧备份后，费用账本不倒退：`restore --replace` 完成后，按请求标识（id）与恢复前的账本对账，保留每个请求完整的 reserve / dispatch / settle 过程（同一个 id 不等于只留一条记录），补回备份之后的请求与后续结算。
2. 无法确认的记录（两份账本对同一步骤内容不一致、当前账本里损坏的行）：保留备份里的版本，另一版本和原始行原样存为证据，不按零元处理、不丢弃；在核实前暂停所有新的付费请求（聊天、自主、瞄一眼、记忆整理）。
3. 聊天、账本等 `.jsonl` 损坏时，有独立的诊断与修复入口 `data_repair.py`：先保存原文件，指出损坏位置并展示将被隔离的内容，输入确认后才修复；被移走的行原样保留；只缺换行的文件只补换行。
4. 账本不会因为一行解析失败就把可能发生的费用当作零：修复费用账本后同样暂停付费请求，直到核对供应商账单并确认（`ledger-verify`）。
5. 「宁可停止，也不静默丢弃损坏记录」不变；程序报错时直接给出要运行的命令。
