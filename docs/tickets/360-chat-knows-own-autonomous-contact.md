# 360｜聊天时 Peter 知道自己自主活动里为什么留言

- 属于 A 陪伴核心（连续性、真实性）。
- lan 能做的新事：Peter 自主活动里去花园论坛发了东西并给她留言，她几小时后回复，他能自然接上，不再说「抽风了」。
- 示例（输入 → 系统行为 → 看到的结果）：凌晨他在花园回帖后给 lan 发「我在花园发了个帖子，你看看？」→ 早上 lan 回「你怎么跑去论坛了」→ 程序在这一轮的末段附上那次醒来的时间、他留下的决定/原因、成功的工具动作和他发出的原话 → 他按真实记录回答，细节不在记录里就说想不起并去查，不编。
- 验收：见下。

## 根因（读代码，未读 lan 真实数据）

1. 聊天历史里，自主醒来发的消息和普通回复一样，是没有时间、没有来由的 assistant 文本（`recent()` 不带 `autonomy_run_id`）。
2. 已有的「自主活动交接」（工单 094）只带**最近一次**活动记录，每次活动只带一次，决定只留 120 字节、工具只留前 2 个；lan 回复前如果又醒过一次（没发消息的），带过去的是后一次，花园那次就丢了；就算带上，论坛发了什么也不在里面。
3. 工单 352 的时间感只说「你自己发过 N 次消息，她可能在回复」，没说为什么发、发前做了什么；且只在她上次说话超过 1 小时才出现。

## 找轮子

复用：`life_state.py`（352，每轮末段、缓存前缀之外）、聊天记录里已有的 `autonomy_run_id`（= 醒来开始时间）、`autonomy.jsonl` 里程序写的活动记录、`autonomy_history` 工具。没有新增存储、工具、依赖或模型调用。候选：给历史里的消息加前缀标记（会被模型模仿进回复，放弃）；扩大一次性交接（仍只管最近一次，放弃）。

## 改动

`life_state.own_contact_text()`：从全部聊天记录取「lan 最后一条消息之后」自主醒来发的消息（最多 3 次醒来、每条 200 字），配上同一次醒来的决定、原因、重点和成功的工具动作（不含发消息本身，最多 6 个）。lan 一开口（本轮之外的下一条）窗口就结束。写明：这是他自己的主意；细节不在记录里就如实说并用 `autonomy_history`/对应工具查；不许编、不许说成故障；不主动提起。

## 整体维度对照

连续性：知道来由 ✔；真实性：只用程序记录，缺失就说不知道 ✔；不翻旧账：只含她没回过的那几次，不主动提 ✔；缓存：放末段，前缀不变（测试）✔；性格/人设：不动人设文件 ✔；记忆写入：不新增，不涉及开关/撤销；并发：不碰发消息/拆气泡代码。
已知不足：花园帖子正文不在活动记录里，只能说他发了哪个工具动作；要补需要另开工单记录工具结果摘要。

## 验收步骤

1. 更新重开；等他自主醒来给你发一条消息（或让他醒来后给你留言）。
2. 隔一阵回「你怎么想起发这个」，他应说出当时为什么发、做过什么，不说抽风。
3. 再追问帖子具体内容：他应说记录里没有并去查，不凭空编。
