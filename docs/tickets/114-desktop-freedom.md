# 工单 114：桌面上放手让 Peter 做事

## 目标（Lan 2026-10-25 选的方案 A）

Lan 躺在床上用 QQ 交代任务，Peter 自己在电脑上完成，不用每一步都等她批准。安全底线由程序守住，不加任何「先验证安全」「先解释计划」之类的人格规则。

## 现状

- 白名单应用里的普通点击、导航、选择、开关和文字输入/编辑直接执行，不再弹审批。
- 只有点在「保存 / 另存为 / 发送 / 提交 / 发布 / 覆盖」类控件上，或文件已存在的覆盖确认框（「确认另存为」「已存在」）里的按钮，才问 Lan。删除、安装、付款、管理员/提权仍被程序直接拒绝。
- 如果这次任务是 Lan 在 QQ 上交代的，审批问题会同时发到 QQ（先发 Peter 这一轮已经说的话，再发问题）。她在 QQ 回「同意」（或 好 / 可以 / 行 / y / ok）就执行，回「不同意」（或 不 / 不要 / 不行 / n / no）就取消；最后一行是这些词才算回答，其他话照常当聊天。VEIL 页面上的按钮照旧能用，先回答的算数。
- 新工具 `desktop_create_file`：Peter 可以在 Lan 的「桌面 / 文档 / 图片」文件夹里新建文件（可带新子文件夹），不审批、不限每天个数、不规定固定文件夹。格式限 txt、md、html、htm、svg、csv、json、css、xml（双击不会运行程序的文本格式），每个文件最多 512 KB。路径已存在就拒绝，所以 Lan 已有的文件不会被覆盖、修改或删除；不跟随链接文件夹，不接受 `..` 或绝对路径。
- 程序自己产生的键鼠输入（Peter 的键盘回退打字、QQ 发消息）不再被另一边当成 Lan 回来了：之前 Peter 在记事本打字会让 QQ 等 2 分钟才收发，QQ 发完消息后 Peter 下一步桌面动作会被「人工操作优先」挡住。
- 自主活动中没有人回答审批，保存类动作照旧自动拒绝；普通操作和新建文件在自主活动里也能用。预算和自主活动上限不变。
- Peter 收到一次英文能力通知（`desktop_freedom_announced`），内容只陈述新能力，不含谨慎类要求。

## 验收步骤

1. 退出 Peter，双击 `update.bat` 更新后重新打开。
2. 离开电脑两分钟以上，在 QQ 上让他「在桌面上给我写个小东西」：确认桌面上出现新文件，过程中没有任何审批。
3. 在 QQ 上让他打开记事本写几句话：确认打字、菜单都不用批准。
4. 让他在记事本里保存：确认 QQ 上收到「Peter 想在记事本里点「…保存」…回复「同意」或「不同意」」，回「同意」后保存成功。
5. 再试一次回「不同意」：确认没有保存，他知道你没同意。
6. （可选）让他用 `desktop_create_file` 写一个桌面上已有的文件名：确认被拒绝，原文件没变。
