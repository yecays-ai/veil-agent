# 工单 332：宿主通道第二轮真机实测发现的问题

工单 331 合并后在 Lan 电脑的测试副本重跑两个场景：记事本场景跑通，网页场景 10 分钟卡死、花费 ¥0.016，没有写出 notes.md。

## 原因和做法

1. 网页任务卡死：OpenCode 1.19.5 的 `GET /permission` 在有一条待批请求（如 webfetch）的 `metadata.timeout` 为空时，整个列表都返回格式错误，VEIL 读不到请求，请求没人回，任务干等。云端用真实 OpenCode 复现（webfetch 请求），改为在发出任务之前就开始读事件流，同时读 `/event` 里的 `permission.asked`（每条请求单独送到）。列表读取连续失败 30 次，且事件流没连上或在这次运行中断开过时，明确停下并写出原因；读权限失败不再让读消息一起被跳过。
2. 浏览器还是起不来：`npx` 装在 `Program Files`，`mcp_hidden_stdio.py` 用列表启动 cmd，Python 把整行命令再加一层引号并把内部引号转成 `\"`，cmd 不认。改成把 `cmd /d /s /c "<整行>"` 作为一个字符串交给系统。
3. 启动失败原因被吞：MCP 服务的 stderr 以前丢进黑洞，现在由一个线程在内存里只保留最后 1200 字节，启动失败时把其中最后一段附在错误里（总长仍在 300 字内）（cmd 的报错、Python 的栈）。
4. 打开记事本被问“直接运行程序”：这类请求现在对 Windows、Program Files 目录下的程序（只有程序名时先在 PATH 里查到它，且必须落在这些目录）直接放行；路径里带 Temp、Downloads、AppData 的，或在项目目录里的程序仍然询问；提权工具、系统壳仍然拒绝。这是按“Peter 自由使用电脑，只拦危险操作”的原则定的，Lan 可以改。

## 验证

- 单元测试：事件解析、cmd 整行命令、程序启动分级。
- 云端真实 OpenCode 1.19.5：webfetch 请求被读到并回复，任务照常往下走（之前卡死）。
- 未验证：Lan 电脑上浏览器真起来、网页场景写出 notes.md。
