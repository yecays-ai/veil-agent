# 工单 326：后台浏览不被打断，出错原因进日志，搜索能连上

## 目标

Peter 查资料、读网页时都在后台进行，Lan 照常用电脑也不会打断他；搜索在 Lan 的网络上能出结果；每次失败的原因都会写进本机日志，可以直接查。

## 当前状态

- 浏览器（`browser_tools.py`）每次都打开一个看得见的窗口，而且只要 Lan 动一下键盘鼠标，动作就中断，动作开始前还要求她 3 秒没碰电脑。工作台里的浏览器网关也会因为 Lan 的输入停掉整个任务。Playwright 驱动浏览器根本不经过她的鼠标键盘，这样的限制没有必要。
- `web_search` 用的 `ddgs` 不读 Windows 系统代理（读网页的 `web_fetch` 会读），5 个境外引擎在 Lan 的网络上全部超时，每次等满 40 秒才报错。
- 主聊天里浏览器和桌面工具的失败，日志只记一句固定的话；工作台里桥接工具（`veil_*`）的错误原文，会随容器里的 OpenCode 会话一起丢失。
- 工作台的桌面网关已在 #325 撤掉，本单不再处理。

## 改动

- 浏览器默认在后台运行（无窗口），不检查 Lan 的输入。只有 `open` 带上 `show: true`（Lan 要亲眼看这个页面）时，窗口才出现在她的屏幕上，这时她的输入优先。工作台里的浏览始终在后台。
- 搜索先直接读 Bing 的结果页，走 Lan 自己的网络（国内不开代理也能连上），不用注册，也不花钱；Bing 不行时，再走系统代理（也可以用 `DDGS_PROXY` 环境变量指定）试其余引擎；上次成功的引擎下次排在最前面；整次搜索最多 20 秒；报错里写清每个引擎的失败原因，以及是否找到了系统代理。
- 日志：主聊天里浏览器和桌面工具失败时，记录程序给出的失败原文。工作台每次运行都把 OpenCode 会话存到 `data/peter/workbench-home/runs/`，保留最近 30 次；诊断信息里带上 `veil_*` 工具的错误原文（命令行和文件类工具仍然只记错误类型）。

## 接入检查

- 入口：主聊天、自主醒来和工作台共用同一个 `BrowserTools`；`show` 只在主聊天的工具说明里出现，工作台网关会把它去掉。
- 停止与恢复：停止键、暂停和 20 步、5 分钟的上限不变；`show` 模式下保留人优先。
- 权限：网址过滤、公网 IP 校验、禁止下载和登录都不变。
- 费用：不变，没有付费搜索。
- 数据：新增的运行日志只在本机 `workbench-home/runs`，最多保留 30 份，每份不超过 2MB，不进 git，也不挂进容器。
- 状态可见：`tools.jsonl` 里能看到失败原文；工作台的运行日志可以逐份打开查看。
- 升级回滚：不需要迁移配置；还原本 PR 即可回退。
- 真实环境：由开发者通过 Remote Control 在 Lan 的 Windows 上实测（搜索代理、后台浏览）。

## 验收步骤

1. 更新并重启 Peter。对他说"帮我查一下今天有什么科技新闻，读两个网页告诉我"，他查的同时你照常打字、动鼠标：不弹浏览器窗口，也不会中途报错停下。
2. 对他说"打开一个网页给我看"：这时浏览器窗口出现在你的屏幕上。
