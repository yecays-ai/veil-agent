# 383 想起判官：补上合并时漏掉的评审修复

所属格：A（记忆与人格连续性）。不涉及新功能：工单 382（想起判官）在评审修复提交推上去之前就被合并了，合并进 main 的是第一版。本单把评审指出、并已验证的 4 处问题补进 main。

## 现状
1. **真实聊天里判官每次都会等锁超时（重要）**：聊天这一轮已持有模型设置锁（`models.env_lock`、`models.lock`），判官在后台线程里调用 `make_model` 的 `call` 又去等同一把锁，主线程在等判官，等到超时才退回规则 A；整轮聊天结束后后台线程才发出一个已经没用的付费请求。结果是真机上判官不起作用，还让每条消息多等最多 4.5 秒，连续 3 次后暂停 5 分钟再来一遍。单测用的假模型不拿锁，没有覆盖到。
2. 请求发出前没有 `mark_dispatched`：请求已发出但程序在结算前退出，重启后这笔预留会被当作「没发出」释放，绕过每日/每月花费上限。
3. 判官成功回答后，Ombre 的「忽然想起来」随机浮现（`random_chance` 默认 0.1）仍可能把一条没被判官判断过的旧记忆补进来，违反「没有就没有」。
4. 自主唤醒在 `rotation_candidates <= 3` 时会进入判官，与「唤醒不用判官」不符。

## 改动
1. `recall_judge._ask`：像 `Chat._model_call` 一样用 `call.raw` 加 provider 快照（没有 `raw` 的假模型照旧直接调用）。
2. 请求发出前 `budget.mark_dispatched(reservation)`。
3. 判官成功回答（包括「没有」）后清掉 `drift`；技术故障时保持原样（退回规则 A，含随机浮现）。
4. 判官入口加 `not rotate`。
测试：新增 4 条（持有模型锁时判官仍成功、dispatch 记录、随机浮现不绕过、三条候选的唤醒不走判官）；测试里的假模型字段 `raw` 改名，避免和真实的 `raw` 属性混淆。用真实 `ModelSettings` 锁在真实 Ombre + 正式库副本 + 真实模型上验证：5 句里判官全部成功，没有超时。
