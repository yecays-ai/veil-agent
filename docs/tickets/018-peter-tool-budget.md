# 工单 018：Peter 工具步骤与额度收尾

## 目标

Peter 在不突破现有费用上限和工具权限的前提下，每轮最多可用 12 个工具步骤；费用或步骤不足时，不把原始 DSML 工具调用文本当作聊天回复。

## 当前状态

Peter 的 `characters/peter/character.toml` 目前为 `max_steps = 6`。工具循环已将最后一步保留给不带工具的整理回复；预算仍由 `Budget.reserve` 在每次模型请求前检查，日/月上限为 ¥10/¥300。额度耗尽分支会拒绝尚未执行的结构化工具调用，但当模型把 DSML 工具标记以普通 `message.content` 返回、且 `tool_calls` 为空时，`Chat._tool_chat` 现在会把该内容当作回复。沿用现有 OpenAI 结构化 `tool_calls` 及工具 allowlist/审批/预算路径；只识别并用简明提示替换未执行的 DSML 标记文本，不解析或执行文本工具指令。未发现可直接复用且适用于本项目的独立解析器。

## 验收步骤

1. 在 Windows 与 Peter 做一个需要多次只读工具调用的任务，让他连续查阅多个已知资料并总结；确认超过原有 6 步的任务可以继续完成，且工具行为仍按原权限执行。
2. 通过 `/cost` 确认每日、每月上限仍分别为 ¥10 和 ¥300；达到上限后请求工具任务，确认明确告知未继续、没有执行未授权工具，也没有显示原始 DSML 标记。
3. 确认普通文字回复和已有文件审批仍可用；不要为了验收故意增加费用或绕过工具确认。
