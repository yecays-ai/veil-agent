# 工单 321：调查续接的只读别名分类修复

## 目标

Peter 在生产工具别名下也能正确复用新鲜只读证据、按需重查过期证据，并且不重放已成功、被拒绝或结果未知的副作用。

## 当前状态

- 工单 318（PR #317）已合并为 `19b8d5b`。`investigation_checkpoint.record()` 之前用模型侧别名（如 `read_the_notes`）判断只读，但只读集合使用规范名（`read_text_file`），导致成功只读证据被记成副作用；续接时既不会标记新鲜，也会挡住过期重查。
- 修复：分类改用规范名，证据仍保存模型侧调用名，防重放签名不变；MCP 的副作用提示也改用规范名。
- 同时修复：最后一步工具已收起时，模型仍输出文本工具调用会被误记为 `tool_failure`；现在按 `step_limit` 保留检查点，继续后可接着做剩余工作。
- 回归：新增生产别名只读/副作用/排除测试、Chat 级别名检查点测试、最后一步文本工具调用测试；相关 209 项测试通过。
- Windows 真实验收已完成：独立 `--acceptance` 实例、真实 deepseek 模型、真实 `pythonw → mcp_hidden_stdio.py → node` MCP 文件工具；步骤上限、无关聊天后续接、重启恢复、副作用防重放均有执行证据。

## 验收步骤

1. 用独立测试实例把 `max_steps` 设为 3，发起多步只读调查；中断后说“继续”，确认不重读新鲜文件；隔 15 分钟以上再继续，确认过期文件可以按需重读。
2. 重启测试实例后说“继续刚才的调查”，确认原目标、已有证据和中断原因恢复。
3. 批准一次测试写入后继续，确认不重复；拒绝一次后继续，确认不自动执行；在写入执行中强制结束进程后再继续，确认“结果未知”不会擅自重试，且新操作仍会弹审批。
