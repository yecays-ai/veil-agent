# 工单 035：给模型看的系统提示全部改成英文

## 目标

Peter 的人设和 lan 平时跟他的对话大多是英文，但我们每次都往上下文里塞很多中文系统文字（自主活动摘要、能力变化通知、记忆召回说明、工具结果、自主唤醒指令等），他被带着切到中文，今天已多次出现。本单把**模型会读到的程序文字**全部换成英文，让他的语言只由人设和 lan 的话决定。

做完后 lan 能看到的：正常聊天里他不再无故切中文；lan 自己说中文时他照常用中文回。网页界面、命令输出、错误提示、`/cost` 等 lan 自己看的文字不变，仍是中文。

## 范围：换

凡是**写进发给模型的请求里**的程序文字，换成自然的英文，意思不变：

1. 每轮系统消息：记忆召回说明（`memory_agent.py` 的开场记忆/每轮记忆说明、`这轮记忆检索没成功…`）、自主活动摘要（`autonomy.py` 的 `recent_chat_context`，字段名 时间/决定/原因…）、`pending_deletion_context`、「程序生成的能力变化记录」前缀、`self_facts` 里尚存的中文。
2. 能力变化通知：`tools_agent.py` 里所有 `capability_event` 文字，以及 `capabilities.json` 里已存的待发通知的生成文字。已发出的历史不改。
3. 自主唤醒指令 `AUTONOMY_WAKE` 及四行总结的要求。四行改成 `Decision: / Reason: / Focus: / Next step:`。**读取旧记录和旧格式（「决定：…」）的解析必须继续能用**，新格式两种都认。`autonomy.jsonl` 里已有的字段名不变。
4. 工具结果和拒绝文字：`memory_native.py`、`long_tasks.py`、`veil_agent.py`（`send_message` 的「已发送。」等）、工具循环里给模型的提示（截断恢复等已是英文的不动）。工具给 lan 看的审批卡片文字不动。
5. 工具说明（给模型的 description）里自己写的中文部分；Ombre 自带的说明不改。

## 范围：不换

- 网页和终端里 lan 看到的所有文字、命令输出、错误弹窗、`/cost`、`/autonomy`、`/memory` 等。
- 人设文件（本地 `persona/peter.md`）、已存的聊天和记忆、`autonomy.jsonl` 历史记录、测试数据。
- 日志和诊断文件的中文。
- 不改行为、权限、预算、工具列表；不改人设；不在代码或仓库里手写任何人设内容。

## 要点

- **模型读到的和 lan 读到的分开**：同一句话两边都用到时（例如工具结果既给模型又显示给 lan），先看现状再定；原则是给模型的英文，显示给 lan 的保持中文，需要时拆成两份。
- Peter 回复的语言**不要**在提示里硬规定（不加「必须英文」之类）；只是不再用中文把他往中文带。lan 说中文他回中文，lan 说英文他回英文，由人设决定。
- 与 PR #66（新英文对话入口）不冲突；#66 里写死的英文提示由 #66 自己处理，本单不碰它。

## 测试

只改和这些文字直接相关的测试断言，加一条检查：给模型的系统消息和工具结果里不含中文字符（lan 可见的文字除外，用白名单列清楚）。提交前全量离线测试跑一次即可。

## 费用

英文比中文省 token，预计每天略降；不新增模型请求。

## 施工规矩

照 `docs/tickets/024-ombre-resident.md` 的「施工规矩」7 条执行：只做本单、测试只跑必要的、不在 lan 电脑上做实验、交付前自己走一遍、15 分钟不等小兔子、卡住就停、汇报十行内中文。STATUS.md、HANDOFF.md 只改本单相关几行。

## 验收步骤（Windows）

1. 更新 main，退出服务再启动。发几句英文，Peter 用英文回，不再夹中文。
2. 发一句中文，他用中文回；再发英文，他回英文。
3. 触发一次自主唤醒，`/autonomy` 里新记录的四行是英文，旧记录仍能正常显示、下次聊天仍能带入摘要。
4. 记忆保存/搜索、文件审批、`/cost`、网页界面文字照常是中文。
