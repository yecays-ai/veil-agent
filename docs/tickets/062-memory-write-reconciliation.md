# 工单 062：记忆写入结果核对与稳定性专项收尾

## 目标

Peter 在 Ombre 写入回执丢失后如实保留待核实状态、不重复保存；有实际成功回执时才确认记忆已保存。

## 当前状态

基于 main `e06d891`。锁定 Ombre 3.6.14（MIT，提交 `115d831d979bf67efc7150f976e2cb34c333c935`）的 `hold` 仅在成功回执返回 bucket ID，接口没有调用方幂等键、稳定操作 ID 或按单次写入读取结果的能力；标题、正文、搜索和本地 Markdown 都不能证明一次特定请求。已查成熟幂等方案：AWS 的 durable-execution 文档要求外部服务接受同一幂等键才可安全重放；`obol-ledger` 的 MIT 设计也在服务端原子保存键、请求指纹与结果。Ombre 不满足该前提，不能直接复用它们的代码或伪造确定性。062 复用现有角色本地 `Store`、`Memory`、MCP 恢复和 unittest：持久账本只记录操作 ID、由角色私钥计算的 HMAC 请求指纹、状态、实际确认的 memory ID 和安全错误分类；私钥另存角色私有目录，不进入账本。成功回执才确认；提交前明确关闭可记为未提交；其他结果保持待核实并阻止同一 `hold` 或非删除 `trace` 重启后重发。账本不保存记忆正文、标题、查询、密钥或原始服务返回。

## 验收步骤

1. 在隔离虚构角色保存一条虚构记忆，确认 Peter 能正常读取，且只出现一条。
2. 由开发端模拟写后回执丢失并恢复服务，确认 Peter 可继续聊天和检索，但该次保存只报告待核实、不会自行重试。
3. 重启隔离 Agent 后再次检查，确认待核实保留、其他角色无法读取其记录，且不用真实数据或付费模型。
