# 工单 421：新经历接回旧故事，完整保存且可恢复

- 格：A（陪伴核心 · 记忆与人格连续性）
- 做完 lan 能多做的一件事：同一件事隔几天再说，Peter 会在原来那段经历上接着写，而不是又存一条互不相认的记忆；长经历不再只剩开头 600 字，阶段、来源和当时的理解都能查回来。
- 她怎么验收：下面三条，按真实聊天做，不看测试。

## 目标

Peter 主动保存和后台自动整理，写入前先找已有经历：明确是同一件事的发展就续写同一个事件 ID，找不到旧事才新建；关系不确定时保留独立经历和候选关联。单篇故事不再有固定字符上限，长内容按真实请求预算分批处理，完整原文、阶段、来源、时间和理解变化都可追查，保存后新会话仍能讲清早期经过和最新发展。

## 当前状态

- 事件层（工单 407/410）已有归组、阶段、故事、证据、版本、锁定和恢复；本单已对 Peter 打开事件层。
- 保存链上的固定上限已取消：`memory_native.MEMORY_CHARS` 改为按模型输出预算；`experience_memory.ENTRY_CHARS/UPDATE_CHARS = 0`、`CANDIDATE_CHARS = 6000`；`event_memory.stage_chars = 0`；故事按批次合并，不再截 16000 字 JSON。
- 恢复：写入中断留下的 pending 阶段按 `source_key` 复用原事件与原 `stage_id`，重词重试不新增阶段；同一来源的旧重复 pending 在恢复时标 `superseded`，只提交最新一条。关闭/合并的事件不再进入后台更新候选；竞态下被拒绝的更新写入 `update-rejected` 并推进游标，不再整批反复调用模型。
- 阶段记录发生时间、保存时间、来源范围和消息 ID；后台整理用聊天批次的时间与 `covers`，不再用整理时间冒充发生时间。
- 主要文件：`event_memory.py`、`experience_memory.py`、`memory_native.py`、`characters/peter/character.toml`、`prompts/defaults/memory.event.*`、`desktop/chat.js`、`web_agent.py`。

## 验收步骤

1. 和 Peter 聊一件有后续的事（例如先谈一个做法，过一两天又用了它，再后来对方说哪些时机好、哪些难受）。打开「记忆 → 经历」：应是一段经历、至少三个阶段，故事里能分清两个「第一次」，并包含后来那条反馈。
2. 让他存一段超过 600 字的长经历，再补一个阶段。打开这段经历的「阶段与证据」：旧结尾和新进展都在事件故事和阶段原文里；Ombre 可检索正文也包含完整故事，但每轮实际注入仍由聊天 token 预算控制。
3. 在记忆页锁定这段经历，再聊一个新的发展。新阶段应保留在经历里并标出「已锁：新发展留在本机」，Lan 审过的正文不被覆盖；解锁后能继续整理。

## 接入检查

- 入口：`hold`（桌面聊天、自主活动、QQ 入站后的聊天共用）、`ExperienceMemory.run_if_due`（后台整理）、`memory_timeline` 与「记忆 → 经历」页。不新增入口。
- 停止与恢复：`[memory.events] enabled = false` 回到一条保存一条记忆的旧路径；事件库只追加，关掉后仍可读。阶段先写 pending 日志再提交；投影/索引失败留 `dirty`，下次保存或后台维护重试。
- 权限：隐藏/归档/锁定仍由程序在读写时过滤；锁定或 Lan 手改过的正文不被后台覆盖，新发展留在本地阶段并标 `pending_review`；不可见事件不能通过 `target_id`/`link_to`/移阶段写入。
- 费用：每次保存新增一次归组判断（仅在有候选时）和一次故事整理；都与后台整理共用 `[memory.experience].daily_budget_cny`。预算不足时阶段照常落盘，保留好稿并标故事待整理，不阻断保存、不丢阶段。真实模型复测 5 次调用约 ¥0.008。
- 数据：`events.jsonl` 增加 `revision`、`story_pending`、`pending_review`；阶段增加 `occurred_at`、`at_known`、`saved_at`、`source`、`source_key`；后台整理记录增加 `covers`、`deferred`、`source_key`。旧行缺字段按旧行为读。
- 状态可见：`hold` 返回新手经历还是续写、事件 ID、是否用阶段原文拼接、是否需要重试；经历详情与列表显示待整理、投影待重试、待恢复阶段、来源范围和已锁新发展。
- 升级回滚：配置关事件层即可；已写入的事件/阶段不影响旧记忆读取，不需要删数据。
