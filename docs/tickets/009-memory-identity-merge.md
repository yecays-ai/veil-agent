# 工单 009：稳定记忆标识与无损整合

## 目标

Peter 能按稳定编号和标题找到、更新并整合相关记忆，追加时保留既有原话；隐藏或删除具体记忆前须由 lan 确认；隐藏（`/forget`）可恢复，删除（`/delete`）不能用 `/restore` 恢复（见工单 015）。

## 当前状态

- `memory_native.py` 当前解析 Ombre 的稳定结果 ID 后没有把 ID 与标题一并交给 Peter；更新只能依赖相同标题，无法明确指定目标。
- Ombre 固定依赖的 `breath_search(with_ids=True)` 提供机器可读 ID 清单，`hold` 同事件合并使用原文追加；改动只复用这些能力，不修改 Ombre 源码。
- GitHub 上的 Mem0（Apache-2.0，约 67.4k stars）有稳定记忆 ID 和变更历史；当前主分支的新算法采用只新增、不覆盖。这里只借鉴稳定身份和追加式保存思路，不复制代码或引入依赖，避免替换现有 Ombre 角色记忆与逐字保存行为。
- `memory_agent.py` 的 `/forget` 目前会立即隐藏；`/delete` 已逐条二次确认，Ombre 软删除；009 原稿写“可恢复”与 005g 冲突，已由工单 015 统一为不可通过普通命令恢复。Peter 的 native 与 extract 两条路径、旧数据均保留。

## 验收步骤

1. 在真实聊天中让 Peter 搜索已有记忆；结果显示正确编号和标题。补充新事实后，Peter 更新同一编号，原文仍逐字存在，标题不变，`/memory` 不新增重复编号。
2. 让 Peter 搜索已有重复事件并整合：他把一条作为目标，将其他命中编号传给整合；检查所有原始正文都逐字保留，来源条目仍在，且没有条目被自动隐藏或删除。
3. 对具体编号试用 `/forget` 和 `/delete`：首次操作只显示该条标题与确认指令；确认后才隐藏或删除；`/forget` 的记忆 `/restore 编号` 后重新出现并被想起，`/delete` 的记忆 `/restore` 被拒绝（工单 015）。
