# 工单 044｜记忆诊断提示与工具拒绝原因

**基线：** `main` `a48f13dec08d89ea2d1667ff550ae2e4cbe6baca`  
**分支：** `ticket/044-memory-diagnostics-tool-errors`

## 目标

同一聊天轮次内，相同的记忆可见性诊断最多显示一次，同时无法确认的记忆仍不得进入模型上下文；确认可见的记忆必须继续进入真实模型请求。程序拒绝工具调用时，模型与网页用户都应收到同一条明确英文原因。

## 现状与证据

- Windows 实测截图显示同一条“记忆可见性无法确认”提示在多轮聊天前后重复出现。
- `Memory.refresh_visibility()` 对每个可见性未知的候选分别入队通知，并将该候选加入 `native_hidden`、清除缓存；`Memory.context()` 对普通、情绪和开场候选均会校验。因此重复提示同时说明被提示的候选当轮被过滤，但截图不能证明所有其他记忆也都检索失败。
- `model_tool_result()` 会把大多数含中文的工具拒绝原因替换成同一条英文泛化信息；网页仍显示中文原因，形成模型与 Lan 可见内容不一致。
- 仅用虚构数据验证；不访问真实聊天或记忆。

## 复用调研

已搜索 GitHub 中按会话轮次去重诊断及工具错误码到英文操作提示的实现，并搜索本仓库。没有找到可直接复用且符合当前线程内通知队列、现有工具权限与安全边界的成熟实现。复用现有记忆通知队列、工具结果送模链路与权限状态；不增加依赖。

## 修改范围

- `memory_agent.py`：按当前线程的聊天轮次合并可见性诊断；英文提示；不改变未知可见性时的失败关闭行为。
- `veil_agent.py`：将可信程序产生的已知拒绝原因映射为固定英文；同一映射内容用于模型和网页显示。未知中文失败使用安全英文兜底，不回传未经映射的文本。
- `tests/test_hidden_memory_context.py`、`tests/test_tools.py`：验证真实模型请求中的记忆过滤、有效记忆召回、每轮仅一条提示及模型/网页收到一致具体英文原因。
- 同一 PR 更新本工单、`STATUS.md`、`HANDOFF.md`。

## 验收

1. 多条虚构记忆可见性未知时，一轮最多出现一条英文诊断，且相应记忆标记不进入模型请求。
2. 同一轮中可确认可见的虚构记忆仍进入模型请求；下一轮可以再报告一次。
3. 隐藏记忆仍从模型请求排除。
4. 无效 `target_id` 的模型结果明确要求本轮重新执行 `breath_search` 并使用其可见 ID；其他权限/参数拒绝不再全部退化成同一句。
5. 模型与网页显示相同的英文拒绝原因；成功数据、工具权限、审批、参数校验与状态限制保持不变。
6. GitHub CI Windows/Linux × Python 3.11/3.12 通过，Claude 独立审查完成并处理功能与安全问题。
7. 合并后由 Lan 在 Windows 用虚构记忆验收正常召回、隐藏过滤、诊断提示及无效 ID 的纠正重试。CI 不代替真实聊天体验。
