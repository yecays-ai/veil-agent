# 工单 005f：打开 Ombre 自带的模型（打标签和同一事件合并）

## 背景

005 为了可控，把 Ombre 自己的模型调用全关了：记忆全按默认值存（主题"未分类"、情绪和重要程度居中），"同一事件就合并"的判断也没有，一律新建。lan 2026-10-19 说记忆质量比省钱重要，同意打开（估算每天最多约 ¥2）。

## 做什么

- Ombre 每次存记忆时调两次便宜模型：打标签（主题、情绪、重要程度、关键词、建议名字），以及新记忆和已有记忆很像时判断是否同一个事件并合并。
- 用聊天用的同一个模型和接口（DeepSeek 时固定关闭思考），key 用本机 `.env` 里聊天那把，通过子进程环境变量传入，不写进 Ombre 的配置文件。
- 这些调用发生在 Ombre 子进程里，我们看不到真实用量，所以每次 hold 按提示词和输入上限估算，记进共享账本（`accounting = ombre-model-estimate`），并先检查 ¥10/天、¥300/月。**是估算，不是供应商返回的实际用量。**
- `[memory] ombre_model = false` 可关回原来的行为；缺省为开。

## 估算方法

输入按 UTF-8 字节数的一半估 token（打标签提示词约 3200 字节 + 内容最多 6000 字节；合并判断提示词约 1000 字节 + 内容最多 5400 + 旧记忆最多 5400），输出固定 800 token。DeepSeek 费率 ¥2/百万输入、¥8/百万输出时，每次 hold 约 ¥0.01 到 ¥0.02。

## 局限

- 未用真实 DeepSeek 和真实 Ombre 子进程验证（假后端测试通过）；lan 在 Windows 验收时看 `/cost` 和 `/memory`。
- Ombre 的打标和合并是它自己的提示词，质量由所用模型决定。
- 合并判断是保守的（有疑问就新建），所以 005d 的提取端去重仍然需要。
