# 工单 005b：补记一直失败（验收阻断）

## 现象（lan 在 Windows 真实使用，2026-10-19）

正常聊天时两次出现"这次没记成（格式或长度）"；`/memory` 没有任何条目。

## 原因

- 补记请求沿用了聊天的 `max_output_tokens = 1024`。四轮对话的中英双语记忆 JSON 放不进去，回复被截断，解析失败。（根据代码推断，lan 的真实回复未保存，所以未直接证实；本地 `thinking="enabled"` 时思考内容也会占用同一个上限，更容易截断。）
- 提示把截断、空回复、非法 JSON、批次编号不一致、接口报错等混成"格式或长度"，无法判断真实原因。
- 模型给出的原话对不上原消息时整条静默丢弃，用户看不到任何提示。

## 修复

- 补记请求使用独立输出上限（默认 4096，`[memory] extract_max_output_tokens` 可调），并固定关闭思考模式。预留和结算都按这个上限算。
- 失败分类并给出具体原因和诊断码：长度截断、空内容、非法 JSON（位置）、结构不对、批次编号不符、条数不合规、字段不合规、接口失败（错误类名、HTTP 状态）、预算、用量、写入失败、原话不符。
- 诊断同时追加到 `data/<id>/memory/_agent/diagnostics.jsonl`，只含时间、诊断码、数字和错误类名，不含聊天内容、模型回复、密钥。
- `/memory` 没有条目时明说"还没有保存任何记忆"，并显示最近一次补记问题。
