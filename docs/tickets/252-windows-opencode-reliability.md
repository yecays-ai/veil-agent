# 工单 252：Windows 日常体验与 OpenCode 审批闭环

## 目标

Lan 启动 Peter 和连续交代开发任务时不再处理黑色命令窗口或重复审批，Peter 能准确说明审批是否等待、获批、被拒绝或取消，以及工作台最终是否继续。

## 当前状态

桌面轮询首次失败就显示断线；OpenCode 的 Git 快照和 Docker 清理没有统一隐藏 Windows 子进程窗口；审批桥丢弃批准/拒绝原因且同一任务不复用批准。工单 249 已修复危险命令与搜索文本的基础分类，但只读复合命令和明确的测试脚本仍会过度询问。本次复用现有 `web_launcher.py`、`executor_opencode.py`、`workbench_scope.py` 和桌面轮询，不引入新权限系统或外部依赖。

## 验收步骤

1. 在 Windows 正常启动、完全退出并重新启动 Peter；全程没有需要手动最小化的命令窗口，停止后没有遗留工作台进程。
2. 连续完成读取、修改、普通测试和修复测试；单次轮询失败不显示断线，相同已批准操作不重复询问，真正停止服务后会显示断开并在恢复后消失。
3. 分别批准一项风险操作和拒绝 `git push`；批准后继续并报告真实结果，拒绝后不执行、不重试，Peter 明确说明 `user_denied`；搜索含 `git push` 的文本不弹审批。
