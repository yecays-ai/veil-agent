# P3-0 · 配置持久化与 P3 前置准备

- 归属：**维护类，不占 A–V 五条线格子**；P3 前置。
- 做完 Lan 能多做的事：以后运行 `update-main`，Peter 的 Brain 唯一权威配置不会再被静默冲回 Ombre 影子模式；P3 的方案、工单、备份/恢复和误删核实都有据可查。
- 之前：`[memory.brain] write_authority=true` / `shadow=false` 只在正式目录工作区；HEAD 仍是 `shadow=true`，一键更新会 stash + reset 回旧配置。
- 之后：Brain 权威配置作为**过渡默认值**提交进 main，更新后保持；P3-2 删除 `[memory.brain]` 过渡开关，Brain 成为唯一记忆后端。

## 目标

解决更新覆盖 Brain 接管配置的问题，并完成 P3 前置的备份/恢复、误删核实、方案与工单固化；不改变正式 Peter 当前运行行为。

## 当前状态

- 正式 Peter 已按 P2 报告切到 Brain 权威（写入/读取均通过），但 Ombre 仍在 18011 作为临时回退，未卸载。
- 该配置只在工作区；`update-main.cmd` 有本地改动时 `git stash push --include-untracked`，随后 `git reset --hard origin/main`，且没有 stash pop → 下次更新会回到 HEAD 的 Ombre 影子配置。
- P2 正式体验验收仍待 Lan；P3-1 未启动。

## 配置方案评估与决定

- **不采用 `character.local.toml` 本地覆盖层**：
  - VEIL 已有四层配置来源：仓库内 `character.toml`（默认）、`.env`（本机密钥）、`data/<role>/models.json`（本机模型选择）、`persona/`（本机身份）。再增加一套 TOML 深合并，会形成第二个配置真源与永久维护面。
  - 该覆盖层在本阶段只为 3 个过渡键服务；P3 完成后 Brain 是默认且唯一，`write_authority/shadow/backend` 不再需要按机器覆盖，长期价值不足。
- **不采用环境变量覆盖或改 `update-main` 特判**：都是额外的临时/永久机制，且会把“更新会重置代码配置”的既有语义弄得更难解释。
- **采用：把过渡配置提交进 main**。本仓库就是正式运行代码来源，P3-0 将该配置作为明确的过渡默认值提交；`tests/test_brain_defaults.py` 锁住这一状态，防止再次被静默回退；P3-2 删除过渡开关并让 Brain 成为唯一实现。
- **已知边界**：P3-0 合并后到 P3-1 完成前，全新 checkout 若没有 `brain.db`，记忆启动会明确失败而不是自动建空库（避免把数据丢失误当成新库）。正式目录已有 `brain.db`，不受影响；全新机器初始化由 P3-1/P3-2 的 Brain-only 启动方案处理。

## 缺陷根因

正式切换把 `character.toml` 当作本机运行时配置直接改在工作区；而更新脚本设计为“保存本地改动到 stash 后 reset 到 GitHub”，不会恢复 stash。该配置因此只在当前进程/当前会话有效，下一次更新消失。同类风险：任何直接修改 tracked `character.toml` 的本机设置都会在更新时丢失。
