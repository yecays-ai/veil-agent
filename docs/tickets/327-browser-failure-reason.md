# 工单 327：浏览器失败时，日志里要有真正的原因

## 目标

Peter 的浏览器失败时，`data/peter/tools.jsonl` 里能直接看到出了什么错，不再只有一个词。

## 当前状态

326 合并后，Lan 电脑上 23:56–23:57 浏览器连续失败 4 次，日志里只有 `Error`。原因：浏览器工具对非预期的异常只返回异常的类名，而 Playwright 自己的异常类就叫 `Error`，所以什么也看不出来。这正是 326 想解决的“失败原文进日志”，在浏览器这条路上没有做到。

## 改动

- 浏览器失败时，结果和日志里写出异常类名加上库给出的第一行说明，例如 `Error: Page.goto: net::ERR_TIMED_OUT at https://example.com/`。
- 说明里的本机路径（Windows 盘符路径和常见的 Linux 目录）换成 `<path>`；网址里的用户名、密码、查询参数和片段去掉；说明最多 200 个字符。
- `STATUS.md` 里 326 的描述改成已合并后的真实状态，并把验收情况如实写进去。

## 接入检查

- 入口：主聊天、自主醒来和工作台共用同一个 `BrowserTools.invoke`，一处修改全部生效。
- 停止与恢复：不变。
- 权限：不变；网址过滤、公网 IP 校验、禁止下载和登录都不变。结果里不会出现本机路径和网址凭据。
- 费用：不变。
- 数据：不新增文件；失败原因只多写几十个字。
- 状态可见：`tools.jsonl` 里失败那一行能看到原因。
- 升级回滚：不需要迁移配置；还原本 PR 即可回退。
- 真实环境：Lan 更新后，让 Peter 读一个打不开的网页，看日志。

## 验收步骤

1. 更新并重启 Peter，对他说“读一下 https://this-domain-does-not-exist-12345.example/”。
2. 打开 `data\peter\tools.jsonl` 的最后几行，浏览器那一行写着 `Error: Page.goto: net::ERR_NAME_NOT_RESOLVED …` 一类的原因，而不是只有 `Error`。
