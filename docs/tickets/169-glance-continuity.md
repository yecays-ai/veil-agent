# 工单 169：瞄一眼后能接住 Lan 对弹幕的回复

## 目标

Lan 看见弹幕后来聊天时，Peter 能知道上次瞄一眼的时间、看见的窗口、自己的观察摘要和实际发出的弹幕原话；这份记录保留到下一次瞄一眼启动时被替换，不主动反复提起。

## 当前状态

分支 `ticket/169-glance-continuity`。复用 `Store` 的角色隔离、锁与原子替换、`GlanceController`、桌面 `shown` 回执和 `Chat` 上下文。`recent_experiences.py` 在私有 `data/<角色>/recent-experiences.json` 保留最近一次瞄一眼及它最多四次屏幕消息；弹幕正文只在显示得到确认后写入，正文不进入工具活动账本。下一次瞄一眼在观察开始前替换旧记录，失败、安静离开和中断也沿用新记录；旧活动的迟到回执不会混进来。上下文每轮带入原始事件时间，不因交付或重启而消失，不设小时期限；标明历史数据、按需接话，不能据显示状态断言 Lan 已读。窗口只保存应用、标题和模型自己的短摘要，不保存原始 UIA 或截图，不自动写 Ombre。

复用调查：检查成熟项目 [LangGraph 的消息合并实现](https://github.com/langchain-ai/langgraph/blob/6f2df053f4487ce6ea8decc0d7482c8e46e0f132/libs/langgraph/langgraph/graph/message.py#L190)（MIT，GitHub 约 4.4 万星，2026-10-29 仍有更新）。其按消息 ID 维护连续状态的思路适用；引入整套运行时会重复 VEIL 已有的 Chat/Store，因此只借思路、不复制源码、不新增依赖，沿用 Windows Python 标准库实现。

本地已覆盖真实 Chat 请求组装、桌面显示回执、持久化后重开、连续追问、下一次启动立即替换、观察失败、原始 UIA 不落盘、未确认显示不记为已发、迟到回执隔离及角色隔离。自动检查与评审以 PR 最新提交为准；Windows 正式程序和真实模型自然接话仍待 Lan 体验验收。

## 验收步骤

1. 更新并重启后，正常使用一个非敏感窗口，等 Peter 瞄一眼发出弹幕；关掉该窗口再回他消息，确认他知道自己刚才说了什么、看的是哪个窗口，时间对应上次瞄一眼。
2. 继续聊几轮或重启再追问，确认仍接得上；聊无关话题时，不会每轮主动重复上次弹幕。
3. 下一次瞄一眼启动后，再问他刚才看见什么，确认对应新的那一次，旧弹幕不会被当作刚发生的事。
