# 工单 182：桌面类 bug 批量修复

## 目标

- Peter 在画图里画画时，他自己移动鼠标不再被当成 lan 动了鼠标；lan 真的动鼠标时他仍然立刻停下。
- 自动发现的应用（如 WPS）的真实窗口能被识别，不再提示「窗口进程路径与允许的应用不匹配」。
- 桌面被整理软件接管时，整理桌面图标的结果如实说「屏幕上可能看不到变化」，不再宣称已验证。
- 全屏（最大化）的窗口能被还原成原来的小窗口。
- 网页搜索失败时，Peter 能看到真实原因，而不是一句固定的话。

## 做了什么

1. `windows_interaction.py`：`DesktopInputMonitor.own_input()` 包住程序自己的鼠标移动、按下、松开和键盘输入。这段期间系统输入时钟的变化都算程序自己的；包住之前和之后的真人输入照常计数，所以 lan 在画画途中动鼠标仍会让 Peter 停下。画布点击、拖动、画线和键盘输入都改用它。
2. `windows_discovery.py` + `windows_interaction.py`：自动发现的应用，如果启动器在 Program Files / AppData 下它自己的安装文件夹里，该文件夹内的 exe 窗口也算这个应用（WPS 的启动器和真正的 wps/et 窗口不在同一个 exe）。系统文件夹、WindowsApps 不适用；命令行、安装卸载程序、浏览器、密码类 exe 永远排除。
3. `desktop_icons.py`：整理或还原图标后，检查桌面图标层是否被隐藏、是否有桌面整理软件在运行。有就把 `verified` 设为 false，并告诉 Peter 「坐标改了、读回了，但不能证明屏幕上看得到」。读回的是同一个系统图标列表，本来就证明不了屏幕上的样子。
4. `windows_manage` 的 `restore`：窗口是最大化时用 SW_RESTORE 还原成小窗口并验证；原来只处理最小化。
5. `web_tools.py`：搜索改用 `backend='auto'`（单个搜索源被挡不再整体失败），失败时把错误类型和简短原因给 Peter。

## 没做

- 小红书图片阅读：现有小红书工具没有读图片这一步，属于新功能，功能冻结期不做，另开单。
- 浏览器 F11 全屏、视频播放器的全屏模式不是「最大化」，这一单不处理。

## 验收（lan）

1. 退出 Peter，运行 update.bat，重新打开。
2. 让 Peter 在画图里画个太阳，手离开鼠标：应画完。画到一半你动一下鼠标：他应立刻停下。
3. 把一个窗口最大化，让 Peter 把它还原成小窗口。
4. 让 Peter 操作 WPS（先让他发现应用，再打开 WPS 看窗口）：不再提示路径不匹配。
5. 开着腾讯桌面整理，让 Peter 整理桌面图标：他应说屏幕上可能看不到变化，而不是说整理好了。
6. 让 Peter 搜一个网页：成功，或者他能说出真实失败原因。

「未验证」：以上都需要在 lan 的 Windows 上确认；桌面整理软件的进程名清单和 DuckDuckGo 失败的真实原因尚未在真机确认。
