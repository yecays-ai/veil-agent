# 交接更新

`STATUS.md` 每个 PR 都要更新，和代码/文档在同一个 PR 里；`HANDOFF.md` 在窗口结束或换人时更新；待验收项统一进 `docs/ACCEPTANCE.md`。进度只记在 `main` 上的 `STATUS.md`，不在别处另存。

## STATUS.md（只写当前正确的状态）

- 更新时间（必须注明时区，如 `UTC` 或 `+08:00`）与 `main` 提交。
- 一句话现状。
- 近期工单表：**工单号 · PR 号 · 合并提交 · 合并时间（注明时区） · 是否部署 · 验收入口（指向 `docs/ACCEPTANCE.md`）**。不另建第二个验收状态权威来源。
- 等 lan 定的事（没有就删掉这一节）。
- 下一步：一件具体的事。
- 验收入口：指向 `docs/ACCEPTANCE.md`。

已经不成立的内容直接删，不留「之前的方案」。**不要把「已合并」「已部署」写成「已验收」。**

## HANDOFF.md

- 停在哪：分支、PR、做到第几步、卡在哪、哪里没验证。
- 下一个窗口第一步做什么。
- 背景：只留仍然成立、新 agent 不知道就会走弯路的事实（含工单号与 PR 号的对应关系）。
- 注意：坑、环境限制和还没解决的问题。

## docs/ACCEPTANCE.md

- 新增待验收项：写进对应模块，含工单、PR、当前状态、验什么、怎么验、复选框。
- 用户确认通过：打勾、写日期，并回到工单补一行验收记录。
- 被替代/取消：移到「已替代、已取消」并写依据，不重复要求验收。

写完自己读一遍：一个从没见过这个项目的 agent，只读 `AGENTS.md`、`STATUS.md`、`HANDOFF.md`、`docs/ACCEPTANCE.md`，能不能马上开工、能不能分清哪件事在等谁？
