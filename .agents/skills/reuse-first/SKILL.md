# 先找现成的

## 1. 先查仓库内部

按顺序看，找到就直接引用（写明提交、日期与结论）：

| 位置 | 内容 |
| --- | --- |
| `docs/reports/` | 架构、审计、实验、验收报告 |
| `docs/reports/config-audit/` | 全局配置审计（668 项清单、8 域证据） |
| `docs/tickets/` | 历史工单里已经确认的目标、取舍与缺陷根因 |
| `交付/`、`待办方案/`（本机，不进仓库） | 调研、方案、设计稿、原方案 |

已经做过的审计不要重做；只核实基线提交有没有变、结论有没有被后续工单推翻、还缺哪一块。

## 2. 再查开源实现

1. 在 GitHub 搜关键词（中英文都搜），看星数、最近提交、许可证。
2. 读源码确认功能真的存在，不只看 README；记下文件、函数和固定提交链接。
3. 判断：
   - 许可证：MIT / Apache / BSD 可以复制，保留版权声明；AGPL、CC BY-NC-SA、没有许可证文件的只借思路，不复制代码。
   - 能否在 Windows 上跑，依赖有多重。
   - 直接用、少量改、只借思路，三选一，写一句理由。
4. 结论写进工单的「当前状态」：用了什么、为什么、查过哪些但不用。

## 3. 不要重复的典型情况

- 同一个报错已经有人查过并写了结论 → 引用结论并验证当前版本是否仍成立。
- 同一份配置清单/权限矩阵已在 `config-audit/` → 直接引用 CSV 与证据文件。
- 同一份 UI/记忆设计已在 `交付/` 或 `docs/reports/` → 以其为基线，只补差异。
