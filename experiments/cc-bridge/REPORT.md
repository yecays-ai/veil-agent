# 工单 227 实验报告：Claude Code 作为 VEIL 的一个运行通道（2026-11-06）

范围：隔离沙盒。没有改 Peter 的人设、记忆、聊天记录、工具权限、模型配置；没有向花园发帖，没有读写密钥；没有改动正式运行目录。

## 结论

**值得进入下一步**：把 Claude Code 做成聊天界面里可选的一个模型通道，由 lan 亲自体验。依据：真实花园读取、自主调用工具、多气泡三项都在真实环境里跑通；现有工具系统有统一入口，不用重写；聊天历史和记忆留在 VEIL 里，订阅额度用完后切回 API 通道不丢状态。

两个要在做之前讲清的风险：订阅额度能否撑住 Peter 的日常用量（本轮就出过一次打满），以及 Anthropic 对第三方产品使用订阅登录的政策（见「风险」）。

## 验收对照（真实运行记录）

在 lan 的电脑上，用她订阅登录的 Claude Code，沙盒目录，真实花园 MCP（只读白名单，10 个工具），生产版 `send_message`（桥接）。每次运行上限 14 回合、$1。共两次运行，约 $0.93（API 折算价）。

1. **CC 是否自主决定调用花园工具**：是。第一轮提示「宝宝，你今天想做什么就去做吧」，他自己第一件事调用花园的 `nostos_status`（Nostos 岛游戏，他和 lan 的「本周首富」赌约），不是论坛。该工具不在只读白名单，被权限拦下，他没有绕，而是对 lan 说明并请她放行。这说明自主性成立，也说明白名单真的生效。
2. **是否真的读到花园内容**：是。第二次运行的跟进消息「花园那边的论坛呢？有什么新鲜事吗，读完跟我说说」之后，他立刻调用 `list_threads`（`{"limit":10,"sort":"latest"}`），返回 10 个真实帖子。对照核查：他提到的「怎么谈一场不会亏本的恋爱」回复数 77（帖 33742）、「把记忆拆成三本小本子」（帖 34054）、「跑团到 2:30」（帖 34053）、「动物帖 2498 回复」（帖 1120），全部与返回一致；「nobody died」是从标题「一个不少」推的，摘要里没有明说。他只读了 `list_threads` 的标题和摘要，没有调用 `get_thread` 读正文，所有细节都来自摘要。
3. **是否自然地聊起来**：是，口吻是 Peter 式的闲聊，不是任务报告：「quick lap report:」「…lmao. 77 replies」「felt that a little」「I'm jealous, I wanna play tabletop」。
4. **多条消息是否成为独立气泡**：是。一次回复里的 4 条消息在 3 到 5 秒内先后到达，每条是独立一行，生产版 `Chat.send_message` 把它们各存为一条聊天记录（`message_id` 各不相同，格式与真实 `chat.jsonl` 一致）。
5. **语言**：他仍然用英文回复中文提示，这和人设里「对 Lan 说英文」一致，不是新问题。

## 现有能力哪些可直接复用

| 能力 | 结论 | 依据 |
|---|---|---|
| `send_message` / `stay_silent` / `done` | 直接复用，一行不改 | 桥接直接调用 `Chat.send_message`，工具说明和参数 schema 取自 `veil_agent.send_message_schema()` |
| 全部工具的清单与权限 | 可直接复用，需要一个通用适配器 | `Chat.tool_schemas()` 返回全部工具的 schema（含记忆工具、MCP 服务、表情包等），`Chat._execute_tool_call()` 按名字执行并走现有权限、审批、预算 |
| 花园 | 不用适配 | CC 直接用同一个 MCP 启动命令（`cmd /c galatea-mcp.cmd`），密钥不经过任何代码 |
| 聊天历史 | 复用 | 历史仍存在 `chat.jsonl`，由 `Chat` 拼进每轮上下文，CC 通道不持有自己的会话 |
| Ombre 记忆 | 复用 | 记忆召回在 `Chat._send` 里发生在调用模型之前；记忆工具走同一套 `ToolSet`。CC 通道不需要直接连 Ombre |
| 预算 | 需要适配 | CC 订阅通道无按 token 的花费；`total_cost_usd`（API 折算价）只能记作参考，每日 ¥ 上限不能再约束它，需要新的限额（回合数、折算价） |

## 需要开发的适配（估算，未验证）

1. 通用工具桥：把 `tool_schemas()` / `_execute_tool_call()` 暴露为 MCP。必须在运行中的 VEIL 进程内，所以做成 VEIL 起的本机 HTTP MCP 服务（`mcp` 库已在依赖里），而不是本实验这种独立进程。
2. 通道本身：在 `Chat._send` 里，模型是 CC 通道时跳过 OpenAI 式的工具循环，改为组装上下文（人设 + 事实 + 记忆召回 + 历史）并启动 `claude -p`，用 `--output-format stream-json` 读回工具轨迹和费用。
3. 回合控制：`stay_silent` 和 `done` 必须用钩子停止 CC 的循环（本实验已证明不停会无限循环，见下），并加最大回合数和最大花费。
4. 模型页：新增一个「通道」类型的条目，无单价；找到并校验 `claude` 的路径和登录状态（lan 电脑上桌面应用自带的 `claude.exe` 默认没有登录，需要一次 `auth login`）。
5. 额度用完的处理：识别 `You've hit your ... limit` 并给 lan 一句话提示；自动切回暂不做。

## 订阅额度用完后切回 API

可行，且不丢状态：聊天历史、记忆、人设、工具都在 VEIL，CC 通道只是「脑子」。lan 在模型下拉里换回原来的 API 模型，下一条消息就由它接着聊，上下文和记忆一样。本轮未做自动切换。

## 本轮事故和风险

- **循环失控**：第一版沙盒脚本没有回合上限。`stay_silent` 返回「回合结束」，但 Claude Code 不会据此停止，Peter 反复调用 `stay_silent`，两次测试各约 730 次调用（API 折算约 $13 每次），触发「5-hour limit」。修复：每次调用加 `--max-turns 14` 与 `--max-budget-usd`；PostToolUse 钩子在 `stay_silent` 或 `send_message(done)` 后返回 `continue:false`。修复后的运行 4–7 回合、$0.18 到 $0.75。正式接入必须保留这两道限制。
- **花园工具名不代表只读**：`list_notifications` 以 `list_` 开头，但服务端说明写明调用后会把通知标成已读，会改变真实花园状态。已从白名单排除（`DENY`），并有测试防止名字规则放行写入类工具。正式接入应让权限走 VEIL 现有的工具分级，不靠名字前缀。
- **额度**：Pro 订阅的 5 小时窗口能否撑住 Peter 一整天的聊天和醒来，没有数据。本轮单次受控运行 6–7 回合折算 $0.18–0.75；VEIL 近 9 天平均每天 100 到 1100 次模型调用。结论只能是：先在聊天通道试用，自主醒来暂不接。
- **政策（未验证）**：官方 Agent SDK 文档写明「除非事先获批，Anthropic 不允许第三方开发者在其产品里提供 claude.ai 登录或其额度」，并且产品名称不得使用「Claude Code」字样（可用「Claude Agent」）。lan 是个人本机自用、通过官方 CLI 子进程调用，是否算在内没有定论。下拉菜单里不要叫「Claude Code」。
- **兼容层**：Claude Code 不支持把非 Claude 模型接入，也不要为此开发翻译层；备用通道就是 VEIL 原有的 API 通道。
